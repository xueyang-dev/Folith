# 流式译文 EPUB

普通 PDF / DOCX 任务可以导出 `translation.epub`，读取当前正式译文，并保留源文件中的内嵌图片与段落顺序。正文可由阅读器调整字号；不承诺原页码、坐标、字体和分页一致。

## 使用

新建任务时，在交付选项中勾选「译文电子书 · EPUB」。已有任务可以在交付页「准备交付」卡片内打开「调整交付内容」，和 DOCX / PDF 一起选择格式，点击「应用」后创建交付版本。文件会出现在主要交付成果中，也会进入交付包和不可变快照。更改输出选项后需要重新确认交付，旧快照保持不变。

下载后通过阅读器的文件导入入口打开。两个生成样本已通过 EPUBCheck 5.4.0（零错误、零警告），并在 macOS Apple Books 实际打开，确认中文、章节、插图与图注的阅读顺序。微信读书和手机端尚未实测，不把标准校验等同于所有阅读器通过。

## 第一版范围

- DOCX：正文段落、标题与内嵌图片；图片独占的空段也会保留。浮动/行内图片放在所属完整段落之后。PNG/JPEG 保留原资源；可解码的其他位图转换为 PNG。
- PDF：文本层正文、标题和内嵌位图。按页内位置排列图文，图片区域渲染为 PNG，保留遮罩、旋转和裁切效果。图注独立保留原文；已有翻译流程没有翻译这些 PDF 图注。
- 图内文字保持原样，不做图中文字替换。正文 PDF 中的独立插图页会原样保图，并注明该页没有译文。
- 纯扫描 PDF、不完整来源映射或不支持的 DOCX 图片资源会明确停止 EPUB 导出。PDF 矢量绘图、DOCX 表格和文本框尚未自动纳入；检测到时列入导出说明，不声称已完整保留。
- 缺译单元沿用现有交付规则：允许导出已有译文，缺译位置留空，在应用内导出范围和报告中列出数量。

`epub_export_report.json` 记录图片数量、正文部分数、原文图注数、缺译数量及范围说明；交付页「查看导出范围」也展示这些信息。电子书不插入生成的书名页或技术说明页。

PDF 的首张无文本图片页整页保留为原书封面；DOCX 的首个正文元素为图片时将其作为封面。封面放在阅读顺序首位，并标记为阅读器封面，正文不重复该图片。未识别到独立封面的文件直接从正文开始。

正文目录（CONTENTS / Table of Contents / 目录）条目与后续章节标题按原文匹配，唯一匹配且有译文时建立章节锚点链接；无匹配或重名条目保留文字。阅读器自带的章节目录仍可使用。

## 来源关联

源文件继续保存在任务的 `source.bin`；图片在导出时读取，不把图片字节重复放入任务 JSON。来源段落引用存于 pair 的 `epub_source_paragraphs`，利用现有清洗 `output_input_indices` 和分句结构建立关联。

拆分继承来源引用，合并保留双方来源引用，插入单元沿用邻近段落位置；排除、恢复和撤销随原有 pair 记录保留来源。EPUB 将同一来源段落的连续句子译文合回阅读段落，图片独立存在，因此排除文字不会顺带删除图片。

跨图片边界合并时，完整合并译文位于图片之前；不根据原文字符比例猜测译文中的图片位置。未经结构编辑的旧任务可以验证原文与初始分句后恢复关联；已编辑且没有来源引用的旧任务会明确提示重新建立关联。

## 验证

`tests/epub_export_test.py` 使用实际生成的 PDF/DOCX 验证图文顺序、图注、句子重组、清洗合并、人工拆分/合并/排除/恢复/撤销、独立插图页、源文件不一致、缺译、XML 转义、资源引用、交付快照和两个界面入口。

EPUB 由 Python 标准库打包，复用已有 PyMuPDF 和 python-docx，不增加运行时依赖。包含 EPUB 3 导航和 NCX 目录、书名、目标语言元数据、章节 XHTML、简单流式 CSS 及本地图片资源。

本次验证：EPUB、交付界面、交付快照和分句四组测试共 45 项通过；段落生命周期及缺译交付扩展测试共 28 项通过、2 项失败。失败项为 `test_exclude_rejects_empty_and_unknown_segments` 和 `test_segment_identity_is_stable_across_structural_edits`；将新增 `bind_source_references` 禁用后仍逐项复现，不属于这次 EPUB 来源关联引入的失败。没有为通过测试而修改原有段落编辑逻辑。
