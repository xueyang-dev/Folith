# Web UI 高、中优先级性能修复

2026-10-01。保留工作区已有修改；本轮针对实际工作台执行路径修改。

## 已实施

- 任务选择列表读取 `summary.json`；历史与语言资产页面需要完整数据时再读取任务状态。普通工作台不再加载所有任务的完整译文。
- 一次工作台渲染共享 planner findings；顶栏、任务概览和翻译区不再分别扫描全部段落。术语源文匹配复用编译模式。
- 问题抽屉也复用这份 findings，展示列表与统计不再额外扫描全文；回归守住打开抽屉时扫描总数仍为一次。
- 40 行工作台共享段落状态投影和轻量运行状态；投影中的审校队列按段落建立索引。
- 有正数 limit 的运行日志请求从文件尾部读取完整行，先过滤再截取，保持原来的时间顺序。无 limit 和负数 limit 保留原有语义。
- 当前段落审校、重译与审校队列的相应动作交给已有后台 worker，复用心跳、暂停、取消和错误展示。处理中允许切换任务，当前任务的修改暂时锁定，完成后重新载入结果并重建译文编辑器；段落失败不会误显示成功，也不会提供整条流水线的继续按钮。
- 后台段落操作期间拒绝其他标签页保存完整任务快照，防止覆盖后台结果。
- 修复保存快照时按数组位置回填旧译文的问题：明确清空译文和拆分出的空译文必须原样保存。旧逻辑会覆盖新源文与段落身份，造成重复编辑器 key。保存成功后重跑应用，重新计算页头和段落状态。
- 概览函数明确承诺异常输入降级为草稿；修复 `pairs="bad"` 导致审校派生函数报错的情况，保持这项公开函数约定。

本轮确认：实际界面只挂载选中行的完整操作菜单，因此早期“40 行各读一次日志”的估算不适用。性能收益来自尾部读取，以及各行共享状态计算。

## 本机测量

使用现有 8 个任务；最大任务 4,845 段；日志 10,264 行、3,033,391 字节。预热后取中位数；这是局部代码路径的测量，不是整页加载时间或浏览器帧率。

| 路径 | 先前方式 | 当前方式 |
| --- | ---: | ---: |
| 任务列表：读取完整状态 / 读取摘要 | 285.30 ms | 0.33 ms |
| 40 次段落状态投影 / 共享一次投影 | 149.45 ms | 3.66 ms |
| 最近 5 条事件：全文件解析 / 尾部读取 | 22.88 ms | 0.04 ms |

完整 planner 单次扫描约 264.86 ms；正常工作台渲染由多处重复调用变为一次，未写入数据的内部翻译 fragment 操作复用该结果。保存和结构操作触发完整刷新，避免派生状态过期。日志测量同时验证了新旧结果完全一致。

## 真实浏览器检查

使用本机 Chromium，在独立输出目录建立 4,845 段测试任务、启动独立 Streamlit 进程。没有修改实际任务数据或调用模型。结果与截图保存在 [浏览器测量](ui-audit/web-hotpath/result.json) 与 [保存后工作台](ui-audit/web-hotpath/workspace.png)。

- 初次渲染 planner 调用一次；真实输入触发的 fragment 刷新与切换段落各增加零次；保存后完整刷新增加一次。
- 完成渲染后挂载 40 个译文编辑器。
- 切换段落再返回后，浏览器中的草稿保持原值。
- 保存后验证浏览器译文值与磁盘快照一致，成功提示显示；未捕获浏览器脚本错误。
- 这次冷启动首屏约 6.8 秒，包含应用／浏览器初始化，没有旧版对照，不能据此声称首屏加速。

后台模型调用使用 mock 验证线程、任务切换、失败、取消与结果回填，没有调用真实模型服务。取消沿用现有机制，在途外部调用的停止时机仍取决于原有请求控制。真实浏览器的草稿保留与保存已验证，键盘焦点回位、滚动帧率和实际模型网络延迟未验证。没有因文件行数长而直接拆分 `app.py`、`core.py`；本轮处理的是影响响应速度与正确性的执行路径。
