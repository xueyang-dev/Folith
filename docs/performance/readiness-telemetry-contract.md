# Readiness and operation telemetry

Draft readiness checks authoritative missing scan pages and target-structure validation. Translation readiness reuses required review coverage and unresolved blockers. Selected reports must satisfy the existing final report gate. Human delivery approval/render/snapshot requirements remain separate.

Ready milestones are written only when the current predicate passes, retain the authoritative translation version (including zero) and selected policy, and preserve the first timestamp for that version/policy. Historical timestamps do not prove current readiness.

Translation, repair, independent review, knowledge feedback, annotation, understanding and terminology use explicit operation IDs at their real call boundaries. Routing role remains separate from operation attribution. Metadata contains identities/counts rather than prompts or credentials.

This observability change makes no generation-speed or quality-improvement claim. It does not enable pipeline overlap or change production batching/scheduler defaults.
