# P6 通知层与任务库（2026-10-15）

分支 `feat/0.6-native-workbench`。P6 的实现已完成；以下区分自动验证与仍需人工签收的项目。没有 push，也没有开始 P9 / P10。

## 实现与边界

- 移除主窗口底部状态栏，提供与展示方式无关的 `last_notice()` 查询并迁移原有测试。
- 按实际入口逐项归类 54 个 `_failure`，连同 `_critical` / `_confirm` 共 78 个入口；见 [通知归类表](notification-routing.md)。任务消息进入运行状态组与已有用户运行日志，全局结果使用顶部轻提示。删除、覆盖、退出、风险接受与输入等必要决定保留原对话框。
- 轻提示 3 秒后淡出；悬停、键盘焦点保留；替换消息时取消旧淡出。关闭按钮可用键盘，显示不改变编辑器焦点。长消息折叠摘要，非模态详情保留完整、可选择的文字。尊重减少动态效果 / 减少透明度；背景使用不透明主题 token。
- 任务错误不会改写流水线状态。运行记录保留最近 50 条，完整错误原因与技术详情可选择查看；流水线提供重试动作时显示“重试当前步骤”（沿用核心的准备重试语义，不擅自启动另一种操作）。向上翻阅时追加不强制跳到底部，选中的消息按内容保留。完整日志继续可在 Finder 中显示。
- 异步启动、编辑、审校、重译与交付捕获原任务编号。切走后仍记录到原任务，在其他页面用轻提示提醒；日志写入失败仍将原因留在轻提示详情中。凭据按既有日志规则隐去。
- 任务卡进度线从实时阶段计数或保存的翻译段数获得百分比，使用和工作台相同的状态判定与蓝 / 琥珀 / 红 / 灰 / 绿语义；暂停、失败、完成后仍显示已有进度。颜色同时配合文字说明。
- 卡片问题图标与工作台共用七类检查事实，数量指“检查与修复”的问题类别数，而非段数或底层 finding 条数；点击直接打开对应任务的检查侧栏。恢复提示只在非活动状态计数，沿用抽屉的黄色严重程度。
- 新摘要在已有保存路径写入状态文案、进度与问题事实；任务库不会为了角标重算全文。旧摘要缺字段时沿用只读 state 回退，下次正常保存后使用新摘要，不在列表读取中写盘。已有交付快照的完整性检查仍可能读取任务和资产，本批没有改变该检查。
- 新增文案追加到 5 个 Qt locale；轻提示、卡片进度方向、问题图标布局支持 RTL。

## 性能

- 3856 段 / 23.6 MB 原任务隔离副本，使用既有 `p1_idle_refresh.py`，offscreen：打开 728 ms；未变化时 6 次刷新为 16 / 16 / 16 / 16 / 16 / 39 ms。与 P1 的约 0.7 秒打开量级一致；不是对 P4 严格 16 ms 帧指标的通过声明。
- `p6_notifications.py` 的 5 任务列表 20 次读取：中位 0.75 ms，最大 1.14 ms，完整状态读取 0 次；原始值见 [metrics.json](metrics.json)。样本不含交付快照。
- 真实 3856 段状态的新增检查摘要计算：首次 59.6 ms，后四次 15.8–16.4 ms。发生在已有状态保存路径；旧摘要的首次读取回退也需要此计算，不承诺首次读旧任务等同新摘要的耗时。
