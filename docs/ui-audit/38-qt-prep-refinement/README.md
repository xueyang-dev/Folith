# 译前准备 · 配置解耦 + 界面压缩 + 收尾加固

日期：2026-10-10 · 界面：桌面端（PySide6 / cocoa，**离屏 + 真实窗口各一套**）· 主题：浅色 / 夜间 / 纸面

## 起因（两条，一条是缺陷、一条是密度）

1. **P0 配置耦合**：试用反馈"换翻译模式会把交付方案重置掉"。译者挑好 DOCX / PDF / EPUB 之后
   回头把模式从「标准」改成「精细」，产物清单被清空 —— 一个决定悄悄覆盖了另一个决定。
2. **密度**：输入与上下文这一块四项平铺，其中「文档识别」（这个文档怎么读成文字）常年占用
   一整屏；交付内容用四张按格式分的卡片，与"需要产出什么"这个真实决策无关。

## 一、P0：换模式不许动交付（根因 + 归属）

**根因**：`setup_panel._on_strategy_preset` 当年是照 Web 向导的 `_apply_preset` 抄的，而 Web
那边**顺手重置交付是合法的** —— 它的向导把"翻译策略"和"产物清单"放在**两个步骤**上，
重置的那一刻用户还没做过交付决定，重置等于给出初始默认值。桌面面板把两个决定放在**同一屏**，
同一个动作就变成了"抹掉用户刚做的选择"。

**归属定案**（每个决定只写自己的字段）：

| 动作 | 可以改 | 不可以改 |
|---|---|---|
| 选翻译模式 / 恢复「x」默认 | 策略 8 个字段 | 交付包、OCR、目标语言、项目 |
| 选交付方案 / 勾产物 | 交付包（+ 子项归一） | 策略字段、OCR、目标语言、项目 |
| **初始默认值** | 全部 | —— 由 `adapter.task_setup_view` 的 `pending` 分支负责，与"用户改过的值"是两件事 |

`payload()` 永远提交全量，所以**可见的耦合就是真实的耦合**：面板不重置，写回就不重置。
`_sync_delivery_preset_label` 是**从勾选反推**方案名（不是存了一个键），所以去掉重置不影响持久化。

## 二、界面压缩（信息架构，不是间距）

### 2.1 输入与上下文 → 两组

| 组 | 内容 | 可见性 |
|---|---|---|
| 主要设置 | 目标语言 / 归入项目 / 术语库 | 常驻（一行一个字段，术语库压成"标签 + 值"单行，说明进 tooltip） |
| **文档识别** | 建立文档画像 / 提取来源 / 何时识别 / 识别语言 / 识别精度 | 整组收进 `DisclosureSection` |

**折叠头右侧的摘要已经把答案写出来了**，这是"收起来"不等于"藏起来"的关键：

| 任务 | 折叠态摘要 |
|---|---|
| PDF（默认，VLM 路径） | `视觉理解 · 自动判断 · 含文档画像` |
| PDF + 本机 Tesseract | `本机 OCR · Tesseract · 自动判断 · 含文档画像` |
| DOCX | `文本层解析 · 含文档画像` |

**可执行的错误挂在折叠头右侧，收起时照样看得见** —— 选了本机 OCR 却没指定识别语言时，
核心会静默退回英语（`core.py:1344/1370` 的 `ocr_language or "eng"`），所以折叠态显示
`未指定识别语言，本机 OCR 会退回英语`（截图 `08a-localocr-collapsed-*`）。

**VLM 是主路径、OCR 是兜底**，本轮没有重新架构提取管线：只把管线已有的事实摆到折叠头这一行。
`识别精度` 只在本机 OCR 时出现（VLM 路径在 `core.py:2336` 固定 `dpi=150`，留一个转了没反应的
旋钮比缺一个选项更糟）；`识别语言` 不隐藏，只换说明（两条路径都要它，含义不同）。

### 2.2 翻译设置：三层没动，只改间距与对齐

① 翻译模式（主决定，三个横排选项）→ ② 内容处理（每行一项）→ ③ 高级设置（默认收起）。
折叠头改用与「文档识别」同一个 `DisclosureSection` 组件，去掉两处各不相同的实现。

### 2.3 交付内容 → 三组、两栏、0 张按格式分的卡片

| 组 | 内容 |
|---|---|
| 交付方案 | 四档分段控件 + **一行实时汇总** |
| 译文文件 | 纯译文 DOCX / 双语对照 DOCX / 标记术语 / 纯译文 PDF / 原排版 PDF / 电子书 |
| 语言资产 | 术语表 XLSX / 翻译记忆 TMX / 标准术语库 TBX / 结构化数据 JSONL |
| 研究产物 | 报告 / 证据 / 案例 / 学术工作区 / 审校报告（按策略显隐）+ 理论框架 |

实时汇总把"方案"与"事实"对上：`将生成 3 个文件 · DOCX ×2 · XLSX ×1`；
勾了 EPUB + TBX + 报告之后是 `将生成 7 个文件 · DOCX ×3 · EPUB ×1 · XLSX ×1 · TBX ×1 · MD ×1`
（docx 3 = 纯译文 + 双语对照 + 报告自带 MD/DOCX；截图 `04-delivery-*` 可逐个核对）。
**所有产物的内部键一个都没改**（`deliver_plain_docx` … `deliver_review_report`），
只是不再为每个格式做一张卡片。

### 2.4 新增：交付子项的显示 = 将被提交的事实

`标记术语与翻译难点` 是「双语对照」的**子项**：父项没勾时它换不来任何产物。
`payload()` 与 `_sync_delivery_summary()` 早就按这条办，但 `load()` 不办 —— 于是一个从别处
（Web 向导 / 共享命令）带进来的 `enable_annotate=True` + 双语关闭的任务，会显示一个**勾着却
什么都不会发生**的复选框。现在三个入口（回填 / 勾选 / 套用交付方案）统一走
`_normalise_delivery_child()`。这与 archive-35 的 `project_id` 事故同源：**控件在、样式在、功能不在**。

## 三、文案与 i18n

**显示名可以翻译，取值一个都不许动。** 目录标签统一在显示层过 `i18n.tr()`
（`ModeSelector.set_options` / `_fill_combo` / `_build_delivery_boxes` / `set_choices`…），
写回任务的永远是键或 `currentData()`。刻意**不过** i18n 的两类：
语言自称（简体中文 / English / العربية…）与项目名（**用户数据** —— 一个叫「标准」的项目会被
静默改写成 "Standard"）。回归用例 `test_user_data_and_language_endonyms_are_never_sent_to_i18n`
与 `test_a_translated_display_name_is_never_used_as_a_value` 钉住这两条。

同一组开关在设置对话框里也用了新词（`自动识别术语` / `使用翻译记忆` / `译后自动审校` /
`建立文档画像`），两个面不再各叫一个名字（archive-37 遗留 3 已关闭）。

五语目录各 +7 键（410 → 417，**键集完全一致**）：本轮 4 条面板文案
（`自动识别术语` / `使用翻译记忆` / `译后自动审校` / `建立文档画像`）+ window.py 的 3 条。
译文取自**目录里已复核的近邻条目**（如 es `Crear un perfil del documento`），不是机器翻译。

## 八、遗留

1. **i18n 覆盖率**：面板自己的短标签（`翻译模式` / `内容处理` / `文本切分方式` / `按句` /
   `按段` / `术语库` / `语言资产` / `交付方案` / `提取来源` / `识别精度` …）在 en / es / ru / ar
   仍回退中文 —— `scripts/qt_i18n_coverage.py` 报 `393/455，缺 62`（setup_panel.py 占 40）。
   这是**仓库既有约定**（中文原文即键，缺条目回退原文并由脚本如实报告），且
   `qt_i18n_test.py` 要求五语键集完全一致，不能只补一门。本轮把**机制**接通了
   （标签真的过 `tr()` 了，以前不过），没有手写这批译文 —— 手写等于凭空造翻译。
2. **`开始翻译` 在首屏折叠线之下**：面板自然高 904（视口 639），按钮在滚动区**内部**
   （`inScroll=True`，面板 y=874），所以要滚到底才能提交。**这不是本轮引入的**：
   archive-37 记录的 1331 高面板同构。修它要把页脚移出滚动区、改成工作台的固定动作条，
   属于 workbench 结构改动，按简报的范围纪律本轮不做。
3. **`docs/ui-audit/38-*` 尚未提交**：与 27–37 一样留作未跟踪归档；提交范围需先与用户商定。
