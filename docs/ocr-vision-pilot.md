# 《علم الدين》原图校对试验

2026-10-03。试验脚本和结果保存在 `benchmark/ocr-vision-pilot/`。本试验当时没有改动应用的 OCR、校对默认配置。

## 结论

这次结果支持为历史阿拉伯语扫描书加入原图识别。新增两个页面片段上，微调 Paddle 的字符错误率为 **7.62%**，现有文字校对流程为 **6.13%**，OCR 加原图校对为 **2.54%**，独立看图转写为 **1.05%**。四个片段合计也有相同趋势。

但不能由此断言独立转写一定更好：新增片段中，忽略 hamza、变音符号和部分字形变体的诊断 CER，两种看图方法均为 **1.05%**。带图校对的部分差距来自补入现代拼写符号。独立转写也会误读完整词。

建议下一步在已有微调 Paddle 的行框基础上，增加**独立看图转写的候选**，把它与 OCR 候选对照，定位分歧并链接原图供复核。带图校对仍可作为候选，但不宜直接把流畅的校对结果认作扫描原文。此次只完成可复现的试验，尚未接入正式工作流；自动选择候选或整本替换的准确率也未验证。

## 方法与请求设置

| 方法 | 模型 | 输入与处理 |
| --- | --- | --- |
| 微调 Paddle 原文 | 本地阿拉伯语 PP-OCR 模型 | 原生识别行，未经过大模型 |
| 现有文字校对流程 | `deepseek-v4.1-flash` | 保存配置中的文字模型，调用现有 `cleanup_source_paragraphs` 提示词、JSON 校验和最小改动保护 |
| 同一视觉模型只看文字 | `deepseek-v4-flash-vision-exp` | 与带图校对相同的提示词，只省去图像，用于区分原图作用与换模型作用 |
| OCR 加原图校对 | 同上 | OCR 候选及原图，同样经过现有校对校验与保护 |
| 独立看图转写 | 同上 | 只给图像，要求按印刷行忠实转写，不提供 OCR；保留 JSON 索引校验，不使用与 OCR 的相似度保护 |

API 使用已有 OpenCode Go 账户与密钥。主对照的全部请求统一设置 `thinking: {type: disabled}`、`max_tokens: 4096`、`temperature: 0`，没有自动重试。16 个请求全部返回有效结果，每个片段每种方法各调用一次。

**文字校对一栏代表现有流程与模型在上述试验设置下的效果，不等于应用默认推理模式的效果。** 初始默认推理请求在 4096 token 上限下没有得到校对内容；一个视觉模型纯文字请求提高到 16384 后仍耗尽推理额度。另对两个新片段补测文字模型 `reasoning_effort: low`、8192 上限，也都在额度耗尽后截断，没有返回校对正文；结果另存 `probes/low-reasoning/`，不混入主表。截断后现有校对流程正确地保留原文，试验将其标为失败/partial，未计作成功校对。这是本次服务与请求设置的失败，不能据此认定文字模型没有纠错能力，也没有验证其默认、不设输出上限时的最终准确率。

推理控制依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。主对照的文字模型返回 `reasoning_tokens: 0`；视觉模型没有报告该细项，返回的 completion token 数量与短 JSON 正文规模相符。模型使用范围参考 [OpenCode Go 文档](https://opencode.ai/docs/go/)。这只是试验请求参数，保存的 provider 配置没有改动。

## 主要结果：新增两页片段

CER 按全部参考字符加权，WER 按全部参考词加权；空白统一，物理换行不作为字符错误。折叠 CER 是附加诊断，合并 hamza/alef、ى/ي、ة/ه 等变体并去除变音符号，**会掩盖部分真实字形错误，不能替代原始 CER**。

| 方法 | CER | 折叠 CER | WER | 两次调用总耗时 | API 总 tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 微调 Paddle 原文 | 7.62% | 7.17% | 35.71% | — | 0 |
| 现有文字校对流程 | 6.13% | 5.68% | 26.98% | 11.38 秒 | 1451 |
| 同一视觉模型只看文字 | 5.98% | 5.38% | 25.40% | 4.44 秒 | 1558 |
| OCR 加原图校对 | 2.54% | 1.05% | 11.11% | 6.57 秒 | 2893 |
| 独立看图转写 | **1.05%** | **1.05%** | **3.97%** | 5.62 秒 | 1999 |

从同一视觉模型的文字对照到加图，CER 从 5.98% 降至 2.54%，支持原图本身带来的收益；这不是单纯更换模型的结果。独立转写的 token 开销较低，因为不需要在输入中再附整份 OCR 候选。本次耗时是单次测量，受网络、缓存和服务负载影响，不能外推为整书速度。

| 新片段 | 原 OCR 的编辑错误数 | 文字校对后 | 视觉模型文字对照后 | 带图校对后 | 独立转写后 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第 121 页，324 字符 | 26 | 26 | 26 | 7 | 5 |
| 第 301 页，345 字符 | 25 | 15 | 14 | 10 | 2 |
| 合计 | **51** | **41** | **40** | **17** | **7** |

相对原 OCR，文字校对净减少 10 次编辑错误，带图校对净减少 34 次，独立转写净减少 44 次。模型没有做到零误改：以最小编辑对齐的参考字符位置统计，三者分别修正 11/40/43 个原错误位置，同时引入 1/7/4 个新错误位置；额外插入字符分别为 5/4/0。位置统计受对齐并列解影响，不能与 CER 编辑数简单相加，也不能把每个新位置都解释成一个新错词。

主对照 16 个请求合计 **18,947 tokens**。连同参数试跑与失败请求，共记录 **30 次返回、106,087 tokens**（其中服务报告 73,407 reasoning tokens），另有 **1 次主动中止请求，消耗未知**。10 次截断失败也包含在该消耗中，未从账目中删除。实际金额取决于订阅与 provider 计费，接口未返回金额，因此不估算费用。主表的耗时不包括已经缓存的 Paddle 渲染/识别，也不包括这些失败试跑。

## 对照原图看到的具体错误

1. 第 121 页原图是 `بحادثة`。OCR 读成 `مجادة`，带图校对返回 `بمجادة`，保留了错误的词干；独立转写返回 `بجاذبة`，也误读这个词。这支持“错误 OCR 候选可能干扰校对”的猜想，但一个例子不能定量证明干扰机制，视觉模型自身也确实有识别错误。
2. 同页原图的 `ويتركوها`、`تقادم`，带图校对保留正确形式，独立转写分别漏成 `ويتركوا`、`تقدم`。独立转写的较低总 CER 不代表每个词都更好。
3. 第 301 页原图是 `صحة`。OCR 的 `محة` 被纯文字校对改成 `محبة`，变得像一个合法词，却离扫描原文更远；两个看图方法均识别为 `صحة`。这是原图能提供文字上下文没有的证据的直接例子。
4. 第 301 页带图校对补入若干 hamza 和变音符号，例如 `ايام` → `أيام`、`اخبر` → `أخبر`。参考没有这些符号，扫描也没有可靠清晰的相应符号。该片段原始 CER 为 2.90%，折叠后仅 0.29%；独立转写分别为 0.58% 和 0.58%。因此要区分误读词干与历史拼写的处理偏差。

正文行已经正确按阅读顺序输入；CER 又统一了换行。本试验显示的提升主要是字词修复，不是把换行拼起来造成的分数提升。污渍、模糊印刷与字母点画断裂仍可在图中看到，但这里没有单独操纵这些因素，不能给它们分配误差占比。

## 可复现与后续验证

输入、参考和 Paddle 原生证据位置保存在 `benchmark/ocr-vision-pilot/dataset.json`。每次请求的模型、提示词、图像是否附带、原始响应、usage、完成状态和校对 metadata 保存在相应 `page-XXXX-MODE.json`；没有保存密钥或图像 base64。请求 journal 同时保留开始和失败记录。试跑与截断记录位于 `probes/`，主汇总只使用一致的完整对照。

```sh
.venv/paddle/bin/python benchmark/run_ocr_vision_pilot.py prepare
.venv/paddle/bin/python benchmark/run_ocr_vision_pilot.py run \
  --thinking disabled --max-tokens 4096 --max-calls 16
.venv/paddle/bin/python benchmark/run_ocr_vision_pilot.py summarize
venv/bin/python -m pytest tests/ocr_vision_pilot_test.py -q
```

脚本会保留已有结果，拒绝直接复用模型、原图区域或推理模式不一致的记录。复跑需要用 `--result-subdir` 保存另一组结果；主汇总仍针对原对照。渲染裁图目前在 `.audit/ocr-vision-pilot/`，可由 `prepare` 重建。`prepare` 对已有 Paddle 记录使用缓存；重新评估一个不同 OCR checkpoint 应另建数据和输出，避免混用。

测量测试覆盖重复阿拉伯语的编辑对齐、修正与新误改分开统计、插入字符计数、图像输入构造、以及新增页面与训练/选择页面隔离。既有旧脚本用 `SequenceMatcher` 计算的某些“修复字符数”会受重复文本的 autojunk 影响；本试验用最小编辑动态规划，原始 CER/WER 算法没有更换。

后续最有价值的验证是：专家审定参考；扩大到未使用过的整页与不同扫描质量；比较原 OCR、独立视觉转写与分歧复核后的最终文本。尚未验证整页遗漏、跨片段接缝、页边注释或其他书籍，因此当前结果支持试接图像候选，尚不足以把全书原文自动替换为视觉输出。
