# Folith 0.8.1 发布说明与验收矩阵

状态：**已发布（2026-11-10）**。tag `v0.8.1` 指向 main `8ae08083`，[GitHub Release](https://github.com/xueyang-dev/Folith/releases/tag/v0.8.1) 附 macOS DMG、Windows 安装版与便携版及 SHA256SUMS。macOS 包未签名未公证；Windows 真机原生验收尚未完成，见下方核对表。

## 版本变化

见 [CHANGELOG](../CHANGELOG.md) 的 0.8.1 条目：智能 QA 分诊（实验，默认关闭，按任务在审校页打开）、分段结构编辑的位置列不变量、思考关闭试用的遗留修复（思考开关作用范围、400 诊断与一次宽限重试、失败记录页码、点引导行 copy-through）、性能报告（真实数据集数字、独占阶段耗时、协议重试观测）、视觉读页用量追踪与任务成本报告，术语卡决定参考字段，简体中文 QA 检测器的编码规则重写，批量统一译名对话框，CJK 子串替换修复（#308），以及 UI 线程崩溃修复（#311）。0.8.0 之后的稳定化修复也在本版：打开大任务不再逐格刷新、Windows `Ctrl+Alt+P`、暂停后继续改用新连接、审校文案本地化、模型能力误配警告。

### 本版新增的界面与交付范围（2026-11-07 起并入）

除上面 CHANGELOG 列出的修复与 QA 分诊外，本版还包含这些改动（均未经原生人工验收，见下方核对表）：

- **界面重做（2026-11-04 设计审查 F1–F20）**：次要文字对比度、最小窗口宽度、矮窗口里「开始翻译」始终可见、任务封面、状态与说法统一。未覆盖：网格正文行距、设置页部分图标语义。
- **交付页重做**：冻结后按「译文 / 双语对照 / 术语表」列出成果，顶部显示版本、文件数、总大小与时间，提供「下载全部（ZIP）」「打开文件夹」「另存交付文件…」。
- **智能 QA 决策工作台**：审校页改为队列 / 译文 / 证据三栏，自动处理开关与批量统一译名按钮在顶部工具条。
- **EPUB 来源保留插图**：译文的 EPUB 与 DOCX 交付带上原书图片并放回原位置；个别无法转换的图片写入导出报告。
- **macOS 辅助功能崩溃修复**：针对上游 Qt 缺陷 QTBUG-149612 的运行时修复，只对 Qt 6.11.x / 6.12.0 安装；`FOLITH_QT_AX_WORKAROUND=0` 可跳过，仅用于诊断。
- **交付页布局**：分组卡片等先挂载子布局再填充，避免重建后留下失效的 PySide 包装器（`tests/qt_layout_item_wrapper_test.py`）。

### 汉字检测器变更说明

「繁体／日文汉字未转换」检测器改为基于编码的规则。**此变更仅对新检测结果生效；已保存的发现不会被改写**；无论分诊开关开启与否均适用，与该开关（默认关闭）无关。检测结果不再建议对应简体字形，而是报告具体字符并要求人工核查。如需了解规则细节，见 CHANGELOG 0.8.1「确定性 QA：汉字检测规则」条目。

### CJK 替换修复（#308）已知限制

`safe_replace()` 保护所有在术语表或实体登记中已注册的更长形式不被较短变体覆盖。**未登记的更长词仍可能被替换**——展开批量统一对话框中的修改预览是应用前的最终确认手段。

## 已知限制

- **智能 QA 分诊是默认关闭的实验功能**：关闭时行为与 0.8.0 一致。打开后只处理有确定性证据的发现，效果目前很小：作者本机 12 个真实任务的副本上，队列里的发现从 1,225 条减到 1,214 条（11 条 orthographic_equivalence 自动处理；离线观察，任务未做过专门的概念决定，不是 HIR 度量）。传统字/简体字的差异（如「河東」/「河东」）不再被视为可等价，改为要求括号外形差异（如「〈奏谳书〉」/「奏谳书」）。整段与原文相同的短汉字段不会被放行，因为其中混有真错误。
- **运行时只接通了「已核验安全」这一步**：确定性自动修复（#288）与批量模型升级（#291）都已实现但**未接入运行时**，不会自动改译文，也不会在翻译流程里发模型请求。
- **没有真实标注语料，故不报任何 HIR / 严重缺陷逃逸（CDE）/ 精确率 / 召回率**。`scripts/qa_triage_measure.py` 在四类标签齐全的语料存在前拒绝输出比率；仓库内只有人造种子语料，其数字仅为夹具结果，不是真实任务的质量结论。
- **任务成本只报调用次数与 token，不报美元金额**：仓库没有该服务商的价目表，`folith/cost_report.py` 不编造单价。补一份可维护价目表以显示金额见 [#304](https://github.com/xueyang-dev/Folith/issues/304)。
- **Windows `Ctrl+Alt+P` 仍需一次真人按键确认**（#276）。本机拦截可能来自系统全局热键或只丢弃注入按键的钩子，自动化环境无法区分；真人手动按一次、看原页左栏是否开合即可完成该项验收。
- **竖排日文扫描书（列序、ruby、跨页）不在本版**（[#219](https://github.com/xueyang-dev/Folith/issues/219)，已移到 v0.8.2），需要有真实扫描样本与真机 VLM 验收后另行处理。
- **#220 剩余项留待后续**（[#220](https://github.com/xueyang-dev/Folith/issues/220)，已移到 v0.8.2，不阻塞本版）：B5（坏回复 / 表格页复现研究）、C1（HTTP 502 与视觉并发建议）、D2（跨语言部分残留检测，较大功能）、F1 / F2（测试环境与个别测试的隔离问题）。协议重试在真实体文本上的比率也仍需真实连接复测。
- 0.8.0 已列的其余已知限制仍适用：macOS 包未签名未公证、最低系统 macOS 15.8.1、保留原版式 PDF 在扫描件上只能尽力还原、阿拉伯语 RTL 与部分语言的语义 / 字体真机验收未完成、随包 OCR 基线为 Tesseract eng / chi_sim / ara。
- **界面线程原生崩溃：已修已确认的来源，不保证全部消除。** 作者 macOS 机器上 0.8.0 试用期出现过两次界面线程崩溃。本版修了已确认的来源：QTBUG-149612 的 AX 崩溃、交付页与 `PdfPanel` 的失效布局包装器（后者是冻结 App 在 CI 里间歇崩溃的主因：构造时先填充再 `addLayout`，折行时 Qt 删除旧条目而包装器仍登记，见 #316）、#311 的同类修复。修复后 main 上连续三次候选验证通过，但这不能证明已全部消除；`motion.py` 构造动画对象处的崩溃另有本机记录，原因没有确认。遇到闪退请在 Issue 里附诊断包（关于 → 诊断）。
- **实验性界面语言（#17，已移到 v0.8.2）**：en / es / ru 等界面语言的语义、字体与 RTL 真机验收仍待人工。
- **本机测试里 3 条顺序相关失败**（`qt_layout_item_wrapper_test` 两条、`qt_terms_panel_test` 一条）在 main 上同样存在，单独运行通过，不是本版回归。
- 自动化（CI、offscreen、mock 平台）不能代替真实 Cocoa / Windows 原生窗口验收。
