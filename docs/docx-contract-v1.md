# Folith / 译页 DOCX Contract v1

状态：2026-10-26 已完成垂直切片实现并通过全部契约验收测试（Issue #26，实现见 `folith/docx_roundtrip.py`，测试与 fixtures 见 `tests/docx_contract_v1_test.py` 及 `tests/fixtures/docx_contract/`）。本文档定义的技术规范与 6 项验收核查全部通过。

## 交付承诺

> Supported correctly, preserved safely, or rejected explicitly.

支持的内容正确翻译，不支持的内容安全保留或明确拒绝；保留但未翻译的内容必须让用户看得见。禁止静默丢失或破坏内容。结构保真不等于分页一致：译文长度会改变换行和页数，不承诺与原文逐页相同。

## Surgical round-trip

```text
保留原 DOCX package 和源版本
  → 识别可翻译范围、受保护结构与不支持内容
  → 提取带 inline 标记的单元，建立 source anchor
  → 翻译 / 人工编辑 / tag QA / 独立审校
  → 在源版本的声明范围内写回 XML
  → 验证输出、呈现未翻译内容、通过既有交付门禁
```

- 保留原文件，导出到新的目标文件。原 package 是写回基础，不使用空白文档重建来实现此契约。
- 未修改的 ZIP 条目，其解压后内容字节保持一致。包括不需要修改的 styles、numbering、relationships、media、customXML 等资源。
- 修改的 XML part 只允许声明的文本与必要 inline 放置发生变化；不能只验证整个 part 可解析就算保真。XML 序列化的前缀、属性顺序不属于内容变化；结构和引用语义必须保持。
- 不要求整个 ZIP 字节相同，也不要求保留压缩字节、条目时间戳等容器元数据。
- 翻译单元允许跨多个 `w:t` / run。不得逐节点孤立翻译，也不得按原字符长度机械分配译文。
- 保留格式和链接的语义归属，允许在受控范围内随目标语言词序调整；不能把“标签个数相等”当成校验完成。
- 如无法可靠定位或表达某个单元，必须报告并停止其写回，不能猜测位置或退回重建整份文档。
- 现有纯译文/双语重建导出可以继续存在，但不得标注为原格式保真输出。

## v1 支持范围

以下策略是计划中的产品边界，须通过下文 fixtures 才能宣布支持。

| 内容 | v1 策略 | 可观察结果 |
| --- | --- | --- |
| 普通正文、多段落 | Translate | 全部范围内文本有单元映射和译文 |
| 表格文本 | Translate | 翻译单元格内段落，保留表格、合并单元格及结构 |
| bold / italic / 基本 inline 格式 | Preserve | 格式随所对应的目标内容保留；不将其误当纯字符串 |
| 超链接显示文字 | Translate | 显示文字翻译，链接语义归属正确 |
| 超链接目标 | Preserve | 外链 relationship 或内部 anchor 不变 |
| 脚注 | Translate | 翻译普通脚注文本，保留引用 ID、引用标记及分隔结构 |
| 页眉 / 页脚 | Translate + Protected | 翻译普通文本，保留节引用；共享 part 只处理一次，字段受保护 |
| 文本框 | Preserve + report | 保留原文和结构，导入与交付报告列出未翻译内容 |
| 字段 | Protected | 保护简单/复杂字段的指令与结果；不承诺自动刷新，依赖 Word 刷新的显示值需明确说明 |
| 批注 | Preserve | 保留内容、作者等元数据及范围标记；批注内容不翻译并列入报告 |
| 未决 Track Changes | Reject | 翻译前明确拒绝；用户在副本中处理修订后重新导入，系统不自动接受或拒绝修订 |
| 公式、图片 | Preserve | 保留对象、引用与资源；其中未翻译文字列入能力说明 |
| 其他结构（如尾注、内容控件、嵌入对象） | Preserve + report，无法保证时 Reject | 不声称支持翻译；不得落入正文兜底提取后静默改变 |

“基本 inline 格式”的具体支持元素由首批 fixture 与 adapter 提取规则共同界定，发布时必须列出范围，不能作为所有 Word 格式的泛称。书签等范围标记即使横跨单元也不得丢失或损坏。

能力检查在模型调用前执行。保留但未翻译的范围必须可定位，并进入交付清单；不得将它计为已翻译。结构损坏不能通过语义风险接受绕过交付门禁。不引入逐内部步骤的额外确认。

## 最小双语模型与身份

模型随本闭环建立，不先构建覆盖所有格式的通用框架。概念必须区分，但本文不预设新的持久化 schema 或迁移框架。

| 概念 | 责任 |
| --- | --- |
| Source version | 绑定原始 package 及本次提取结果 |
| Instance ID | 在这一文档版本中唯一标识翻译单元；不是可变数组索引 |
| Source anchor | 定位这一源版本中的 part、节点范围及受保护结构；不能直接用于另一版本 |
| Translation unit | 带 inline 标记的源/目标内容、状态、来源，连接既有 finding / decision / evidence |
| Correspondence | 跨版本关系；不通过共享 UUID 隐式表达 |

Correspondence 后续支持 unchanged、moved、modified、split、merged、unmatched，以及一对多/多对一和歧义复核。`B → B'` 保留各自版本内身份，关系为 modified 并要求复核。相似度只作为匹配证据，不能作为人工批准。

v1 不实现完整 Source Update，但不能让 source anchor、Instance ID 和跨版本关系成为同一个字段。实例身份不需要内容哈希；不得为了“稳定”堆叠指纹。

分段粒度与 LLM 上下文粒度分离：TM/人工编辑可以面向句子，翻译上下文仍可包含段落、章节和已确认知识。已有 translation truth、审校和快照继续作为唯一真值，不另造第二套批准流程。

## 验收与 fixtures

以下是计划中的 fixture 名称，不是已经存在的测试资产。优先通过可重复生成器构造；真实来源文件可补充验证，需记录可使用的来源及预期结果。

| Fixture | 检测的失败与验收重点 |
| --- | --- |
| `docx-simple.docx` | 正文/多段遗漏、顺序错误、写回错误节点 |
| `docx-table.docx` | 表格文字遗漏、合并单元格或表格结构损坏 |
| `docx-inline-formatting.docx` | 跨 run 翻译断裂、目标词序变化后格式归属错误 |
| `docx-hyperlinks.docx` | 显示文字漏译、外链目标/内部 anchor 改变 |
| `docx-footnotes.docx` | 脚注漏译、引用错配、分隔结构被当正文翻译 |
| `docx-headers-footers.docx` | 共享 part 重复处理、节引用损坏、页码字段被覆盖 |
| `docx-unsupported-features.docx` | 未翻译内容未报告、受保护对象被改写；含未决修订时必须明确拒绝 |
| `docx-mixed-structures.docx` | 表格中超链接、脚注附近格式切换、页眉字段等组合结构失效 |

每个可导出 fixture 必须验证：

1. 支持范围内全部内容完成提取、编辑/翻译和写回，保留项不计入翻译完成数。
2. 未修改 ZIP 条目逐项比较解压内容；修改 part 检查允许变化范围、tag 配对/嵌套、字段、书签和关系引用，而非只检查 XML 可解析。
3. 丢 tag、失效 anchor、版本不符等故障输入必须明确失败，不产出可交付的损坏文件。
4. 未翻译报告同时可用于导入判断与最终交付核查。
5. 文件可正常打开，记录实际检查使用的 Word / LibreOffice 与版本，检查译文、格式归属及混合结构的显示；不能把一个渲染器通过等同所有客户端通过。
6. 现有审校、人工批准、失效传播、快照与恢复路径仍成立，键盘可完成基本确认和问题导航。

离线固定译文用于验证写回及词序改变，真实模型质量另行评估。当前三个场景门禁继续验证旧工作流，但不能代替以上验收。未通过前，README 和界面不得宣传“DOCX 原格式保真已支持”。
