# Folith 0.8.3 发布说明

状态：**候选，等用户签字。** 候选是 Release Validation run [44904183640](https://github.com/xueyang-dev/Folith/actions/runs/44904183640)（main `8dda7b55`，版本号 0.8.3）。标签与公开发布在用户点头后进行，标签打在 `8dda7b55` 上。

第一个候选 `eba19231` 经用户 2026-11-21 亲测发现一批界面问题（见第 6 节），用户裁定「修好再发」；修复合入后从 main 重新出候选，旧候选作废。因为从 main 出，新候选也带上了这期间已合入 main 的几项改动（见第 7 节）。

本版是 2026-11-20 拆分后的第一个小版本（用户裁定）：原来的 0.8.3 太大，拆成 0.8.3 启动提速与设置改进、0.8.4 稳定可恢复（引擎子进程默认开启）、0.8.5 大书流畅、0.8.6 审校与交付打磨、0.8.7 Trados / memoQ 交换。**每版只背自己主题的门槛**，其余门槛的进度写在下方「未覆盖」。

一句话：这一版**启动更快、内存更省**，设置页的**思考强度改成按用途选、按模型自己声明的档位**，切换界面语言会**提示重启**，并修掉了一批 Windows 上退出和状态保存的问题。

## 这一版改了什么

### 1. 启动更快、内存更省（#514、#515）

- 主页任务列表移出窗口构造（#514，PR #532 / #535 / #541 / #556）：窗口先出来，任务列表随后填入。
- 项目页不再每次重读全部任务状态（#515，PR #546）；读项目摘要时不再整份复制任务状态（PR #563）。
- 实测见「性能」：macOS 冻结包启动到窗口出现 **−14%**、峰值内存 **−27%**；Windows 冻结包冷启动 **−14%**。

### 2. 思考强度：按用途选，档位由模型自己声明（#540）

- 设置 → 模型 →「用途」区每一行（翻译 / 审校 / 视觉）变成「连接 · 模型 · 思考强度」三列。第三列**只列这个模型声明过、并经实测有效的档位**（如 Off / Low / Medium / High），选中值原样下发。
- 不在档位目录里的模型显示灰色的「服务默认」，不可选，悬停说明「这个模型没有已验证的思考档位」。
- 连接行的摘要里写出这条连接默认模型的档位，例如「思考：Low / Medium / High」。
- 连接编辑器里原来的「推理强度」「思考」两行移走，连接只管地址、密钥和模型清单。
- **旧设置自动迁移，请求参数不变**：存在连接上的旧档位迁移到对应用途；有测试断言迁移前后同一个任务发出的请求体逐字段一致。旧值不在新目录里时照原值下发，界面标「旧设置」。
- 每次模型调用在运行时遥测里记下实际下发的档位和下发方式。
- 审校 / 视觉没有单独连接时，第二列显示「沿用翻译模型」，第三列显示实际沿用的档位，如「Off（沿用翻译）」，可单独改；三行第三列对齐（PR #589）。
- PR #559（档位目录与下发）、#562（设置页与迁移）、#576（禁用下拉的灰色样式）、#589（沿用显示）。

### 3. 切换界面语言提示重启（#547）

设置里改界面语言后，弹出「需要重启 Folith」：选「立即重启」，应用自己退出并重新打开、界面换成新语言；选「取消」，语言与设置都不变。PR #551。Windows 冻结候选上取消与接受两条路径都已实测（W-18）。

### 4. 设置窗口与小通知（#517、#520）

- 设置窗口**每一页**和「添加连接」对话框都不超出屏幕可用区域并居中，内容多时页面内滚动；底栏只占一行（状态文字在按钮左边）（#517，PR #533 / #588）。
- 小通知：图标与语气统一，**贴窗口内容区底部、在内容区居中**；最多叠 3 条、最新在上，关掉一条后其余自动贴底；错误与警告常驻，悬停暂停消失（#520，PR #538 / #571 / #587 / #591）。

### 5. 值得单独说的修复

- **Windows 引擎子进程退出的两个时序缺口**（#453，PR #537）：子进程模式下退出可能因锁超时失败、或丢掉用户的退出请求。Windows 真机 20 轮（运行中退出 10、暂停后退出 10）全部退出码 0、无残留、标志 20/20 保留（W-12b）。子进程模式本版**仍默认关闭**。
- **「启动中」从启动侧显示**：子进程模式下点开始后 1 秒内就显示启动状态，不再等子进程冷启动完（PR #534）。
- **读不出的状态日志不再被当成空日志**（#441，PR #444）。

### 6. 用户亲测后修复的问题（2026-11-21）

用户在第一个候选上逐页检查，发现以下问题，本版全部修复：

- 设置的「任务默认值」「存储」页和「添加连接」对话框超出屏幕底部（#588）。
- 设置底栏占两行、把窗口隔开（#588）。
- 小通知出现在窗口中偏上的奇怪位置（#587、#591）。
- 用途行「沿用翻译模型」时显示灰色「服务默认」，与实际发出的档位不符（#589）。
- 存储页：长路径被截在右边、「占用空间」数值被挤出窗口、「在Finder中显示」缺空格；卸载区三条路径改为各自**中间省略**，结尾文件夹名可见（#590）。
- 浅色主题下术语侧栏出现黑色块（系统外观为深色时），同状态圆点颜色不一致（#592）。这是 0.8.2 起就有的旧问题，一并修掉。

第二个候选（`89c52e57`）上，Windows 冒烟（W-21）又发现两处，UX 审查发现三处；用户决定一并放进本版：

- 存储页「在 Finder / 资源管理器 中显示」对数据目录无效，什么也不打开（两平台，0.8.2 起就有）。现在目录会直接打开（#600）。
- 翻译行为「服务默认」时，审校 / 视觉行只显示「服务默认」，没有「（沿用翻译）」（#600）。
- **从交付门禁「去处理」或审校页「修改译文」跳转时，若工作台有搜索词或筛选，会落到另一段**，译者可能改错段落。现在会自动清除挡住目标的筛选并提示「已清除筛选，显示第 N 段」（#603）。
- 搜索 `²` 这类上标数字时报错、表格停在旧结果；搜不到时没有提示，右侧还留着旧段落的操作。现在上标按文字搜索；零结果时在表格位置显示「没有匹配的段落」，检查器隐藏（#603）。
- 设置里没填 API 密钥也能点「仍然应用」，界面显示已应用，实际仍无法翻译。现在缺必填项时只提示缺什么；没有任何连接时主按钮是「添加连接」；连接测试失败的错误完整显示，服务商拒绝访问（403）时附一句该去哪里检查（#601）。

存储页整页重做、关于页、交付文件分组、「翻译范围」移到译前准备放在 0.8.6；密集页识别超时与「5 分钟没有进展」提示含糊放在后续版本。

### 7. 随新候选一起带上的改动

新候选从 main 出，以下改动已在 main 上、经 CI 全量回归，一并发布：

- **引擎监视结束前必定发布终态**（PR #570）：原属 0.8.4 的稳定性修复——还有进程持有证据时不发布终态，终态真正落盘后才标记完成。
- **准备页与交付页共用交付摘要组件**（#521，PR #578）、**审校统计标签可见 + 自动处理模式开关**（#523，PR #580）：原属 0.8.6 的两项小改动。

### 8. 开发约束（不影响使用）

本版把四条反复出现的纠正变成了会红的检查：四个大文件的行数棘轮（#458）、AGENTS.md 中可机器检查的规则（#459）、界面线程热路径检查（#505）、ruff 冻结基线（#460）。合并政策写进贡献文档：1.0 之前任何 PR 都不自动合并（#513）。

**纠正转检查计数（#510）**：累计 **11** 条，本版新增 **4** 条（见 [docs/agent-corrections.md](agent-corrections.md)）。

## 性能（#511，按用户操作列）

### macOS（同机、同一份合成数据，0.8.2 正式版 `e0e0a887` vs 0.8.3 候选 `89c52e57`，交替各 10 次）

| 用户操作 | 0.8.2 | 0.8.3 | 变化 |
|---|---:|---:|---|
| 启动到窗口出现 | 1874 ms | 1604 ms | **−14%** |
| 启动到可交互 | 340 ms | 340 ms | 持平（分布重叠） |
| 打开任务 | 410 ms | 410 ms | 持平（分布重叠） |
| 峰值内存 | 453 MB | 331 MB | **−27%** |

第一个候选 `eba19231` 上的同项测量（−23% / −33%）保留在证据文件附录；两次的 0.8.2 基线绝对值随机器状态不同，以同一轮交替对照的相对变化为准。

任务库 ↔ 项目页切换、打字回显、滚动 / 选中 p95 三项在冻结包上无法自动测量，本表不填；0.8.5 统一测量。证据：[0.8.3 macOS 性能表](evidence/0.8.3-perf-table-macos.md)。

### Windows（Windows 真机，0.8.2 正式版便携版 vs 0.8.3 候选，两版交替各 5 次）

第二个候选 `89c52e57` 上的复测（W-21）。之后的 #600、#601、#603 不涉及启动和打开任务，未重测。

| 用户操作 | 0.8.2 | 0.8.3 | 变化 |
|---|---:|---:|---|
| 冷启动到窗口出现 | 3.339 s | 2.881 s | **−14%** |
| 打开任务（210 段） | 0.868 s | 0.838 s | 持平 |
| 空闲内存（Working Set） | 361.5 MB | 362.2 MB | 持平 |

0.8.2 的首次运行（6.263 s）是解压后的首次启动（杀毒软件扫描），作为异常值保留在证据里，没有计入中位数。

**结论：0.8.3 在两个平台上都不比 0.8.2 差。**

## 未覆盖 / 已知问题

1. **引擎子进程仍默认关闭**。是否默认开启属于 0.8.4（门槛 G-E）。进程内与子进程的卡顿对照在两个平台上方向不一致、严重卡顿（>500 ms）都是 0，判为「不可判定」。
2. **Windows 上翻译进行中的界面卡顿明显多于 macOS**：同一负载下超过 100 ms 的停顿每分钟 10–13 次，macOS 是 0.2–0.5 次（W-16）。属于 0.8.5「大书流畅」。
3. **10,000 段大任务的滚动与选中超出预算**（G3）：滚动 p95 56.6 ms（预算 50）、选中 p95 约 120 ms（预算 100）。属于 0.8.5。
4. **8 小时长跑**：macOS 冻结版 8 小时 1,141 轮 0 崩溃、0 无响应；同一进程空转 8 小时内存不增长（尾段 +0.5 MB）。Windows 尚未跑，属于 0.8.4（G1b）。
