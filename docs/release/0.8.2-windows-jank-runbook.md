### 0.5 网关（**每轮重开一次**，两臂用同一个种子）

```powershell
function Start-Gw([string]$tag, [double]$scale) {
  $log   = "$OUT\$tag-gw.log"
  $ready = "$OUT\$tag-ready.json"
  Remove-Item $ready -ErrorAction SilentlyContinue
  $p = Start-Process -FilePath $PY -PassThru -NoNewWindow `
        -RedirectStandardOutput $log -RedirectStandardError "$log.err" `
        -ArgumentList @("$CAND\scripts\replay_latency_gateway.py", "--port", "$PORT",
                        "--seed", "$SEED", "--time-scale", "$scale",
                        "--role-default", "translation", "--timeout-hold-grace", "0.5",
                        "--log", "$OUT\$tag-gw.jsonl", "--ready-file", $ready)
  for ($i = 0; $i -lt 120; $i++) {
    if (Test-Path $ready) { return $p }
    Start-Sleep -Milliseconds 500
  }
  throw "网关没起来：$tag（看 $log）"
}
function Stop-Gw($p) { if ($p) { Stop-Process -Id $p.Id -Force -ErrorAction SilentlyContinue } }
```

网关一定要用 `$CAND` 里的那份（两臂同一份脚本 = 同一个回放实现），这与 macOS 第二轮一致。

## 1 每臂建一个「已完成模板任务」（各约 3–5 分钟）

S3 的 10,000 段任务是从**引擎真实跑完**的任务平铺复制出来的（不是手工造），
所以每臂先跑一个小的 S1 到完成，拿到它的 `job_id` 当模板。

```powershell
foreach ($arm in @("base", "cand")) {
  $tree = if ($arm -eq "base") { $BASE } else { $CAND }
  $tag  = "tpl-$arm"
  $gw   = Start-Gw $tag 0.05
  Push-Location $tree
  try {
    & $PY scripts\runtime_baseline_runner.py `
        --out "$OUT\$tag-round" --data-dir "$OUT\tpl-$arm" --mode source --scenario S1 `
        --paras 1000 --seconds 120 --settle-timeout 1800 `
        --base-url "http://127.0.0.1:$PORT/v1"
  } finally { Pop-Location; Stop-Gw $gw }
}

# 记下两臂的模板 job id（后面 S3 要用）。
# 注意：S1 轮次的 runtime-baseline.json **没有** job_id 字段（macOS 第二轮也是这样），
# 模板 job 只能从数据目录里按「有 pairs 的那个任务目录」找。
function Get-TemplateJob([string]$dataDir) {
  $best = $null; $bestPairs = 0
  foreach ($dir in Get-ChildItem $dataDir -Directory -ErrorAction SilentlyContinue) {
    $stateFile = Join-Path $dir.FullName "state.json"
    if (-not (Test-Path $stateFile)) { continue }
    try { $state = Get-Content $stateFile -Raw | ConvertFrom-Json } catch { continue }
    $n = @($state.pairs).Count
    if ($n -gt $bestPairs) { $bestPairs = $n; $best = $dir.Name }
  }
  if (-not $best) { throw "no finished task under $dataDir（找不到带 pairs 的 state.json）" }
  Write-Host "$dataDir -> $best ($bestPairs pairs)"
  return $best
}
foreach ($arm in @("base", "cand")) {
  Write-Host ("tpl-" + $arm + " job_id = " + (Get-TemplateJob "$OUT\tpl-$arm"))
}
```

把这两个 `job_id` 抄下来：`$TPL_BASE`、`$TPL_CAND`。

```powershell
$TPL_BASE = "<上一步打印的 base job id>"
$TPL_CAND = "<上一步打印的 cand job id>"
```

## 2 S3：只测 I（每臂 3 轮，交替，每轮约 70 秒，合计约 7 分钟）

```powershell
for ($round = 1; $round -le 3; $round++) {
  foreach ($arm in @("base", "cand")) {
    $tree = if ($arm -eq "base") { $BASE } else { $CAND }
    $tpl  = if ($arm -eq "base") { $TPL_BASE } else { $TPL_CAND }
    $tag  = "s3-$arm-$round"
    $gw   = Start-Gw $tag 0.01
    Push-Location $tree
    try {
      $env:FOLITH_QT_SETTINGS_DIR = New-Item -ItemType Directory -Force `
          "$env:TEMP\qs-$tag" | Select-Object -ExpandProperty FullName
      & $PY scripts\runtime_baseline_runner.py `
          --out "$OUT\$tag" --data-dir "$OUT\tpl-$arm" --mode source --scenario S3 `
          --s3-small-paras 40 --seconds 60 --settle-timeout 900 `
          --seed-template $tpl --seed-segments 10000 `
          --base-url "http://127.0.0.1:$PORT/v1" | Out-File "$OUT\$tag-run.log"
    } finally { Pop-Location; Stop-Gw $gw }
    & $PY scripts\runtime_baseline_runner.py --verify "$OUT\$tag" |
        Out-File "$OUT\$tag-verify.json"
  }
}
```

每轮记：`tasks.segments`（必须 10000）、`tasks.digest`（**两臂必须相同**）、
`valid_round`、I 档每分值。

> **`--verify` 对 S3 轮次一定报 `ok:false`，这是设计如此**，不是那一轮坏了：
> S3 没有翻译阶段，`R_valid`、`run_phase_operations_sampled`、`gui_jank_json_on_disk`
> 这几条「R 阶段」检查必然不成立（macOS 第二轮的数据也是这样，本地复核过）。
> S3 要看的是 **`valid_round: true`**、**`aggregate_ready: true`** 和 `checks` 里的
> `I_valid: true`。S1 轮次才看 `ok`。

## 3 S1：只测 R（每臂 3 轮，交替，每轮约 12 分钟，合计约 72 分钟）

R 窗口固定 `120:720`（翻译开始后第 2–12 分钟），**两臂必须同一窗口**。

```powershell
for ($round = 1; $round -le 3; $round++) {
  foreach ($arm in @("base", "cand")) {
    $tree = if ($arm -eq "base") { $BASE } else { $CAND }
    $tag  = "s1-$arm-$round"
    $gw   = Start-Gw $tag 1.0
    Push-Location $tree
    try {
      $env:FOLITH_QT_SETTINGS_DIR = New-Item -ItemType Directory -Force `
          "$env:TEMP\qs-$tag" | Select-Object -ExpandProperty FullName
      & $PY scripts\runtime_baseline_runner.py `
          --out "$OUT\$tag" --data-dir "$OUT\s1-$arm" --mode source --scenario S1 `
          --paras 1000 --r-only --r-window 120:720 --settle-timeout 600 `
          --base-url "http://127.0.0.1:$PORT/v1" | Out-File "$OUT\$tag-run.log"
    } finally { Pop-Location; Stop-Gw $gw }
    & $PY scripts\runtime_baseline_runner.py --verify "$OUT\$tag" |
        Out-File "$OUT\$tag-verify.json"
  }
}
```

> `--data-dir "$OUT\s1-$arm"` 每臂一个，**不要复用 S3 的目录**：
> S3 那边放的是 10,000 段的播种任务，混在一起会让 S1 的导入变慢、R 窗口起不来。

## 4 校验与聚合

`--verify` 已经在上面每轮跑过。判定规则见上：**S1 轮看 `ok`，S3 轮看 `valid_round`
与 `I_valid`**（S3 的 `ok:false` 是 R 不适用的必然结果）。
最后做两臂聚合：

```powershell
foreach ($arm in @("base", "cand")) {
  # 聚合器要求「每个子目录下有 */runtime-baseline.json」
  $dst = "$OUT\arm-$arm"
  foreach ($r in 1..3) {
    New-Item -ItemType Directory -Force "$dst\s1-$r" | Out-Null
    Copy-Item "$OUT\s1-$arm-$r\runtime-baseline.json" "$dst\s1-$r\"
    New-Item -ItemType Directory -Force "$dst\s3-$r" | Out-Null
    Copy-Item "$OUT\s3-$arm-$r\runtime-baseline.json" "$dst\s3-$r\"
  }
  & $PY scripts\runtime_baseline_runner.py --aggregate $dst |
      Out-File "$OUT\aggregate-$arm.json"
}
Get-Content "$OUT\aggregate-base.json", "$OUT\aggregate-cand.json" | Select-Object -First 40
```

也可以对单轮做校验（例如怀疑某一轮无效时）：

```powershell
& $PY scripts\runtime_baseline_runner.py --verify "$OUT\s1-cand-2"
# ok=false 时按 checks 里点名的字段重跑该轮，不要手改结果
```

## 5 判定（70%）

对 R 与 I 分别算，每档各 3 轮取中位：

```
降幅 = 1 - (候选中位 / 基线中位)
```

- 要 ≥70% 的格子：R>100ms、R>500ms、I>100ms、I>500ms
- **R>500ms 两臂都是 0 时写「不可判定」**（macOS 第二轮就是这一格）
- 达不到照实写，**不调参、不换窗口、不挑轮次**

## 6 交回什么

整个 `$OUT` 目录打包（含每轮的 `runtime-baseline.json`、`*-verify.json`、
`*-run.log`、`*-gw.jsonl`、两份 `aggregate-*.json`），外加一页纸：

- Windows 版本（`winver`）、CPU/内存、显示器缩放
- 两个工作树的提交（`git -C <tree> rev-parse --short HEAD`）
- 两臂的模板 `job_id` 与 `tasks.digest`（必须相同）
- 12 轮每轮的：`ok`、`valid_round`、R 或 I 的两档每分值
- 判定表（4 格 + 不可判定的格子）
- 任何异常（窗口被挡、误触鼠标、网关重启失败…）照实写

## 7 Windows 与 macOS 的已知差异（写进报告，不要藏）

1. **没有 `caffeinate` 的等价物**：用 `powercfg` 关掉睡眠；如果机器中途睡了，
   那一轮记作无效并重跑。
2. **窗口合成器不同**：Windows 的 DWM 开着，macOS 那边也是开着的，量级可比但绝对值
   不可混比。报告里分开列两平台。
3. **字体与缩放**：Windows 默认 125%/150% 缩放会改变布局成本。**固定 100%**，
   在报告里写明实际值。
4. **进程名**：退出后残留检查用任务管理器看 `python.exe` 与 `Folith.exe`
   （第 4 条的清单会用到）。
