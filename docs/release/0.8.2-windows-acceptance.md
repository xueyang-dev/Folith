# 0.8.2 Windows 验收包（草稿）

给一台 Windows 机器上的人照着做。命令核对于 `origin/main` `d3dad9b6`（2026-11-14）。
某条写着「main 上没有这个脚本」时，不要换一个听起来像的脚本顶上。

结果放进 `docs/evidence/`，写上构建号、机器、命令和原始输出。离屏和单元测试不算本包通过。
`dist\qt-windows\Folith\Folith.exe` 是构建脚本和 `.github/workflows/release-validation.yml` 里的产物路径，不是某台已经验收过的机器。

## 0. 先打出冻结版

仓库里有这个脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_qt_windows.ps1 -Python python -Clean
```

脚本自己的用法说明还写了 `-Python .venv-windows\Scripts\python.exe` 和本机 Tesseract 路径。那是说明，不是这里要你照抄的路径。产物是 `dist\qt-windows\Folith\Folith.exe`。

## 1. 加压 30 轮

**main 上没有 30 轮脚本。** `scripts/qt_ocr_baseline_runner.py` 没有 `--rounds`。
`docs/evidence/a3-frozen-30round-macos-0.8.2.md` 里提到的 `run30.sh` 不在仓库里，而且那是 macOS、A3 分支，不能沿用。

一次冻结 OCR（不是 30 轮）：

```powershell
python scripts/qt_ocr_baseline_runner.py --out <目录> --frozen-app dist\qt-windows\Folith\Folith.exe
```

`--out` 和 `--frozen-app` 必填。`--with-negative` 默认开着，`--no-negative` 把它关掉。
退出码 0 只说明这一次的三次 OCR（eng / chi_sim / ara）和缺语言包负例符合脚本的预期。

要做 30 轮：对最终候选的这份 exe 自己连跑 30 次，不要跳过、不要失败了重试当没发生。
记下每轮退出码、`ocr-baseline.json` 里的 `ok`，以及系统崩溃报告有没有新增。
原始日志放进 `docs/evidence/`。

不要用 `scripts/qt_stale_wrapper_probe.py --repeat 300`。那是过期包装器探测器，退出码 3 表示包装器增长，不是崩溃门槛。

## 2. 流畅度对照

脚本在：`scripts/runtime_baseline_runner.py`。默认 `--seconds 90`，**90 秒不够**计划的「每轮至少 5 分钟」。

冻结臂、动画开着（不要加 `--offscreen`，也不要设 `QT_QPA_PLATFORM=offscreen`）：

```powershell
python scripts/runtime_baseline_runner.py --out <目录> --paras 10000 --seconds 300 --mode frozen --frozen-app dist\qt-windows\Folith\Folith.exe
```

基线和候选各至少 3 轮，同一台机器。中位数：

```powershell
python scripts/runtime_baseline_runner.py --aggregate <目录>
```

官方数字目前要求 `--mode source`（见 `.loop/reports/P1-5-runbook.md`），冻结臂只证明流程能跑。
那份 runbook 还没执行。未合并的 PR #412 想改旗标；那些旗标现在不存在，不要加 `--verify`。

回放网关是 source 臂用的，不是流畅度本身：

```powershell
python scripts/replay_latency_gateway.py --port 8765 --seed 7
```

S2 和 S4 可以写进 `--scenario`，但会立刻退出，报告里是 `implemented: false`。选了 S4 不等于跑了 8 小时。

要的结果：R（翻译中）和 I（完成后）分开；>100 ms 和 >500 ms 两档的中位卡顿率，候选相对基线 `8109b9c2` 各降至少 70%。macOS 的数字不能代替 Windows。现在没有这份 Windows 包。

## 3. 8 小时

## 4. 休眠、唤醒、退出续跑

**main 上没有这个脚本。** 需要人工。

1. 用第 0 节的冻结版打开一个正在翻译的任务，记下时间。
2. 让 Windows 睡眠，再唤醒。
3. 记下唤醒后界面是否还能操作、任务是否还在、用了多久。
4. 退出，再打开，记下它是否接着跑，以及这次耗时。

`scripts/qt_hung_provider_probe.py --out <目录> --hang-seconds 600` 只是让假端点先睡再回复。文件头写明它代替不了睡眠和唤醒。不要把这个探针的退出码写成 #320 的结果。

## 5. 导入向导，真实 TMX

**main 上没有「打开原生文件对话框并导入一份真实 TMX」的脚本。** 需要人工。

1. 打开冻结版。菜单是 **文件 → 导入资产并校验…**（`folith/qt/window.py` 里的原文）。
2. 文件对话框应是 Windows 自己的。向导代码用的是 `QFileDialog.getOpenFileName`，没有 `DontUseNativeDialog`。若弹出的不是系统对话框，记下来，不要改对话框再测。
3. 选一份真实 TMX，不是测试里写出来的空文件。
4. 把向导报告的条数和引擎导入条数对上。两个都记进 `docs/evidence/`。

`tests/qt_import_wizard_test.py` 是离屏测试。它通过不等于这一条通过。

## 6. 冷启动、杀毒软件、应用内更新

**main 上没有这三项的验收脚本。**

仓库里有、但不是这三项的命令：

| 做什么 | 命令 | 不是什么 |
| --- | --- | --- |
| 冻结主流程 | `python scripts/qt_desktop_probe.py --data-dir <数据目录> --out <报告.json> --fixture both --frozen-app dist\qt-windows\Folith\Folith.exe` | 不是冷启动计时。默认离屏；加 `--window` 才用原生窗口。代替不了睡眠和干净机器 |
| 安装包检查 | `python scripts/check_windows_artifact.py --installer <dist\installer\*.exe> --out build\qt-windows\windows-artifact-check.json` | 不是杀毒软件记录 |
| 安装、升级、卸载 | `python scripts/check_windows_installer_roundtrip.py --installer <同上> --out build\qt-windows\windows-installer-roundtrip.json` | 不是「程序还在运行时更新」 |
| 签更新清单 | `python scripts/create_update_manifest.py --installer <安装包> --version <版本> --private-key <密钥> --out <目录>` | 不是验收更新 |

冷启动：图上的 E-1 证据文件 `docs/evidence/0.8.2-e1-engine-coldstart.md` **不在** `d3dad9b6`。不要引用别的工作树里未跟踪的那份数字。这一条需要你在干净 Windows 上对冻结版记第一次启动耗时。现在没有命令。

杀毒软件：没有脚本。打开冻结版时如果 Defender 拦截或扫描很久，把提示和时间记下来。没有这份记录。

应用内更新：设置里的路径是 **文件 → 设置 → 关于 → 检查更新**。有新版本且清单齐全时才会出现「下载更新」。
`d3dad9b6` 上没有 `folith/resources/update-public-key.txt`。没有这把公钥，`windows_available()` 为假，界面会停在「此版本尚未配置应用内更新。」不要编一条命令让它装完。`folith/desktop/install-update.ps1` 在，但工作流里没有「进程还在跑的时候更新」这一步，不要把它当成验收命令。

## 7. 界面验收（最小窗口宽度）

**main 上没有 Windows 真机最小宽度脚本。** 需要人工。

最接近的脚本强制离屏，打印的标题也写着离屏。它不能代替真窗口：

```powershell
python scripts/ui_overhaul_measure_widths.py --detail
python scripts/ui_overhaul_measure_widths.py --lang zh-CN --lang en --lang es --lang ru --with-job --json <文件>
```

`--lang` 只能是 `zh-CN`、`en`、`es`、`ru`。写成 `zh` 不会被接受。

人工：用第 0 节的冻结版，四种界面语言各把窗口往窄里拖，记下拖不动时的宽度。
上一份验收把上限写成 1280，并写明 Windows 真机当时不在范围：`docs/ui-overhaul/90-acceptance-report.md`、`docs/release-notes-0.8.1.md`。
离屏数字不能填进那一格。截图脚本 `scripts/qt_showcase_screenshots.py` 也不是这一条。
