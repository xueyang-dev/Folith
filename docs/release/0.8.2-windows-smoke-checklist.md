# Folith 0.8.2 Windows 冒烟清单（门槛第 4 条）

这份清单给用户在自己那台 Windows 11 x64 机器上照做，约 1 小时。做完把每步的「通过 / 不通过」和第 8 节的产物发回来即可；**不通过也照实记**，它决定这一版发不发。

它只覆盖第 4 条门槛要求的范围：**装得上、打开得了、能翻完一份小文档并交付、XLIFF 能进出、翻译中退出没有残留进程、3 轮加压 0 崩溃、界面没有明显错位。** 这一版没有 Windows 的 30 轮加压、8 小时长跑、休眠唤醒，也不做 0.8.1 界面的逐项原生验收——那些在 0.8.3。

判定口径与证据要求见 [0.8.2 验收对账表](0.8.2-acceptance-ledger.md)。门槛 9 的流畅度测量有单独手册 [Windows 卡顿 runbook](0.8.2-windows-jank-runbook.md)：那份管「两臂各 3 轮、S1 R 与 S3 I、按 70% 判定」，这份管「装得上、能翻完、能交付、XLIFF 能进出、退出不残留」。两份用同一套进程名（`Folith.exe` / `python.exe`）与同一套退出检查，别写成两种说法。

## 0. 准备

1. 从发布候选页面下载两个文件（和 `SHA256SUMS.txt`）：
   - `Folith-Setup-0.8.2-windows-x64.exe`（安装版）
   - `Folith-Qt-0.8.2-windows-x64.zip`（便携版）
2. 校验哈希：

```powershell
Get-FileHash .\Folith-Setup-0.8.2-windows-x64.exe -Algorithm SHA256
Get-FileHash .\Folith-Qt-0.8.2-windows-x64.zip   -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

**通过**：两个哈希与 `SHA256SUMS.txt` 里对应行一致。

3. 准备三份测试文件：
   - 一份小文档：`.docx` 或 `.txt`，最好 10–40 段（一屏到两屏）。
   - 一份通用 XLIFF 1.2：`.xlf` 或 `.xliff`。仓库里有现成的 `tests\fixtures\xliff12\validators.en.xlf`；没有仓库就用任何自己手边的通用 XLIFF 1.2。
   - 一份 Trados 或 memoQ 文件（有就测，没有跳过这一步并在第 8 节注明）：`tests\fixtures\sdlxliff\QuotesSample.docx.sdlxliff` 或 `tests\fixtures\mqxliff\locked.mqxliff`。

> 需要跑第 6 节的加压脚本时，机器上还要有仓库副本和 Python 3.11（`py -3.11 --version` 能打出版本号即可）。

## 1. 安装

1. 双击 `Folith-Setup-0.8.2-windows-x64.exe`，按默认路径装完。
2. 开始菜单能找到 Folith。安装目录按当前用户安装，默认在 `%LOCALAPPDATA%\Programs\Folith\`，里面应该有 `Folith.exe` 和 `_internal`：

```powershell
Get-ChildItem "$env:LOCALAPPDATA\Programs\Folith" | Select-Object Name
```

3. 如果需要，再单独解压便携版 ZIP 到另一个目录：ZIP 的顶层就是 `Folith.exe` 和 `_internal`（没有再套一层目录），解压后直接能双击运行。

**通过**：安装无报错、无 SmartScreen 拦截（或被拦截时能正常放行）、开始菜单有图标、安装目录里 `Folith.exe` 存在。
**不通过**：安装中断、报错、装完找不到可执行文件、杀软直接隔离且无法放行。

---

## 2. 冷启动

1. 关掉所有 Folith 窗口，确认任务管理器里没有 Folith 进程。
2. 从开始菜单启动 Folith，用秒表或心里数秒。
3. 看主窗口是否正常出现：任务库在左侧或主区，没有白屏、没有半透明的空壳、没有「未响应」。

**通过**：窗口在 10 秒内出现并可点击；首页能加载出任务列表（首次为空列表也算正常）；标题栏是 Windows 原生样式（有最小化/最大化/关闭，不是 macOS 的红绿灯）。
**不通过**：超过 30 秒还白屏、窗口无响应、启动即闪退、出现控制台黑框。

**记录**：冷启动大约几秒。

---

## 3. 小文档：翻译 → 审校 → 交付

1. 「导入文档」或直接拖入那份 `.docx` / `.txt`，等任务出现。
2. 打开任务，在「准备」页保持默认设置，点「开始翻译」。**需要先在设置里配置好模型连接**（这一步和 0.8.1 一样）。
3. 等翻译跑完（小文档通常几分钟）。观察翻译过程中界面是否还能滚动、切页、点按钮。
4. 进「审校」页，对至少一段做一次人工确认或修改，然后让它进入已审校。
5. 进「交付」页，点「审校完成后冻结交付」。
6. 冻结成功后点「下载全部（ZIP）」或「另存交付文件…」，把文件存到桌面。

**通过**：
- 任务建出来、开始翻译后进度在走；
- 翻译过程中界面能操作（允许偶发卡顿，但**不能**整窗假死超过几秒）；
- 审校页能确认/修改段落；
- 冻结成功并给出交付版本与文件清单；
- 存下来的 ZIP 能解开，里面有译文文件（`.docx` 或 `.txt` 对应的产出）且能打开。

**不通过**：翻译中界面完全无响应且不恢复、冻结报错且无法完成、ZIP 打不开或里面没有译文文件。

**记录**：翻译耗时、冻结是否一次成功、ZIP 里有哪些文件。

## 4. XLIFF 导入与导出

### 4A 通用 XLIFF 1.2（可写回译文）

1. 把 `validators.en.xlf`（或自己的 `.xlf`）拖进任务库或「导入文档」。
2. 打开任务，确认段落、原文、译文都在工作台里显示。
3. 随便改一段译文并保存（**必须在任务没有运行的时候改**，运行中会被拒绝，这是已知限制）。
4. 进「交付」页，点「导出双语文件并写入译文…」，存到桌面。
5. 用记事本或 VS Code 打开导出的文件，搜你刚改的那段译文。

**通过**：导入后段数与文件里的 `<trans-unit>` 数量一致（`validators.en.xlf` 应为 161 段；如果选的是别的文件，按文件里的 `<trans-unit>` 个数核对）；导入报告里没有「拒绝」；改动的那段译文出现在导出文件的 `<target>` 里；导出过程没有报错。
**不通过**：导入报错、段数明显不对、导出报错、导出文件打不开或找不到改动。

### 4B SDL / memoQ（只读，只允许原样导出）

1. 导入 `QuotesSample.docx.sdlxliff` 或 `locked.mqxliff`。
2. 在工作台里点几个段落：**锁定段应该能看见但不能编辑**，右侧/状态行会写「已锁定（只读）」；试着在锁定段里打字或点保存，应该被拒绝并给出原因。
3. 进「交付」页：**只有「原样导出双语文件…」，没有「导出双语文件并写入译文…」。**
4. 原样导出到一个新文件，然后比对哈希：

```powershell
Get-FileHash .\QuotesSample.docx.sdlxliff -Algorithm SHA256
Get-FileHash .\导出的文件.sdlxliff        -Algorithm SHA256
```

**通过**：锁定段只读且保存被拒；交付页没有写回入口；两个 SHA256 **完全相同**（原样导出逐字节相同）。这一版的方言导出是「原样写回」，**不会**把你改过的译文存进去。
**不通过**：锁定段能改并保存、出现写回译文的入口、导出文件哈希不同、导出报错。

**记录**：两个哈希值。

## 5. 翻译中退出，检查残留进程

这一条要测**两种情况**。

### 5A 默认（引擎在应用进程内）

1. 重新导入一份小文档并开始翻译，等进度明显在走。
2. 直接关窗口退出。会先弹「退出 Folith」对话框，里面写明「退出会先停止它们并释放写入锁；已完成的进度会保留」，点**「退出」**。
   - 如果停下来花了很久（超过约 45 秒），会再弹「无法安全退出」，按钮是「强制退出」和「继续等待」。这一条要测的是**正常「退出」**；如果你点了「强制退出」，请在第 8 节注明，因为强退不保证进程立即消失。
3. 等 10 秒，打开任务管理器「详细信息」，或用 PowerShell：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -match '^(Folith|python|pythonw)\.exe$' } |
  Select-Object Name, ProcessId, CommandLine
```

**通过**：列表为空（或只剩你自己另开的 Python，比如这个 PowerShell 里的不算）。任务在重新打开应用后仍然在，并且可以看到「已中断/可继续」这类状态。
（进程名与 [Windows 卡顿 runbook](0.8.2-windows-jank-runbook.md) 第 7 节第 4 条一致：残留就看 `Folith.exe` 与 `python.exe`。）
**不通过**：退出 30 秒后仍有 `Folith.exe` 或它的 `python` 子进程占着，或者任务消失/进度丢失。

### 5B 引擎子进程（可选，但建议测一次）

1. 在 PowerShell 里设环境变量再启动，这样应用会为每个任务另起一个引擎子进程：

```powershell
$env:FOLITH_ENGINE_PROCESS = "1"
& "$env:LOCALAPPDATA\Programs\Folith\Folith.exe"
```

2. 导入小文档、开始翻译、等进度在走，然后用同样方式退出。
3. 重复上面的 PowerShell 检查。

**通过**：翻译能正常跑完或正常中断；退出后 `Folith.exe` 与那个引擎子进程都消失，不留 `python`/`pythonw`。
**不通过**：子进程在退出后仍存活（这是发布阻塞项）、或翻译在子进程模式下根本跑不起来。

**记录**：两种情况下 `Get-CimInstance` 的输出（空列表也要记）。

## 6. 3 轮冻结包加压

在仓库副本里跑（`py -3.11` 或你已经装好的 Python 3.11）：

```powershell
cd <你的 Folith 仓库目录>
py -3.11 scripts\frozen_stress_rounds.py `
  --frozen-app "$env:LOCALAPPDATA\Programs\Folith\Folith.exe" `
  --rounds 3 `
  --out "$env:TEMP\folith-stress-082"
Get-Content "$env:TEMP\folith-stress-082\summary.json"
```

**通过**：`summary.json` 里同时满足：

- `rounds` 为 `3`；
- `abnormal_exit_count` 为 `0`（每轮退出码 0，且每轮都产出了 `ocr-baseline.json`）；
- `crash_query_supported` 为 `true`，`system_crash_record_count` 为 `0`（脚本按 WER 事件 1000/1001 比对 3 轮前后的崩溃记录，没有新增）。

**不通过**：任意一轮崩溃或跑不完（`abnormal_exit_count` > 0）、`system_crash_record_count` 不为 0、或者 `crash_query_supported` 为 `false`（那说明它没能真正查崩溃记录，按不通过记，别把它读成 0 崩溃）。

**记录**：`summary.json` 全文（就是上面那几个字段），以及 `%TEMP%\folith-stress-082\rounds.jsonl`。

## 6.1 如果崩溃了（P2-21）

**状态：已修复**（[#443](https://github.com/xueyang-dev/Folith/pull/443) 帧环、[#446](https://github.com/xueyang-dev/Folith/pull/446) 默认不跨线程取帧）；main 上 20 轮复核通过：产品默认口径 **0/20 崩溃**，阳性对照（开跨线程取帧）仍 **6/20**（run `44076100998`）。详见 [对账表 §1.1](0.8.2-acceptance-ledger.md)。

- 原来的两种形态（主线程 Qt 原生派发里的 `access violation`；worker 线程 `Garbage-collecting` 时的 `Fatal Python error: Aborted`）都指向同一个产品缺陷，修完之后**产品默认不再采其他线程的栈**（诊断时 `FOLITH_JANK_OTHER_THREADS=1` 才打开）。
- 本清单用的是小文档，正常不该命中；**如果还是崩了**：截图 + 记下你当时在做什么，第 8 节照实报「崩溃」——**崩溃是发布阻塞项**，不要重跑几次凑成「通过」，也不要用 `FOLITH_JANK_MONITOR=0` 把采样器关掉来「绕过」。
- 门槛 9 的 S3 轮次曾更容易命中；那边的处理方式仍是**重跑该轮并如实记录**（[runbook](0.8.2-windows-jank-runbook.md) 第 8 节），不是改窗口或阈值。

## 7. 界面错位扫一眼（约 5 分钟）

1. 窗口拉到最小可用宽度，再拉大；看顶栏按钮、审校页、交付页有没有被裁掉一半、文字压住按钮、横向滚动条乱跳。
2. 在设置里把界面语言切到 English，重启，看首页、工作台、交付页是否正常（其余语言可选）。
3. 打开一个任务再回首页，看卡片是否整齐。

**通过**：没有明显错位（文字压控件、按钮被裁、空白大块、错位重叠）。
**不通过**：任何一处明显错位——记下页面名并截图，这条不单独阻塞发布，但会进 0.8.3。

**记录**：截图（有问题的才需要）。

## 8. 回传什么

把下面这些发回来（有就发，没有就写「未做」并说原因）：

- 每步的**通过 / 不通过**，以及不通过时的截图；
- 第 2 步的冷启动秒数；
- 第 4B 步的两个 SHA256；
- 第 5A / 5B 的 `Get-CimInstance` 输出；
- 第 6 步的 `summary.json`；
- 你的 Windows 版本与机器型号（`winver` 的版本号即可）。

**什么算发布阻塞**（看到这些就停下来告诉我，不要继续凑）：

- 崩溃、或应用打不开；
- 数据丢失/损坏（任务消失、进度丢失、导出文件打不开）；
- 「翻译 → 审校 → 交付」主流程走不通；
- XLIFF 导出把文件写坏；
- Windows 冷启动失败，或退出后残留 `Folith.exe` / `python` 进程。

其他问题（错位、文案、偶发卡顿）记成 issue，进 0.8.3。
