# Folith 0.8.2 发布说明草稿

状态：**草稿，不是发布。** 初稿对照 `origin/main` `b9e7c924`（2026-11-14）。#418（`d070e9bd`）、#419（`b0ccb76a`）和 #422（`760b9683`）已合入 main，下面通用 XLIFF、独立校验和 30 轮按合入后的事实改过。没有打 tag，没有上传安装包。

「能说的」里每一句都链到已经在 main 上的 PR 或 `docs/evidence/`。做不到这一步的写在「待验证」，不写进能力列表。

---

## 能说的

- 4 个 SDLXLIFF 样本和 5 个 MQXLIFF 样本可以原样导出：结构 diff 为空，导出字节与原文件相同；单元数、锁定段数、状态分布与审计脚本一致。证据：[docs/evidence/0.8.2-g5-dialect-readonly.md](../evidence/0.8.2-g5-dialect-readonly.md)，合入 [PR #417](https://github.com/xueyang-dev/Folith/pull/417)（`bc5227a0`）。测量提交 `ed61a064`。这 9 个文件没有在 Trados 或 memoQ 里打开过。导出是不改字节的原样写回，不是改完译文再存回去。
- 四个真实通用 XLIFF 1.2 文件可以不改就导出，结构 diff 为空。`validators.en.xlf` 改 5 个单元的译文后，不套白名单的结构 diff 只有这 5 条译文；再导入身份相同、再指派 0 次，标过确认的仍是确认。`test1_es.xlf` 两个 `<file>`、24 个跨文件重复的单元 id、140 个单元全部导入，`rejections` 为空。证据：[docs/evidence/0.8.2-g4-xliff12-kernel.md](../evidence/0.8.2-g4-xliff12-kernel.md)，合入 [PR #418](https://github.com/xueyang-dev/Folith/pull/418)（`d070e9bd`）。没有在 Trados 或 memoQ 里打开过。
- 未知命名空间按 XLIFF 1.2 扩展点处理。扩展点上的外来元素原样保留、不拒绝。出现在 `<source>`、`<target>`、`<mrk>` 行内时，该单元拒绝 `UNKNOWN_NAMESPACE`，错误含元素名、文件偏移和行号。SDL / memoQ 方言配置里声明过的命名空间不算未知。两个通用样本和 9 个方言样本的单元数、拒绝数不变。证据：[docs/evidence/0.8.2-g4-unknown-namespace.md](../evidence/0.8.2-g4-unknown-namespace.md)，[PR #424](https://github.com/xueyang-dev/Folith/pull/424)，测量提交 `b0dc807f`。没有在 Trados 或 memoQ 里打开过。这不是工作台行为，也不是 1,000 单元。
- 上面这些通用文件，加上 4 个 SDLXLIFF 和 5 个 MQXLIFF，原样导出没有带来新的 OASIS XLIFF 1.2 校验错误。strict 和 transitional 都对过。原文件在 strict 上本来就有的扩展错误还在，不是导出引入的。证据：[docs/evidence/0.8.2-p3-6-xliff-validation.md](../evidence/0.8.2-p3-6-xliff-validation.md)，合入 [PR #422](https://github.com/xueyang-dev/Folith/pull/422)（`760b9683`）。测量提交 `99dcf593`。没有在 Trados 或 memoQ 里打开过。这是内核原样导出，不是界面导出。

## 待验证

这些都还不能当成这一版的能力：

- **G2 流畅度。** 见下方已知限制。不是「变流畅了」。
- **通用 XLIFF 还缺的几项。** 四项内核证明已合入 #418。未知命名空间的口径已按扩展点保留、行内拒绝记在上面，对账表这一行改为「有证据」。工作台里看见锁定段但不能编辑，以及 1,000 单元的真窗口，仍等 P3-5。损坏文件的错误原文在证据里，不是一条单独的能力。
- **界面导出的抽查。** 内核原样导出的独立校验已合入 #422，见上面。从界面导出后再抽查，仍等 P3-5。没有在 Trados 或 memoQ 里打开过。
- **冻结包加压 30 轮、0 崩溃。** macOS 上旧的 A3 记录不能沿用。驱动已合入 [PR #419](https://github.com/xueyang-dev/Folith/pull/419)（`b0ccb76a`）。本机只对一个已有的 macOS 冻结包跑过 3 轮冒烟，不是 30 轮，也不是 Windows，不能当成 G1 通过。Windows 30 轮、两个平台各 8 小时，都没有记录。
- **Windows「减少动态」。** 读取系统设置的代码已合入 [PR #415](https://github.com/xueyang-dev/Folith/pull/415)（`09c5715a`）。没有人在 Windows 设置里拨过「显示动画」，单元测试是 mock，不能当成真机记录。
- **五个操作的 p95、交互延迟预算。** 没有实测，也没有签字的校准值。
- **TM / TB 导入向导的两个平台真窗口和一份真实 TMX。** 只有离屏测试。
- **休眠唤醒、退出后续跑。** 没有记录。
- **一本真实书的理解阶段耗时对照**（#319）。[docs/understanding-speedup-0.8.2.md](../understanding-speedup-0.8.2.md) 写明没有真实书、没有真实网关计时。
- **0.8.1 界面在 Windows 上的原生验收。** 仍然没有。
- **#220 的 B5**（坏回复长什么样）需要真实视觉模型，[docs/issue-220-remaining-0.8.2.md](../issue-220-remaining-0.8.2.md) 写明未做。视觉并发默认值（官方端点 3、中转 2）写在那份说明里，但当前 `CHANGELOG.md` 没有这句，这里不把它算成已发布的能力。

验收对账是草稿：[docs/release/0.8.2-acceptance-ledger.md](0.8.2-acceptance-ledger.md)，合入 [PR #416](https://github.com/xueyang-dev/Folith/pull/416)（`588eff42`）。那份表自己写了不能当成通过。Windows 上怎么测，见 [docs/release/0.8.2-windows-acceptance.md](0.8.2-windows-acceptance.md)。30 轮的命令在 #419 合入之后才在 main 上；那次合入之前的 `b9e7c924` 仍写着「没有脚本」。命令有了，30 轮没有跑。

## 已知限制

- **G2 未测成。** [docs/evidence/0.8.2-p1-5-macos-jank.md](../evidence/0.8.2-p1-5-macos-jank.md) 那一次不是计划里的负载：两臂几乎都不卡，基线在 R 段采到 2,288 次滚动，候选是 0 次，两边的操作对不上。不能把这次读成「变快了」或「变慢了」。Windows 没测。冻结候选对冻结基线的对照也还没有。
- **方言只读。** SDLXLIFF / MQXLIFF 的 `write_target` 直接拒绝。界面不提供这两种格式的写回。没有 Trados / memoQ 回读。
- **没有在 Trados 或 memoQ 里做过往返。** 通用 XLIFF 和方言样本都一样。
- **macOS 安装包仍未签名、未公证**（0.8.1 已写明，本草稿没有新的签名记录）。
- 离屏测试、mock 和单元测试不能代替真实窗口。

# Folith 0.8.2 release notes draft

Status: **a draft, not a release.** First written against `origin/main` `b9e7c924` (2026-11-14). #418 (`d070e9bd`), #419 (`b0ccb76a`), and #422 (`760b9683`) are now on main; the generic XLIFF, validation, and 30-round items below were updated to match. No tag and no uploaded installers.

Every sentence under "What can be said" links to a PR or a file in `docs/evidence/` that is already on main. Anything short of that is under "Not yet verified" and is not a capability.

## What can be said

- Four SDLXLIFF samples and five MQXLIFF samples can be exported unchanged: the structural diff is empty, the exported bytes match the original, and the unit count, locked-segment count, and status distribution match the audit scripts. Evidence: [docs/evidence/0.8.2-g5-dialect-readonly.md](../evidence/0.8.2-g5-dialect-readonly.md), merged in [PR #417](https://github.com/xueyang-dev/Folith/pull/417) (`bc5227a0`). The measured commit is `ed61a064`. Those nine files were not opened in Trados or memoQ. The export writes the original bytes back; it does not save edited translations.
- Four real generic XLIFF 1.2 files export unchanged with an empty structural diff. After editing the target text of five units in `validators.en.xlf`, the unwhitelisted structural diff contains only those five target texts; re-import keeps the identity, makes no reassignment, and keeps a confirmed status confirmed. `test1_es.xlf` has two `<file>` elements, 24 unit ids repeated across files, and all 140 units import with an empty `rejections` list. Evidence: [docs/evidence/0.8.2-g4-xliff12-kernel.md](../evidence/0.8.2-g4-xliff12-kernel.md), merged in [PR #418](https://github.com/xueyang-dev/Folith/pull/418) (`d070e9bd`). Not opened in Trados or memoQ. An unknown namespace was not rejected, so that is not part of this capability.
- Those generic files, plus the four SDLXLIFF and five MQXLIFF samples, gain no new OASIS XLIFF 1.2 validation errors when exported unchanged. Both strict and transitional schemas were used. Strict errors that were already in the original files stay; the export did not add them. Evidence: [docs/evidence/0.8.2-p3-6-xliff-validation.md](../evidence/0.8.2-p3-6-xliff-validation.md), merged in [PR #422](https://github.com/xueyang-dev/Folith/pull/422) (`760b9683`). The measured commit is `99dcf593`. Not opened in Trados or memoQ. This is a kernel no-op export, not a UI export.

## Not yet verified

None of the following is a capability of this draft:

- **G2 fluency.** See known limits. This draft does not say the app got smoother.
- **What generic XLIFF still does not claim.** The four kernel proofs are on main in #418, above. Inserting a foreign element in an unknown namespace was not rejected, and `rejections` stayed empty, so that ledger row stays partial. Locked segments visible but not editable in the workbench, and a real 1,000-unit window, still wait on P3-5. The damaged-file error text is in the evidence; it is not a separate capability.
- **A spot check of a UI export.** The independent check of a kernel no-op export is on main in #422, above. Checking a file exported from the UI still waits on P3-5. Not opened in Trados or memoQ.
- **30 frozen stress rounds with zero crashes.** The older A3 macOS record does not carry over. The driver landed in [PR #419](https://github.com/xueyang-dev/Folith/pull/419) (`b0ccb76a`). A 3-round smoke on an existing macOS frozen app is not 30 rounds and was not Windows, so it does not pass G1. There is no Windows 30-round record and no 8-hour record on either platform.
- **Windows "reduce motion".** The code that reads the system setting landed in [PR #415](https://github.com/xueyang-dev/Folith/pull/415) (`09c5715a`). Nobody has toggled "Show animations" in Windows Settings for this. The tests are mocks, not a real-machine record.
- **p95 for the five operations, and the interaction-latency budget.** No measurement and no signed calibration.
- **The TM / TB import wizard on a real window on both platforms, with a real TMX.** Offscreen tests only.
- **Sleep, wake, and resume after quit.** No record.
- **A before/after timing of the understanding stage on a real book** (#319). [docs/understanding-speedup-0.8.2.md](../understanding-speedup-0.8.2.md) says there was no real book and no real gateway timing.
- **Native Windows acceptance of the 0.8.1 UI.** Still none.
- **#220 item B5** (what a bad vision reply looks like) needs a real vision model. [docs/issue-220-remaining-0.8.2.md](../issue-220-remaining-0.8.2.md) says it was not done. The vision concurrency defaults (3 for an official endpoint, 2 for a relay) are written there, but `CHANGELOG.md` does not say so, so this draft does not treat them as a released capability.

The acceptance ledger is a draft: [docs/release/0.8.2-acceptance-ledger.md](0.8.2-acceptance-ledger.md), merged in [PR #416](https://github.com/xueyang-dev/Folith/pull/416) (`588eff42`). That ledger says it must not be read as a pass. How to test on Windows: [docs/release/0.8.2-windows-acceptance.md](0.8.2-windows-acceptance.md). The 30-round command is on main only after #419. The earlier `b9e7c924` still said there was no script. The command exists; the 30 rounds were not run.

## Known limits

- **G2 was not successfully measured (未测成).** [docs/evidence/0.8.2-p1-5-macos-jank.md](../evidence/0.8.2-p1-5-macos-jank.md) was not the planned load: both arms barely stalled, and the running-phase actions did not match (the baseline sampled 2,288 scrolls, the candidate sampled 0). That run is not "faster" and not "slower". Windows was not measured. A frozen-candidate versus frozen-baseline comparison does not exist yet.
- **Dialects are read-only.** `write_target` for SDLXLIFF / MQXLIFF refuses. The UI does not offer to write those formats back. There is no Trados / memoQ round trip.
- **No Trados or memoQ round trip**, for generic XLIFF or for the dialect samples.
- **The macOS build is still unsigned and not notarized** (already stated for 0.8.1; this draft has no new signing record).
- Offscreen tests, mocks, and unit tests do not stand in for a real window.
