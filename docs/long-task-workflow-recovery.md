# 长任务恢复与收尾

## 恢复执行

恢复任务前检查实际存活线程和所属进程；过期心跳本身不代表旧执行已经退出。强制取消仍需等待线程返回，不会提前开放第二个执行器。

每个任务的 `.worker.lock` 由操作系统持有到执行器退出，进程终止也会释放。恢复事件在取得锁后发布。运行状态的读、合并、写通过 `.runtime-write.lock` 串行执行；状态快照与运行状态使用独立临时文件再替换，避免固定临时文件互相覆盖。

## 致命错误

磁盘空间耗尽、模型余额不足、认证或权限拒绝会终止当前工作流，阻止该执行中的后续模型请求。已经发出的请求无法撤回。新的恢复尝试会清除停止标记，应先由操作者解决外部问题。

写入磁盘失败时保留先前完整快照；界面可从内存停止记录显示失败。未能落盘的最后一批结果不能保证保留。定点重译遇到余额等错误时，先保存此前完成的段落，再将错误交给执行器处理。

## 失败、降级与补跑

全文理解分别保留正常摘要、备用摘要和概要的状态。补跑复用成功摘要，生成失败或缺失单元，并按需生成全文概要。

标注批次记录成功、有意义的空结果、请求失败、解析失败以及译文变更导致的待更新状态。失败或待更新的批次阻止完整完成状态；补跑保留成功批次。

旧任务若只保存失败总数而没有批次位置，界面明确提示无法定点补跑，只能重建全文标注，并记录补跑前的状态。这不是已经定位到旧失败批次。

## 实体译名收尾

审校工作台的“长文处理收尾”按当前原文和译文生成待确认实体列表，合并单纯引号、书名号差异。不同译法不自动视为错误；可以确认它们符合各自语境，或指定统一译名。

统一前显示逐段原文及修改前后译文。提交时重新核对预览，拒绝已经过期的修改；只修改确认过的实体出现段落，记录人工操作，并撤销受影响译文的审校、标注与下游批准状态。

## 验证范围

`tests/workflow_recovery_test.py` 覆盖存活执行器互斥、跨进程持锁与释放、跨进程状态合并、余额错误停止、磁盘满保留快照、失败批次补跑、摘要补跑和实体修复。`tests/workflow_followup_ui_test.py` 使用 Streamlit AppTest 验证收尾入口和预览确认操作。

验证使用临时任务和模拟模型响应，没有对历史任务发起付费请求，也没有修改其译文。没有验证实际供应商故障或真实磁盘耗尽环境。

核心回归 111 项通过。后续处理了扩展检查中的 4 个失败用例：自动术语测试改为验证过滤原文未出现的候选及其提示；模拟请求匹配当前术语提示词，重新验证审核、冻结与恢复门禁；上下文界面测试验证实际段落选择控件和审核操作。另修复了语言资产页面与应用路由保存不同 URL 状态字段的问题，避免刷新把刚选中的标签恢复成旧标签。

后续术语、上下文和任务导航回归 122 项通过，另有 6 项相关界面用例通过，涵盖标签切换、深链接、搜索、分组、项目术语保存及长文收尾入口。以上是选定回归范围，没有运行全库测试。
