# 借鉴 open-claude-ui：值得学的交互，以及在 Folith 里怎么落

来源：<https://github.com/Caho1/open-claude-ui>（2026-10-16 阅读：全部 30 个组件示例，
文档第 2、6、8 篇）。本文只记录**对 Folith 的 Qt 桌面端有用的部分**，以及每一条在
本仓库里的落点。

## 0. 读之前要知道的两点

* **出处。** 该仓库自称是从 Claude 桌面版安装包反编译整理出来的。我们只借鉴交互思路，
  不复制代码、常数或品牌元素（陶土色 `#d97757` 等）。它是 React / Electron 代码，
  对 Qt 本来也没有可以直接照抄的东西。
* **数字不可全信。** 它号称“逆向验证过的精确常数”，但自相矛盾：
  * 第 8 篇的弹簧参数和 `ClaudeMotionPresets.ts` 对不上：SNAPPY 一处写 600/30，
    一处写 320/28；BOUNCY 和 SNAPPY 的取值也互换了；
  * 7 档渐隐的取值，第 8 篇和 `ScrollFadeContainer.tsx` 不一样；
  * 次级按钮：第 2 篇说有边框，第 8 篇和 `CdsButton.tsx` 说不能有边框。

  所以只学**机制**（为什么要这样做），具体数值按 Folith 自己的 token 和 `motion.py` 定。

## 1. 已经落地（`feat/0.6-native-workbench`，2026-10-16）

| 机制 | 原理 | Folith 落点 |
| --- | --- | --- |
| 滚动边缘渐隐 | 只在还能往那边滚的边缘淡出；贴边时清晰；没东西可滚时不留效果 | `components.ScrollEdgeFade` / `scroll_fade()`：用 viewport 上的不透明度遮罩实现，不用预先知道背景色。已装在检查器、检查与修复抽屉、任务详情浮窗、运行记录 |
| 流式跟随不抢视口 | 离底部 40px 内算“在底部”；用户刚滚动或按键后 150ms 内不自动跟随；离底超过 120px 浮出“回到最新 / N 条新记录” | `activity_panel.ActivityPanel`（`PIN_TOLERANCE` / `INPUT_GRACE_MS` / `JUMP_DISTANCE`）；列表高度变化时，原本贴底的继续贴底 |
| 运行中锁定展开 | 内容还在变时不许收起（避免视口跳动）；结束后交还收起权，详情不会自己合上 | 运行记录的详情区（`live()`、`detail_toggle`） |
| 分割条的手感 | 4px 死区，点击不会挪动列宽；拖动中按 Esc 回滚；双击恢复默认宽度；拖到阈值以下松手就收起那一栏 | `components.ResizeSplitter`，用在翻译页 `translation_split`。原页拖窄到 240px 以下会通过原页开关收起，并记住拖动前的宽度；段落网格不能被拖到 0 宽 |

测试：`tests/qt_interaction_physics_test.py`。

**落点不够显眼。** 第 2、4 项目前只在运行记录浮窗里，平时看不到。渐隐也避开了段落网格和
首页卡片。推广到这些位置见下文 P3。

## 2. 待做，按优先级

### P0　危险确认框：回车默认就会永久删除（2026-10-16 已修）

* **问题。** `prompts.ConfirmDialog` 已经支持 `tone="danger"`（红色实心按钮），但
  `window._confirm` 不传 tone。所以下面几处不可撤销的操作，弹出的都是普通主色按钮：
  “永久删除任务”“清空翻译记忆”“删除术语”。更要紧的是，确认按钮 `default=True`
  并自动获得焦点：弹窗一出来，直接按回车就执行了。
* **借鉴。** 第 2.4 节把对话框分成 default 和 danger 两种。毁灭性操作用危险色，
  Esc 和遮罩都能退出。
* **做法（已落地）。** `window._confirm` 加 `tone` 参数；11 处不可撤销的确认都传
  `tone="danger"`：删除任务（两处）、清空翻译记忆、删除术语（两处）、删除空段、放弃草稿、
  丢弃全部修改、覆盖同名文件、重新扫描 PDF、强制退出。`ConfirmDialog` 在 danger 时
  把默认按钮和初始焦点都给“取消”。测试：`tests/qt_prompts_test.py`、
  `tests/qt_client_window_test.py::test_main_window_confirm_uses_the_apps_own_dialog`。

### P1　等宽数字

* **问题。** 频繁变化的数字（顶栏运行状态的百分比 `views.py` `_row_percent`、字数统计、
  运行记录时间戳、首页计数）用的是系统字体。SF 的数字默认不等宽，数字一变，
  文字宽度就可能跟着抖。是否真的会抖还没实测。
* **做法。** Qt 6.11 可以用 `QFont.setFeature("tnum", 1)`。给这些标签统一一个
  helper 或 objectName，在那里打开 tnum。

### P1　边框里不再套边框

* **借鉴。** 第 8.4 节：带边框的容器里，次级按钮不带边框，只靠悬停底色表达可点。
* **做法。** 排查卡片、浮窗、抽屉里的次级按钮，比如 `followup_panel.IssueCard` 的动作按钮
  和 `SectionCard` 内的按钮，框里套框的改成无边框加悬停底色。只改 QSS，不改控件结构。

### P2　分段控件的滑块

* **现状。** `style.SegmentedControl` 是一组可选中的按钮，选中项直接换底色。它在首页视图
  切换、状态筛选、审校筛选和准备页都有使用，属于全局可见的控件。
* **借鉴。** 第 2.2 节：轨道里放一块滑块，切换时滑过去，大约 120ms。
* **做法。** 在轨道上自绘滑块，位置和宽度跟随选中按钮的几何；用 `Motion` 的 "select"
  过渡（140ms）；减少动态效果时直接跳到位。`set_options` 的“只改文字不重建”优化要保留。
  “窄宽度时只剩图标”的规则不适用，因为 Folith 的分段只有文字。

### P3　把“跟随 / 锁定展开 / 渐隐”推到显眼位置

* **阶段条**（`stagebar.StepButton`）：翻译运行时，当前阶段直接显示正在做的那一步和
  已用时间，不用点开运行记录。`components.StatusDot` 的“运行中”状态加一个缓慢的呼吸效果，
  减少动态效果时关掉。
* **段落网格**：翻译进行中，如果停在最新译出的位置就跟着往下走；往上翻了就不抢视口，
  并浮出“回到最新”。
* **段落网格和首页卡片的渐隐**：网格有 120 多行，用不透明度遮罩可能让每次滚动都走离屏重绘，
  要先测帧率；不行就改为在边缘叠一层同色渐变（网格底色是固定 token）。首页卡片是毛玻璃，
  要实际看一下叠加后的效果。

### P3　窗口顶栏：内容顶到窗口最上沿（第 6.1 节）

* **借鉴。** 隐藏标题栏的背景，内容一直延伸到窗口顶部，红绿灯浮在侧栏上；按安全区避让；
  全屏时安全区归零；顶部空白处可以拖动窗口，控件不会被误拖。
* **对 Folith。** 这正是 Golden Gate 重设计记录为“未完成”的一项。PySide6 6.11 有
  `Qt.WindowType.NoTitleBarBackgroundHint`；`QWindow.safeAreaMargins()` 和
  `safeAreaMarginsChanged` 会直接给出系统的实际边距（比原文写死 74px / 45px 更可靠）；
  空白处拖动用 `startSystemMove()`。主窗口、术语窗口、项目窗口三个顶栏都要适配。
* **风险。** 标题栏区域里控件能否正常点击、拖动是否顺手、全屏切换时边距是否跳动，
  这些离屏测试覆盖不到，必须在 macOS 真机上验证。先在 worktree 里给主窗口做原型。
* **顺手检查。** 冷启动时有没有白屏一闪；如果有，在 `show()` 之前把 palette 设成主题底色。

## 3. 看过但不采用

| 内容 | 原因 |
| --- | --- |
| 弹簧动效预设 | Qt 没有弹簧动画；`motion.py` 用固定时长加缓动曲线，并尊重减少动态效果，已经够用；原文自己的参数也对不上 |
| 陶土色、暖纸底色、表面阶梯取值 | Folith 有自己的品牌色和四套主题（见 `docs/brand.md`） |
| 双环焦点光晕 | QSS 没有 box-shadow，要做只能自绘，收益小；现有 accent 边框加 `focus-ring` token 已经足够 |
| 中文输入法回车守卫 | 在 Qt 里，组字期间的回车由输入法事件消费，一般到不了 `keyPressEvent`；译文提交本来就要按 ⌘↩。真机用拼音试一次搜索框和术语对话框即可 |
| 按钮四级尺寸阶梯 | Folith 已有胶囊按钮规范（`RADIUS["control"]`）；原文的变体规则自相矛盾 |
| 窗口圆角 8→0、红绿灯随缩放补偿 | 原生窗口的圆角由系统处理；Qt 界面不存在网页那种缩放 |
| 附件磁贴、富文本输入框、@提及、模型切换、Token 仪表 | 都是聊天输入框的场景，Folith 没有 |
| 合成音效、麦克风波形、iframe 沙箱桥 | Web 专属，或者 Folith 用不上 |
| Cowork 多代理画布、侧栏会话拖放排序 | 和 Folith 的任务模型不对应；首页任务没有手动排序的需求 |
| 灯箱缩放平移 | 机制可以借鉴到 PDF 原页（光标锚点缩放、拖动平移），但目前只有缩放下拉框，属于单独的功能需求，不放在交互打磨里 |
