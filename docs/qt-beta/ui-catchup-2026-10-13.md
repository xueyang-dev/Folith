# 后端能力 → Qt 界面：补齐清单（2026-10-13）

## 方法

Streamlit 对照审计（`streamlit-parity-audit.md` §0，2026-10-11 复核）已经把旧界面的功能
基本迁完；这一份只看**后端新增、但 Qt 没有地方显示或操作**的能力。三步核对：

1. `EngineConfig` 的每个字段：Qt 设置/准备页**全部有入口**（无缺口）。
2. `folith/qt/adapter.py` 的公开函数：没被界面调用的 23 个基本是内部辅助（`pipeline_kwargs`、
   `job_is_alive` 之类）或已被别的入口覆盖（导入范围 / 重扫在「检查与修复」页）。
3. **后端写进任务状态、但 Qt 与 application 层从不读取**的键：126 个里有 75 个。大部分是内部
   簿记（锁、日志、迁移标记），下面只列**用户能感知、值得显示**的那些。

`FOLITH_*` 环境开关只剩开发/性能用途（审校重叠、状态日志、性能追踪），不需要界面。

## 缺口（按对用户的价值排序）

### A. 运行透明度：花了多少、复用了多少、卡在哪

| # | 后端能力（证据） | 现在 Qt | 建议入口 |
| --- | --- | --- | --- |
| A1 | **用量账本** `llm_usage`（调用次数、失败、耗时、token：精确/估算，按角色 翻译/审校/辅助、按模型拆分），`translation_prompt_cost`（提示词成本） — `folith/usage.py`、`core._record_translation_prompt_cost` | 完全不显示 | 「任务详情」加「用量」一节；工作台底栏一行"约 N 万 token · M 次调用"；明确标注"估算，不是账单" |
| A2 | **复用统计** `tm_used_count`、`tm_recovered_count`、`translation_cache`（完全相同原文的结果复用，`fd623a0`）、`knowledge_cache` | 段落事实里有"翻译记忆（已匹配并复用）"，没有任务级汇总 | 任务详情「复用」：翻译记忆 N 段、缓存 N 段、省下的调用 |
| A3 | **翻译失败批次** `translation_failures` | 不显示（只有运行状态"失败"） | 「检查与修复」列出失败批次 + 只重跑这些批次 |

| A5 | **边识别边翻译** `streaming_ingest`（`folith/streaming_ingest.py`，**另一个会话正在做，未提交**） | 步骤条提示"已识别 x/y 页"已在做 | 由那一轮负责；这里只登记，避免重复 |

## 建议顺序

1. **第一批（运行透明度）**：A1 用量、A2 复用、A4 全文理解、A3 失败批次 —— 都是"后端已有数据、
   只缺展示"，集中在「任务详情」与「检查与修复」，风险低、用户感知强。
2. **第二批（译员工作面）**：B1 难点标注、B2 术语影响面、B3 定向终审 —— 改工作台网格与右侧栏，
   需要和上一轮的就地编辑一起回归。
3. **第三批**：B4 术语版本、B5 项目知识条目、C2–C4。
4. **C1 透明标题栏**单独做：要在真机上调，离屏测试看不出效果。

每一批：新文案进五个 `qt-*.json`；离屏截图存 `docs/ui-audit/`；跑 `qt_*` 全量（窗口用例约 25 分钟）。
