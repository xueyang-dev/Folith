# Folith 动效系统审计（2026-10-14）

范围：Qt Widgets 桌面客户端（`folith/qt/`），当前工作树为 `codex/beta-freeze-0.5.0` 分支，HEAD 是 `0b8afdf`，另有未提交的「运行事实」相关改动。**本轮只做审计，没有修改任何实现。**

依据的原则：Calm Precision Motion。动效只用来表达反馈、空间关系和状态变化；正文和长文档阅读时保持稳定；动画不能拖慢响应、不能打断焦点和编辑，必须支持减少动画。

## 0. 证据来源与边界

- **源码审查**：本文所有结论都标了文件、函数和行号，行号以当前工作树为准。
- **真实窗口实测**：macOS 27.0.1，PySide6 / Qt 6.11.2，Cocoa 平台插件（不是 offscreen），窗口 1440×900。测量用的是你本机三个任务的**副本**，复制到临时目录里跑，原数据没有改动：
  - 验收样本.docx：3 段；
  - arxiv-attention.pdf：353 段 / 107 条审校记录；
  - The Midnight Library.pdf：3856 段 / 981 条审校记录，state 约 23 MB。
- **测量脚本**：[`acceptance-feedback-2026-10-14-tools/motion_*.py`](acceptance-feedback-2026-10-14-tools/)（`motion_seg_switch.py`、`motion_row_jump.py`、`motion_nav.py`、`motion_save.py`、`motion_stray.py`、`motion_busy.py`、`motion_focus_probe.py`）。用法：`venv/bin/python -I <脚本> <任务目录>`；脚本会先复制任务，不改动原数据。
- **边界**：
  1. **Windows 没有验证**。0.5.0 只发布 macOS Apple Silicon 版本，本机也没有 Windows 环境，表里「Mac / Windows 一致性」一列只能写「未验证」，只能从 Qt 的机制上推断。
  2. 「快速连点」是用 `QTest.keyClick` 模拟的，没有覆盖真实键盘的自动重复速率。
  3. VoiceOver 和辅助功能自动化**不能用**：已知的 QTBUG-149612 会导致崩溃，所以焦点相关的结论来自 `QApplication.focusWidget()`，没有经过读屏器验证。

## 2. 差距及优先级：该动的、不该动的

### 2.1 动画之前必须先修的（不修的话，加动画只会更糟）

1. **保存后焦点被孤立窗口抢走**（上表中的 bug）：直接违反「不能打断焦点和编辑」。
2. **保存并下一段的冻结**（300ms–7s）、**打开任务的冻结**（反馈文档第 10 条，大任务 10.5 秒）、**导航时的阻塞**（180–450ms）：主线程被阻塞时，任何动画都会冻在半路，比没有动画更难看。
3. **reduce motion 的读取方式**：Qt 拿不到，需要自己读（见 3.2），而且在任何动画上线之前就要接好。

### 2.2 该动的（按收益排序）

| 场景 | 动什么 | 参数 | 理由 |
|---|---|---|---|
| 段落切换 | **只动行高**：上一行收起、新的一行展开，两者在同一条曲线上同步插值；同时**锚定滚动位置**，让目标行在屏幕上的 y 坐标保持不变（或者平滑地过渡到新位置） | 140ms，OutCubic（选中切换这一档） | 现在 62px 的瞬移是唯一真正的「空间关系丢失」。行高插值能交代「这一行展开、那一行收起」。文字本身**不动**：不淡入、不位移，阅读保持稳定 |
| 进度条数值 | 显示值向真实值平滑过渡 | 250ms，OutCubic | 按批次跳格太生硬；只做向前插值，**永远不超过真实值**；切换阶段归零时直接跳，不做反向动画 |
| 侧栏和抽屉（等 D2 / Q1 落地后） | 容器宽度从 0 展开到目标宽度，网格同步收缩 | 240ms，InOutCubic（侧栏这一档） | 交代空间从哪来。**内容在动画期间按最终宽度布局并裁剪**，不让文字每一帧都重新换行 |
| 任务库 ⇄ 工作台（等冻结修好之后） | 侧栏宽度 240 → 0 的过渡，加内容区 8px 位移和淡入 | 300ms（主视图这一档） | 消除 240px 的横跳；但必须**先**修好阻塞，否则动画只会冻在第一帧 |
| 保存确认 | 被保存的那一行的状态图标换成 ✓，同时底色做一次很淡的色调淡出 | 底色 400ms 淡出（只动背景，不动文字） | 现在的保存反馈太弱，而且容易被状态栏的其他消息覆盖；行内反馈正好落在用户视线所在的位置 |

### 2.3 不该动的（以及理由）

| 场景 | 理由 |
|---|---|
| 检查器的内容（注意事项、术语、前后文） | 这些是要**阅读**的文字，淡入或位移会干扰阅读。真正的问题是高度跳动 70–140px，**应该从布局上解决**：给每个区块固定位置和最小高度，没有内容时显示占位文字。不靠动画掩盖 |
| 编辑框里的文字、原文和译文正文 | 正文和长文档阅读保持稳定；切换时立即换内容，不做逐字浮现或交叉淡化 |
| 悬停 / 按下 | QSS 不支持过渡；macOS 原生控件本来就是瞬时的；自绘成本高、收益几乎为零 |
| 审校队列、术语列表的增删项 | 列表很长，逐项动画会导致大量重绘，也会打乱用户正在扫读的位置 |
| 接受建议、撤销 | 结果本身就在编辑框里，瞬间可见；系统撤销的行为不要改 |
| 键盘快速连点、自动重复 | 两次切换的间隔短于动画时长时，**直接跳到终态，不播放动画**（规则见 3.2）。否则动画会排队、拖慢操作 |
| 任何「为了好看」的弹簧、回弹、模糊 | 违背 Calm Precision 原则 |

## 3. 最小实施计划（验证切片：段落切换 + 审校侧栏）

### 3.1 前置条件（单独提交，不算动效工作）

- 修复保存后的孤立顶层窗口：先精确定位是哪一处让已拆下的控件重新可见，再在 `_clear` 里改成先 `hide()`、再 `setParent(None)`、再 `deleteLater()`。补一个回归测试：保存并下一段之后，`QApplication.topLevelWidgets()` 里除了主窗口，不能再有任何可见的控件，并且 `focusWidget` 必须是编辑框。
- 「保存并下一段」改成异步：提交在后台写盘，界面立即进入下一段，写完之后再刷新那一行的状态。这一条和反馈文档第 10 条、第 2 条第一步属于同一类改动。

### 3.2 新增 `folith/qt/motion.py`（约 80 行，不引入任何新依赖）

```python
DURATION = {"press": 80, "select": 140, "local": 180, "panel": 240, "view": 300}  # ms
EASING   = {"select": OutCubic, "local": OutCubic, "panel": InOutCubic, "view": OutCubic}

def reduced() -> bool: ...
    # 优先级：QSettings appearance/reduce_motion（应用内开关）
    #       > 环境变量 FOLITH_REDUCE_MOTION
    #       > macOS 系统设置（启动时读一次，然后定时或在窗口激活时刷新）
    #       > 测试 / 自动化环境（QT_QPA_PLATFORM=offscreen 或 FOLITH_QT_NONINTERACTIVE=1）一律视为 reduced，保证结果确定

def animate(key, start, end, setter, kind) -> None: ...
    # 按 key 管理：同一个 key 上的旧动画先「跳到终态」再开始新动画（这是中断规则）
    # 两次调用的间隔短于这一档的时长（快速连点、键盘自动重复）时，直接 setter(end)，不播放动画
    # reduced() 为真时直接 setter(end)
```

- 读取 macOS 的减少动画设置：没有 pyobjc，用 `ctypes` 调用 `libobjc`，读 `[[NSWorkspace sharedWorkspace] accessibilityDisplayShouldReduceMotion]`。这是公开 API，约 15 行。`defaults read com.apple.universalaccess reduceMotion` 只在用户改过这个设置时才有这个键（你本机就没有），不可靠，**不采用**。
- 时长参数取自 brief 里的候选区间，取中间偏短的值，并且只先定义切片里会用到的几档。

### 3.3 切片 A：段落切换

- 改 `views.py:3561 _activate_position`：改行高的那几行，改成调用 `motion.animate("active-row", …)`，每一帧同时设置两行的行高，并调用一次 `_place_inline_editor`。
- 滚动锚定：动画开始前记下目标行的 `visualRect().top()`，每一帧补偿垂直滚动条，让它保持在原来的 y 坐标上；减少动画时只做锚定。
- `segment_editor.py`：`_place_inline_editor` 在动画期间跳过 `source_height` 的重新计算（最终高度在动画开始前已经算好），避免每帧都重新排版一遍。
- 预算：在 3856 段的任务上，每一帧必须小于 4ms。`setRowHeight` 会触发表头重新计算各行位置，必须实测；超出预算就降级为「只锚定滚动、不插值行高」。
- 检查器：**不加动画**，只修布局：注意事项、术语、前后文三个区块设最小高度，空的时候显示占位文字，把高度跳动压到 0 附近。

### 3.4 切片 B：审校侧栏（依赖反馈文档的 Q1 先确定形态）

- 如果 Q1 选「右侧滑出的面板」：在 `views.py:2042` 的 `translation_split` 里，用 `motion.animate("review-drawer", …)` 插值 `setSizes`（240ms）。面板内容在动画开始前就按最终宽度布局（例如 `setFixedWidth(final)` 加裁剪），不让文字每一帧都重新换行；动画结束后再恢复成可拖动的宽度。
- 连续快速点击：同一个 key 的中断规则会保证「展开 → 收起 → 展开」不会叠加动画，最后的状态以最后一次点击为准。
- 焦点：展开时焦点移到面板里的第一项；收起时焦点回到编辑框。Esc 收起面板。

### 3.5 测试与回退

- 新增 `tests/qt_motion_test.py`：
  - `reduced()` 的优先级顺序；
  - 中断规则：连续调用，最终值等于最后一次的目标值；
  - 快速连点不排队：20 次切换之后，没有残留的动画，行高都是终态；
  - 测试环境下动画时长为 0，现有测试的断言不受影响。
- 切片 A 回归：复用 `row_jump.py` 的断言，「动画结束后，目标行的 y 位移 ≤ 2px」；复用 `seg_switch.py` 的断言，「切换耗时的中位数不回退」。
- 回退手段：`appearance/reduce_motion=true`（以后在设置里暴露为「减少动画」开关），或者环境变量 `FOLITH_REDUCE_MOTION=1`。两者都能让所有动画立即退化成直接设置终态。切片的代码只改 `_activate_position` 一处，回滚也只需要还原这一处。
