## A. 干净机器安装（约 5 分钟）

在**没有** Python / Homebrew / 仓库副本的 Mac 上：

1. 双击 DMG，把 `Folith.app` 拖到「应用程序」。
2. 打开「应用程序」→ 右键 `Folith` → **打开** → 再点「打开」（未签名候选需为本应用放行一次；
   **不要**全局关闭 Gatekeeper）。
3. 确认启动后能看到任务首页；未配置模型时顶部出现配置提示条，空列表显示「还没有任务」。
4. 关闭应用；把 `Folith.app` 拖到废纸篓；确认 `~/Library/Application Support/Folith/data` 仍然存在。

记录：能否安装、能否启动、是否出现安全提示、卸载后数据是否仍在。

## B. 模型连接与设置（约 4 分钟）

1. `⌘,` 打开设置（macOS 会把「设置…」归到应用菜单；`⌘,` 在任何窗口下都可用）。
2. 「模型连接」：选提供商、填模型名与 API Key（自定义中转站需填 `https://…/v1`）。
3. 点「测试连接」：应显示成功或**可理解**的失败原因；失败可重试。
4. 「外观」：切换 `跟随系统 / 日间 / 夜间 / 纸面`，确认界面立即变化；选「跟随系统」后
   切换 macOS 浅色/深色，确认应用跟随。
5. 保存后状态栏应显示 `模型：<提供商> / <模型> → <目标语言>`。
6. **回归点**：改一次模型名或目标语言并保存，重开设置确认显示的就是你刚才的选择
   （设置不应被重置或回退）。

记录：成功/失败信息原文；主题切换是否即时；设置是否被重置。

> 自动化已做的**错误映射**验证（用本地端点注入真实 HTTP 状态码）：401 → "API Key
> 无效或已过期"、402 → "余额不足"、404 → "请检查服务商配置"、429 → "请求过于频繁"、
> 500 → "服务商暂时不可用"；运行中遇到同样的错误也会在任务详情里给出同一句话，
> 且**不会**泄露原始 JSON 或异常类型名。真实服务商的实际返回仍需人工确认一次。

## C. 真实中文输入法（关键人工项，约 5 分钟）

打开一个已有任务，光标放到右侧「译文」编辑框：

1. 用系统输入法输入中文：确认**候选词窗口**出现、能选词。
2. 组合输入（未上屏状态）时移动光标、按 Esc 取消、再继续输入。
3. 选中一段文字后用输入法直接替换；确认替换结果正确。
4. `⌘Z` / `⌘⇧Z` 撤销重做；`⌘C` / `⌘V` 复制粘贴。
5. 切到别的段落再切回：未提交内容应仍在（段落状态出现「已保存草稿」）。
6. 点「保存并提交（⌘S）」→ 确认译文进入交付内容；点「复制原文到译文」确认可一键填入。

记录：候选窗口是否正常、组合输入是否丢字、撤销/粘贴是否正常、切换段落是否丢内容。

> 自动化已做的**结构性预检**（不能替代这一步）：编辑器可编辑、已启用输入法、
> 应用级事件过滤器不吞 `InputMethod` 事件、合成组合输入后文本正确、自动存草稿
> 不打断正在进行的组合输入。真实候选窗口、选词、Esc 取消仍必须人工确认。

## D. 系统文件面板与交付保存（约 5 分钟）

1. 「导入文档…」：用系统面板选择真实 PDF、DOCX、EPUB、TXT 与 Markdown → 确认建任务；
   **再点一次取消** → 确认没有产生半成品任务。
2. 在工作台点「冻结交付」（需先审校通过）→ 交付页出现资产清单（`translation.docx`、
   `bilingual.docx`、`terms.xlsx`…），双击资产可在 Finder 中显示。
3. 「保存冻结交付文件…」：选择一个**中文名且含空格**的目录 → 确认写出文件。
4. **再保存一次到同一目录**：应出现「目标文件夹已有同名文件」的确认；
   选「取消」→ 确认**没有**覆盖任何文件；选「覆盖」→ 确认写出全部文件。
5. 在 Finder 中双击 `translation.docx`，确认默认应用能打开；用「用默认应用打开」按钮同样验证。

记录：面板是否原生、取消是否干净、中文/空格路径是否可用、覆盖确认是否符合预期、文件能否打开。

## E. 睡眠 / 唤醒（约 5 分钟）

1. 启动一个任务，在运行中让 Mac 睡眠（合盖或 `⌃⌥⏏`），1 分钟后唤醒。
2. 观察：任务是否继续、进度是否恢复、能否取消、退出是否正常。

记录：唤醒后任务状态、是否需要重试、退出是否残留进程/锁。

## F. 真实模型服务（需授权，约 10 分钟）

用真实凭据（不写入日志、不截图 Key）完成一份 PDF、一份 DOCX，以及 EPUB / TXT / Markdown 各一份的完整流程：
导入 → 翻译 → 修改并提交 → 审校 → 冻结交付 → 保存 → 退出 → 重开确认。

顺带试两项段落级操作：**「重译本段」**（只重译这一段，其它段不变）与
**「排除本段」**（段落从工作台移出；到「交付」页的「已排除段落」清单里可以恢复）。

记录：是否完成、耗时、错误信息、交付文件是否包含人工修改。

## G. 生命周期与交互（约 5 分钟）

1. 首页无任务时 `⌘Q`：应直接退出（不应被拒绝）。
2. 编辑框有未提交内容时 `⌘Q`：应保留草稿并退出；重开后内容仍在。
3. 运行中 `⌘Q`：应先取消并等待 worker 释放锁；若超时应给出「继续等待 / 强制退出」。
4. 对几百段执行「审校全部段落」时，等待框应有「**在后台运行**」按钮：点击后应用恢复可用，
   任务继续跑，完成后界面自动更新（不是取消）。
5. 菜单与快捷键：`⌘O` 导入、`⌘S` 保存并提交、`⌘W` 关闭窗口、`⌘,` 设置、
   `⌘R` 开始/继续、`⌘⇧R` 重新载入；「关于 Folith」显示版本与构建；
   Tab 焦点、窗口缩放与全屏是否连贯。
   （机器侧已验：纯键盘能选中并打开任务、键盘输入能进译文框且草稿落盘、最小高度 621pt 能装进
   1440×900 的屏幕、缩放与全屏往返后仍可编辑——E176–E178；这里只需判断"手感/观感"是否连贯。）

记录：每一步的实际表现与任何卡顿。

## H. 工作台就地编辑与译者辅助（约 10 分钟）

本轮新增的工作台功能。自动化测试已覆盖逻辑，这里只看实际操作顺不顺手、显示对不对。
用一份已翻译完的任务（任意格式，最好有几段原文完全相同）：

1. **就地编辑**：点中间双语对照的某一行，该行展开，原文完整显示，译文格直接变成编辑框；
   右侧**没有**单独的译文编辑卡片。改一个字后行底出现「● 未保存」和保存按钮；
   `⌘↩` 保存并跳到下一段未确认的段；没改时 `⌘↩` 只是跳到下一段；换行后上一行收回一行高。
2. **右侧操作栏随选择变化**：选一段时显示「第 N 段」、需要注意、术语、前后文、「重译本段」、
   批注等；`⇧`/`⌘` 多选几段后标题变成「已选 N 段」，出现「审校所选段落」，单段专用的操作隐藏。
3. **按要求重译**：在「按要求重译，比如：更口语一点」里写一句要求 →「生成」→ 出现候选译文，
   原译文**不变**；点「采用」才放进编辑框，仍需你保存。
4. **批注**：给一段写批注 →「保存批注」；用「筛选」里的批注条件能筛出这段；交付文件里**不含**批注。
5. **重复段**：改一段原文有重复的译文并保存，应弹出「……是否复用译文？」；选否时其他段不变，
   选是时只更新那几段，不会自动替换没确认的段。
6. **查找替换**：工具栏「查找替换…」，只作用于译文；先列出预览，确认后「全部替换」；
   被替换的段记为人工修改、需要重新审校。原文不受影响。
7. **字数统计**：工作台底栏显示原文总词数和已译百分比；选中段落时显示所选段的原文 / 译文字数；
   「字数统计…」打开分项表（全部、已译、未译、已审校、人工修改、重复、已排除）。
   中文、日文按字计，其他文字按空格分词。
8. **筛选**：「筛选」菜单里勾两个条件应同时生效（按钮显示「筛选（N）」），「清除全部筛选」后恢复全部。
9. **草稿横幅**：留几段未保存的修改后切换任务再回来，顶部应出现草稿提示，「全部保存」/「全部丢弃」有效。
10. **接受风险交付**：仍有必须处理的问题时普通交付不可用；「接受风险并交付…」要求写说明，
    交付后说明记录在交付版本里。
11. **补生成**：交付后在「交付」页「还能补生成的文件」里点「生成译文电子书（EPUB）」，
    应产生一个新的交付版本，旧版本不变，**不重新翻译**。
12. **准备页与暂停**：导入一本较大的 PDF，准备页在封面和元数据出来前应有加载提示，不是空白卡住；
    翻译运行中「暂停」按钮应常驻，不闪烁或消失，点后显示「正在暂停…」。
13. **原生 PDF 断行拼接**：带文本层的 PDF，工作台里的段落应是完整的句子 / 段落，不是一行一段。

记录：每一步是否符合预期；不顺手或看不懂的地方直接写下来（这一节欢迎主观意见）。

## I. P4 动效与等待反馈（本地开发候选，尚未人工签收）

1. 任务库与工作台之间往返，侧栏收合后内容完整可读；快速返回、再打开，终态与最后一次操作一致，编辑器和检查器有当前段落。
2. 检查与修复和 PDF 原页交叉开合、拖动分隔条并调整窗口；当前编辑行保持可见，文字不逐帧缩放；PDF 渲染完成后原页完整显示，切换任务不会显示上一个任务的页。
3. 浮窗从按钮处展开，Esc、关闭按钮及点击外部均能关闭；展开途中立即关闭或重开，没有残留浮窗或焦点被延迟抢走。
4. 导入和启动在按钮内显示等待；超过 3 秒的导入进度窗口仍允许操作主窗口。成功或失败后按钮恢复，不会重复启动。
5. 保存成功后该行显示 ✓ 和轻微底色反馈；立即继续输入或撤销，光标与内容不被重置。失败时不显示成功反馈。
6. 切换浅色 / 深色与阿拉伯语，检查浮窗锚点、原页 / 侧栏方向和进度填充。开启系统减少动态效果后，尺寸与位移直接到终态；系统设置最多有 5 秒读取缓存。减少透明度下无新增半透明叠层。
7. 实际按住方向键自动重复，并人工使用 VoiceOver 确认可操作；不要通过 AX 自动化代验（QTBUG-149612）。

当前仍有约半秒的大任务同步导航读取与未达到 16 ms 的严格心跳间隔；这些不是已签收项，详细测量见 [P4 记录](../ui-audit/46-p4-motion/verification.md)。

## J. P6 通知与任务库（本地开发候选，尚未人工签收）

- [ ] 任务库可直接区分蓝色工作 / 琥珀色重试或停滞 / 红色失败 / 灰色暂停 / 绿色完成；已有进度保留。问题角标与打开后的检查面板数量一致，点击角标直达该面板。
- [ ] 浅色 / 深色与阿拉伯语界面显示正常；系统打开“减少动态效果”或“减少透明度”后，轻提示直接消失而不淡出。VoiceOver 人工朗读可辨识通知、关闭按钮及任务问题图标。

## K. 模型连接、视觉连接与外观（0.6 新增，约 8 分钟，尚未人工签收）

1. **多条连接**：设置 › 模型，添加两条不同的连接（例如翻译用一条、审校或视觉用另一条），分别为翻译 / 审校 / 视觉选一条。「测试并保存」通过才保存；侧栏的连接状态芯片点开应逐条列出，可单独测试，并显示今天的 token 用量。删除一条连接要经过红色确认，默认停在「取消」。
2. **从旧配置升级**：用装过 0.5.0 的数据目录首次打开，原来的单条连接应已出现在列表里，且翻译 / 审校 / 视觉的选择合理。
3. **视觉连接**：给含扫描页的 PDF 选另一条视觉连接，运行中检查请求确实发往该连接；暂停后恢复，应询问这次用哪条连接（默认当前）；把该连接删掉再恢复，应改用当前连接，并在运行记录里说明。
4. **本机 OCR 缺失**：临时让 Tesseract 不可用（例如改 PATH 启动，或在未安装的机器上），设置里本机 OCR 应停用并给出安装链接；已选本机 OCR 的任务应改由视觉模型处理，运行记录里能看到说明。
5. **外观与主题色**：设置 › 通用，「外观」只有跟随系统 / 日间 / 夜间，「主题色」单独选。选「夜间」再改回「跟随系统」，界面应跟随 macOS 当前明暗而不是停在深色，滚动与切页不应变卡；之后在系统设置里切换浅 / 深色，应用跟着变。
6. 浅色 / 深色 / 阿拉伯语下检查侧栏、任务库、设置各页；阿拉伯语和俄语的字标应是各自语言的写法。

## L. 项目页与语言资产（0.6 新增，约 10 分钟，尚未人工签收）

1. 侧栏进入「项目」：左边项目列表、右边总览与详情；侧栏里已没有独立的「术语库」页。把窗口缩到最窄，项目页不应出现横向滚动条，长项目名省略显示。
2. 项目里的「术语库」是一个列表，每条带审核状态；任务抽出的术语、候选与冲突都在「待审核」里，没有单独的「待审核」页签。采纳一个候选只提升那一条；两个任务对同一术语译法不同时应列为冲突，不会自动覆盖。
3. 「未分类」只汇总，不参与注入；在「未分类」里直接提升候选应被拒绝，需要先「移到项目」。
4. 「移到项目」对话框：选几个任务和目标项目，先出现预览（会带走哪些已锁定术语、翻译记忆，哪些冲突）；确认后目标项目已有翻译记忆不被覆盖，只追加。预览卡高度应贴合内容，不留空带。
5. 项目有语言方向：对方向不一致的任务，项目术语不应注入翻译。
6. 项目很多、任务很长时，项目页应分批填充；刚看过的项目再次打开几乎瞬间显示。清空项目记忆的确认应留在窗口内。

## M. 扫描流（0.6 新增，需要一份几十页以上的扫描 PDF 和视觉连接，尚未人工签收）

**本节含三个已修复、待人工复核的扫描问题**（M.7–M.9，对应 `e11a0f0`、`6421f42`、`383093e`）。

1. 导入扫描 PDF 开始翻译：识别读完前 5 页就应开始翻译，工作台空态显示「正在识别第 N / M 页」，进度按页前进。
2. 识别中点「暂停」，不应卡住；继续后顶栏不应残留「正在暂停」。
3. 让某一页读取失败（例如临时把视觉模型指到会超时的接口，或用一页无法识别的图）：该页应记为识别失败并跳过，任务继续；认证 / 额度错误则应让任务失败并说明原因。
4. 连续三页超时：任务应自动暂停并建议换视觉模型；换一个可用的视觉连接后继续，失败的页应在其余页之后重新读取，已读的页不重读。
5. 顶栏状态行只显示最新一条消息，可滚动看全文；重试与单页失败会出现在运行记录里。
6. 识别出的 PDF 文本导出 EPUB 应能成功。
7. **未识别页不能交付**（`e11a0f0`）：让某一页读取失败后，其余页翻完。交付门禁应把未识别页列为必须处理，不能冻结交付；检查与修复里出现「补读失败页」一项。点「继续」应只重读失败页，其他页取自页缓存、不重新请求；补读成功后门禁解除，可正常交付。对已完成的任务再次「继续 / 重新运行」同样只补读失败页。
8. **补读的页回到原页序**（`6421f42`）：第 7 步补读成功后，被补的页的译文应出现在它原本的位置（例如第 8 页在第 7 页与第 9 页之间），不是在全书末尾；检查工作台网格、原页对照、交付后的 DOCX / EPUB 的顺序，且译文仍与各自的原文对应。已有的审校结论若因段落位置变化受影响，应显示为需要重新审校。
9. **暂停后换视觉连接**（`383093e`）：连续超时自动暂停后，在设置里为视觉换成另一条可用连接，点「继续」：尚未识别的页和末尾对失败页的重读都应走新连接（可看服务端请求或运行记录），已识别的页不重读；恢复时若出现选择连接的提问，按所选执行。

## N. 审校、一次性操作与数字（0.6 新增，约 8 分钟，尚未人工签收）

1. 对几百段的任务做「审校全部段落」：顶栏运行状态里应显示进度条和一行说明（不弹「请稍候」对话框），中途可以继续阅读、切到别的任务；完成结果出现在同一行；在同一任务上再发起第二个操作应被提示拒绝。导出、交付等一次性操作同理。
2. 审校耗时应明显低于逐段审校（每批最多 10 段、两路并发）；某一批失败时只影响该批里出问题的段，不影响相邻段；余额或权限错误应直接停下并说明原因。
3. 手动审校 / 重译期间，已完成任务的状态不应变成「等待模型」，暂停中的任务也不应被卡住。
4. 阿拉伯语 → 中文（或英文）：脚注标记（١）、电话号码应写成 0–9 数字；网址、邮箱、DOI 里的数字保持原样；检查与修复里不应出现因数字转写而来的「保留项丢失」；目标语言为阿拉伯语 / 波斯语 / 乌尔都语时不做转换。
5. 改了目标语言或项目的任务，用原来的语言再导入同一份文档，打开的应是原语言的那个任务，不是另一个。
