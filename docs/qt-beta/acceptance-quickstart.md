## 四点五、macOS 26/27 + 辅助功能扫描会崩溃（重要，请先读）

2026-10-05 的验收在 macOS 27.0.1 上用 AI "Computer Use"（辅助功能/AX 扫描）打开任务时，
候选进程两次原生崩溃（`EXC_BAD_ACCESS`；栈顶 `libqcocoa` + AppKit
`NSAccessibilityAttributeAccessorInfo getAttributeValue:forObject:` + HIServices
`__AXCopyAttributeValueForHierarchy`）。

**2026-10-05 R62 更新（已复现、已定性，且不再提供无效开关）**：我用
`scripts/qt_ax_scan_probe.py`（以与外部 agent 相同的 AX API 顺序遍历界面）在本机**稳定复现**：
选中任务行 + 外部 AX 扫描 + 打开任务 → **3/3 次** SIGSEGV/SIGBUS，崩溃栈与上面两份 `.ips`
逐帧一致（`libqcocoa` +553984/553996）。上游根因是 **QTBUG-149612**
（"macOS: synthesized table elements can delete their parent accessibility interface"，
影响 Qt **6.11.0–6.11.2**；截至 2026-10-05 状态 Reported、**没有修复版本**，
Gerrit 765434 仍在评审）。同一签名同样出现在 calibre（PyQt6）、Qt Creator、Anki、FreeCAD
等 Qt 应用上——**不是本候选独有**。

**没有可用的应用侧开关**（R62 实测，故 R61 的 `FOLITH_QT_DISABLE_ACCESSIBILITY=1` 已删除）：

- `QT_ACCESSIBILITY=0` 在 Qt 6.11 上**完全无效**——随包 Qt 二进制里根本没有这个字符串；
- `QAccessible.setActive(False)` 会被系统在 AX 客户端接入时**重新激活**（实测连接前
  `isActive=False`、连接后立刻 `True`）；即使每 100ms 重申一次，同样的操作**照旧崩溃**。

**因此验收请这样做**：

1. **用人工键鼠操作**，验收时**不要挂载 AX 代理** / Computer Use——这是正常使用路径，
   不受此缺陷影响；
2. 崩溃记录请连同 `.ips` 一起回传（我会继续跟踪上游修复：修好后升级 PySide6 并全量重验）；
3. 这个缺陷**不阻塞**受邀 Private Beta，但必须如实披露：挂 AX 代理的环境（含 VoiceOver
   重度用户与部分窗口管理工具）会遇到原生崩溃。
4. **崩溃会丢多少输入**（已实测，E172）：未提交编辑的自动保存防抖是 **1.5 秒**（每次按键重新计时，
   切换段落/退出会立刻落盘）；草稿写在任务目录的 `translation_drafts.json`，新进程能读回。
   所以硬崩溃最多丢失最后一次自动保存之后的输入——正在输入大段文字时请留意这一点。
5. **崩溃不会弄坏任务**（已实测，E173）：崩溃前后对全部任务做指纹比对——行数、状态、人工修改、
   交付快照资产、原文/译文哈希、文件大小**逐项完全一致**，没有残留进程，同一个数据目录可以直接
   重开继续用。也就是说：挂 AX 代理的代价是"崩一次 + 丢最后一次自动保存后的输入"，不是"数据损坏"。
