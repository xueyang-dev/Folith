## 三、你要做的四件事（约 25 分钟，按优先级）

1. **真实中文输入法**（最关键）：打开任一任务 → 在右侧「译文」框里用系统输入法打字，
   确认**候选词窗口出现、能选词**；组合输入中途按 Esc、移动光标；选中文字直接替换；
   `⌘Z`/`⌘⇧Z` 撤销重做；切段再切回，未提交内容仍在（段落状态出现「已保存草稿」）。
   *判定：候选窗口正常、不丢字、撤销与粘贴正常、切换段落不丢内容。*
2. **系统文件面板**：「导入文档…」选一份 PDF 与一份 DOCX → 建任务；再点一次**取消** →
   确认没有产生半成品任务。交付后「另存交付文件…」选一个**中文名且含空格**的目录；
   **再另存一次到同一目录**，应出现「目标文件夹已有同名文件」的确认：选取消不覆盖、
   选覆盖写出全部文件。用「下载全部（ZIP）」确认打出的包就是这一版交付；双击
   `translation.docx` 或点行内 ↗ 确认默认应用能打开。
3. **干净机器**：在没有 Python / Homebrew / 仓库副本的 Mac 上，把 DMG 里的 `Folith.app`
   拖进「应用程序」→ 右键**打开**放行一次（未签名候选；**不要**全局关闭 Gatekeeper）→
   确认首页能开、能配置模型、能导入并跑完一个小任务；之后把应用拖到废纸篓，确认
   `~/Library/Application Support/Folith/data` 仍在。
4. **真实模型服务**（需授权）：用真实凭据（不要把 Key 写进日志或截图）跑一份 PDF 与一份
   DOCX 的完整流程：导入 → 翻译 → 修改并提交 → 审校 → 冻结交付 → 保存 → 退出 → 重开确认。
   顺带试「重译本段」与「排除本段」（排除后可在「交付」页的已排除段落里恢复）。

**可稍后补**：睡眠/唤醒（合盖 1 分钟后唤醒，看任务是否继续、能否取消、退出是否正常）；
菜单/快捷键/Tab/全屏是否连贯；Dock 图标右键退出。

## 四点五、macOS 26/27 + 辅助功能扫描：已用运行时修复缓解（重要，请先读）

2026-10-05 的验收与 2026-11-05/06 的用户回传里，用 AI "Computer Use"（辅助功能/AX 扫描）
打开任务时，候选进程多次原生崩溃（`EXC_BAD_ACCESS` / SIGSEGV/SIGBUS；栈顶 `libqcocoa` + AppKit
`NSAccessibilityAttributeAccessorInfo getAttributeValue:forObject:` + HIServices
`__AXCopyAttributeValueForHierarchy`）。0.8.1（`git:bdf440a`）用户回传的 **9 份 `.ips`**
是同一签名。

**根因在 Qt，不在本项目的业务代码**：上游缺陷 **QTBUG-149612**
（"macOS: synthesized table elements can delete their parent accessibility interface"）——
Qt 为表格合成的 row/cell 占位元素与父表共用 accessibility id，析构时把父表的
`QAccessibleInterface` 一起删掉，下一次 AX 查询读到已释放内存。上游修复 commit
`8148c48deb8e4345bacb797cb75c011df6f797fa` 已于 2026-10-27 合入 qt/qtbase `dev` 与 `6.12`，
计划随 **Qt 6.12.1**（2026-11-17 计划发布）发布。随包的 PySide6 **6.11.2** 不含这个修复；
6.11.3（2026-10-26 发布）与 6.12.0（2026-10-08 发布）也都早于合入，同样受影响。

**所以应用自带一个运行时修复**（`folith/qt/macos_accessibility.py`，启动时安装）：把上游的
**两处**删除点都变成不删除 interface——`-[QMacAccessibilityElement dealloc]` 先把私有
`axid` 清零再调用原实现，`+[QMacAccessibilityElement removeElementsFromCache:]` 改为空实现
（与上游修复的语义一致）。只改前一处**不够**：表格缓存的单元格 interface 仍会被后一处删掉，
下一次模型变更就读已释放内存。修复只在 macOS + cocoa、且 Qt 属于受影响范围
（6.11.x / 6.12.0）时安装；安装后自检不通过就什么都不做。**升级到含上游修复的
PySide6（Qt 6.12.1+）后版本门自动生效、不再安装**，届时可以删除这段代码。A/B 用环境变量
`FOLITH_QT_AX_WORKAROUND=0`（只用于诊断/复现，不是给用户的「关闭辅助功能」开关）。

**已验证与未验证（别把两者混在一起）**：

- **因果证据（已测）**：进程内确定性复现器（上游 QTBUG-149612 附件 MRE 的纯 `ctypes` 改写，
  PySide6 6.11.2）——无修复时崩溃（SIGSEGV，exit 139），v2 完成（exit 0），
  `accessibilitySelectedChildren` 仍返回 **7 个**选中子元素、父表 `QAccessibleInterface` 仍可解析
  （E205）；**25 次**连续创建/遍历/销毁循环，无修复 cycle 0 就死、v2 **25/25** 完成（E206）。
  加上游版本事实（E204），这条上游缺陷语义确已被修掉。
- **支持性证据（已测，但不构成因果）**：重建的 `.app` 启动日志出现
  `macOS AX workaround: installed (installed); Qt 6.11.2; upstream QTBUG-149612`（E208）；
  应用内 AX 扫描探针在 v2 下：源码无动作 **3/3 ALIVE**（每轮 32–35 次扫描）、源码「继续 → 打开任务」
  动作路线 **3/3 ALIVE**、重建 `.app` 同路线 **2/2 ALIVE**，都没有新 `.ips`。**但把修复关掉
  （`FOLITH_QT_AX_WORKAROUND=0`）的对照臂也 4/4 ALIVE、无 `.ips`**——本机没有复现出用户报告的那条
  `libqcocoa`/AppKit 崩溃，所以这组 A/B 只能算"没有反证"（E207）。（只改 `dealloc` 的中间版本
  3/3 崩溃是"只修一半"的人为缺陷，不是用户那种崩溃模式，见 E209。）
- **未验证**：真实 Computer Use 在重建候选上的完整验收路径（E211，唯一还能直接回答"用户那条
  路径是否安全"的验证）；**冻结 DMG 上的验证**（没有构建新 DMG）；**AX 表格/行/单元格是否仍对
  辅助功能可见**（E210：`表格` 切换是 `AXCheckBox`，`AXPress` 被接受，但卡片视图路线上从未出现
  `AXTable`）。也就是说：不能说"所有 AX 客户端在所有场景都安全"。

**因此验收可以这样做**：

1. 可以用 Computer Use / VoiceOver / 窗口管理器的 AX 扫描做验收（旧版速览写的是
   「不要挂载 AX 代理」，这条限制自 2026-11-06 起作废），但仍请把崩溃与异常连同 `.ips`
   一起回传——我们要知道哪条路径还会撞上；
2. **请把 A/B 结果一起回传**：同一份数据目录下，默认启动（修复生效）与
   `FOLITH_QT_AX_WORKAROUND=0` 启动（故意复现上游缺陷）各跑一次相同操作，记录进程是否存活、
   是否有新的 `.ips`；
3. 这个缺陷**不阻塞**受邀 Private Beta，但必须如实披露：修复目前只覆盖已测路径，冻结 DMG 与
   真实 AX 客户端的完整 A/B 仍是待办；
4. **崩溃会丢多少输入**（历史实测，E172）：未提交编辑的自动保存防抖是 **1.5 秒**（每次按键重新计时，
   切换段落/退出会立刻落盘）；草稿写在任务目录的 `translation_drafts.json`，新进程能读回。
   所以硬崩溃最多丢失最后一次自动保存之后的输入——正在输入大段文字时请留意这一点。
5. **崩溃不会弄坏任务**（历史实测，E173）：崩溃前后对全部任务做指纹比对——行数、状态、人工修改、
   交付快照资产、原文/译文哈希、文件大小**逐项完全一致**，没有残留进程，同一个数据目录可以直接
   重开继续用。也就是说：即使撞上这条上游缺陷的代价是"崩一次 + 丢最后一次自动保存后的输入"，
   不是"数据损坏"。
