# 0.5.0 Beta 范围冻结与候选收口

日期：2026-10-11（Asia/Riyadh）。范围以 [发布计划](../release-plan.md) 为准。

本轮目标：固定现有 Qt 功能，并按用户更新的范围加入 EPUB / TXT / Markdown 导入，处理工程门禁并重建同一候选。人工强制项尚待最终安装包验收，不宣称 PRIVATE_BETA_READY。

## 已确认的收口修复

- HTTP 重试测试使用本地真实 HTTP 端点，覆盖 429 和连接中断，不再把不同 HTTP 库的 MockTransport 与 SDK 客户端混用。
- 视觉连接测试遵守现有边界：原生文档可以无视觉凭据；真正扫描页仍明确失败，不静默回退。
- 独立交付生成曾把 `performance.json` 的原有 OCR / 翻译阶段清空。保留原有阶段，继续覆盖实际发生的交付计时；现有 Paddle 导入→翻译→导出→恢复用例验证该问题。
- 受控服务显式加入仓库根路径，避免 CI 子进程无法导入 core。
- 验证链逐文件运行测试；冻结主流程探针使用已跟踪脚本，不依赖缺失的本地临时脚本。
- 本机路径从发布树的证据文档脱敏；证据中的测试假密钥以占位符表达，脱敏测试在运行时生成合成密钥。保留环境变量兼容边界，不绕过发布卫生检查。

## 新增导入范围

- EPUB：按 OPF spine 顺序读取无 DRM 的 XHTML / HTML 正文；加密或缺失章节整体报错，避免翻译半本书。图片、音视频与非正文阅读项在导入报告中明确列出。
- TXT：UTF-8、带 BOM 的 UTF-16、GB18030，保留空行分段及单字符段落。
- Markdown / `.markdown`：正文、标题、列表、链接可读文字与表格文字；代码块和图片明确排除。
- 所有新格式共用现有任务、翻译、审校与交付流程；不提供原文件格式写回。

- CI 的两条 macOS 构建链使用 macOS 15；确认 pikepdf 10.16.0 / Python 3.11 的 arm64 wheel 存在，避免旧 macOS 14 安装落入缺 qpdf 头文件的源码构建。Qt 测试在构建候选及刷新验收身份后逐文件执行；冻结流程显式运行随包程序。

- 随包 OCR 自检显式选择 Tesseract，并关闭需要原生文本来源的图文 EPUB / 原版式 PDF，避免 VLM 默认路径把本机语言包基线误送到视觉端点。自检等到导入完成回调已执行再选择任务，避免多文件导入的回调切换正在检查的工作台。
- Qt 窗口测试使用临时 QSettings 文件，实际派发延迟销毁事件，避免旧窗口累积后全局换主题的样式刷新成本不断增长。
