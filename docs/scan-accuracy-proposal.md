# 扫描页识别准确率与原文复核方案（issue #8）

> 状态：提案。本文只做选项比较与首步建议，不改变应用默认行为。
> 复现脚本：`benchmark/scan_accuracy_probe.py`（见文末）。
> 已有试点记录：[《علم الدين》原图校对试验](ocr-vision-pilot.md)、[三路 OCR 来源实测](ocr-sources-verification.md)、[OCR 子系统的真实基准](ocr-subsystem.md)。

## 1. 结论摘要（推荐首步）

最危险的一类是**看起来合法、实则误读的整词**（issue 中的 `احواله` ← `احوالهم`）。它既不是乱码，也不会降低结构/流畅度，因此只靠"提高 DPI"或"让模型自查"都不足以稳定捕获，靠更强的模型也只是降低概率、无法给出可核对的证据。

**建议首步：先用可复现的测量脚本把成本与效果钉在纸面上，再决定实现哪一项。**
即运行 `benchmark/scan_accuracy_probe.py`，在同一页（PDF 第 13 页）上做一组受控对照，记录每页 token 用量、耗时、以及四个已知误读的复现情况：

| 对照臂 | 目的 |
| --- | --- |
| 现模型 + 150 DPI | 复现 issue 的原始条件 |
| 现模型 + 300 DPI（生产 high） | 分离"分辨率"的收益 |
| 现模型 + 350 DPI（生产 historical） | 上界参考 |
| 现模型 + 自查二次请求 | 分离"模型自查"的收益与新增误改 |
| 若可用，更强视觉模型 + 150/300 DPI | 分离"换模型"的收益 |

在第一档里，**推荐优先落地的实现候选是"原文复核（标记可疑词 + 原图对照）"**（第 4 项），因为它直接针对"静默污染译文"这一类，成本主要在一次性工程与用户确认时间，而不是每页 API 费用；并且它可以复用现有 `folith/source_quality.py`（确定性来源准入/隔离）与 `folith/text_layer_quality.py`/`folith/spatial_index.py`（定位与顺序证据）。但它必须与测量结果一起评估，不能先写死阈值。

## 2. 问题事实

issue #8 的测试用例：Internet Archive 上的公有领域扫描版 *علم الدين*（item `alamaldin00alimuoft`），PDF 第 13 页（印刷页码 ١٣），150 DPI，经**翻译连接**使用视觉模型 `deepseek-v4.1-flash` 读图。约 150 词中出现 4 处错误：

| 识别结果 | 原文 | 类型 |
| --- | --- | --- |
| `كافعامل` | `كافعالهم` | 非词（nonword） |
| `احواله` | `احوالهم` | **看似合法的错词**（最难） |
| `كال` | `كمال` | 非词 |
| `وانكرة` | `والفكرة` | 非词；隐喻主语丢失 |

结构识别正确：两个小标题、三个正文段落，页码未进入正文。也就是说，问题集中在**词形级别**，不在版面级别。

## 3. 当前实现与成本口径

与本次成本估算直接相关的事实：

- 扫描页主流程把页面渲染为 PNG，交给所选 OCR 来源；线上来源是 OpenAI 兼容的 `/chat/completions` 图像转写（`folith/ocr_online.py`，提示词版本 `v1`），逐字转写、不翻译、不补写，返回没有行框、没有置信度（都显式记为 unknown）。
- 分辨率由质量档决定（`folith/ocr_language.py`）：`standard=220`、`high=300`、`historical=350` DPI；自适应试验为低 150 / 高 300。**生产默认是 220 DPI；150 DPI 是自适应试验的低档**，即 issue 用的是偏低的一端。
- 线上 OCR 的页缓存身份包含 provider/model/prompt/max_tokens/temperature/reasoning 等；改变 DPI 会生成新的页面缓存条目（`backend_options`/DPI 参与身份），因此 DPI 对照会各自计算并计费一次。
- 视觉模型的图像 token 用量大体**与像素面积成正比**（具体切图方式由服务商决定），所以 150→300 DPI 约为 4× 像素，350 DPI 约为 150 DPI 的 5.4×；这会把每页输入 token 显著推高。**这是方向性判断，必须由脚本实测确认。**

现有**已实测**锚点（来自试点，均为 6 行裁片，不是整页，只作量级参考）：

| 试点方法 | 2 次调用 tokens | 2 次调用耗时 |
| --- | ---: | ---: |
| 逐字转写（只看图） | 1999 | 5.62 s |
| 带图校对 | 2893 | 6.57 s |
| 纯文字校对 | 1451 | 11.38 s |

Tesseract（可作交叉核对的本地引擎）在 10 页人工参考上的真实基准：350 DPI、PSM 6 时平均 CER **21.67%**、WER **54.12%**，约 2.5–3.4 s/页（见 `ocr-subsystem.md`）。这个错误率本身就是"交叉核对"的噪声下限。

## 4. 选项对比

评估维度：对**非词**的捕获、对**看似合法错词**的捕获、每页额外成本、主要风险。

| 选项 | 捕获非词 | 捕获"合法错词" | 每页额外成本 | 主要风险 |
| --- | --- | --- | --- | --- |
| 1. 提高 DPI + 调提示词 | 中 | 低 | 本地渲染无 API 费用；图像 token 随分辨率上升（150→300 ≈ 4×像素） | 未必修复断笔/点画；推高费用与延迟；提示词过强会诱发"补写" |
| 2. 模型自查（二次请求） | 中 | 低–中 | ≈ +1× 该页请求 token | 会引入新误改；对被问"是否可疑"倾向回答"否" |
| 3. 与 Tesseract 定位层交叉核对 | 中 | 低 | 本地 Tesseract 数秒 + 可选一次对账请求 | Tesseract 自身 CER ~22%，直接比对噪声大，误报多 |
| 4. 原文复核：标记可疑词 + 原图确认 | 高 | 中（提供可核对证据） | 无额外 API 费用；增加人工确认时间 | 需要词表/启发式；"合法错词"仍需人看原图 |
| 5. 更强视觉模型（同 DPI） | 中–高 | 中 | 取决于服务商定价（常高于现模型） | 未在本项目内跨模型测量；成本/收益未知 |

### 1. 提高渲染 DPI 与调整识别提示词
- **机制**：更高 DPI 让字母点画、连字与细笔画更可分；提示词强调"不补写、不现代化拼写"。
- **效果预期**：对因分辨率导致的断笔/粘连有效；issue 的 150 DPI 是低档，升到 300 DPI 有理由改善 `كال/كمال` 这类丢字。但 `احواله/احوالهم` 这类只差一个字母（或字母点）的错词，即使更清晰也可能继续误读。**单靠本项不足以作为交付保证。**
- **成本**：本地渲染几乎无 API 费用；线上图像 token 随像素近似线性上升，150→300 DPI 约 4×、→350 DPI 约 5.4×。真实增幅由脚本按页记录。

### 2. 让模型检查自己的识别结果
- **机制**：第二次请求（可只针对低可信行）要求模型复核/重读可疑词。
- **效果预期**：能抓住部分非词；对"合法错词"帮助有限，因为模型第一步正是把它读成了合法词。可能修正，也可能引入新错。
- **成本**：约 +1× 每页请求 token（若全页复核）。

### 3. 与 Tesseract 定位层交叉核对并标记不一致词
- **机制**：本地跑 Tesseract 得到词/行与坐标，与线上转写做词级对齐，不一致即标记；可仅把分歧点交给用户或一次对账请求。
- **效果预期**：非词若两路都不支持，可疑度较高；但 Tesseract CER ~22%，直接"字面不一致"会大量误报，须结合词表/形态约束。线上来源无坐标，需要额外对齐。
- **成本**：本地 Tesseract 约数秒/页、无 API 费用；可选对账请求按方案 2 计。

### 4. 原文复核：标记可疑词供用户确认
- **机制**：确定性规则给出可疑度并**保留原文、不改写**，在工作台把可疑词与原页并排，请用户确认。可复用 `source_quality.py`（隔离、要求人工来源核对、绝不删除或臆测替换）与 `spatial_index.py`（把行/区域映射回原页）。
- **效果预期**：对非词较好（未知词、无 `ال` 前缀且不常见等）；对"合法错词"只能提供"请核对原图"的证据而非自动判定——但这正是最危险一类，**让人看到比自动猜更诚实**。与小词表（如 `text_layer_quality.py` 的 `_ARABIC_COMMON_WORDS`，需扩充）结合可降低误报。
- **成本**：无额外 API 费用；成本是工程实现与用户确认时间。风险是把过多词标为可疑造成打扰，需要测量校准阈值。

### 5. 更强的视觉模型
- **机制**：换用更强的多模态模型（同 DPI）。
- **效果预期**：通常降低整体 CER，但对个别"合法错词"仍非零。本项目**尚未跨模型测量**（试点只比了一个视觉模型），因此收益未经验证。
- **成本**：取决于服务商定价，常高于现模型；应按每页 token 与实际单价换算。

## 5. 成本口径

- 线上协议只返回 token 用量（prompt/completion/reasoning/total），**不返回金额**，因此本方案一律以 token 与耗时计量，不折算货币。
- 因为页缓存身份包含分辨率与模型，DPI/模型对照会各计费一次；脚本会把每次请求的 usage 与耗时逐页落盘。
- 图像 token 与像素面积近似成正比（服务商切图规则不同，需实测）。

## 6. 推荐首步与后续验证

1. **测量优先**：运行脚本，得到 150/300/350 DPI 与（如可用）更强模型、自查二次请求在**同一页**上的 token、耗时与四个检查点的复现结果。据此判断哪一项真的降低了误读，尤其是"合法错词"。
2. **实现候选**：无论测量结果如何，第 4 项（原文复核，标记+原图确认）都是针对"静默污染译文"的低风险补充；建议在测量后按数据校准可疑度阈值再落地。
3. **暂不承诺**：不把"提高 DPI"或"换模型"当作单一交付保证；不自动替换整页原文（与试点结论一致：当前证据不足以把全书自动替换为视觉输出）。

## 7. 验收对应

- 本文件即 issue #8 要求的**选项比较提案**（含各选项的预期效果、每页成本、推荐首步）。
- `benchmark/scan_accuracy_probe.py` 即要求的**复现脚本**：渲染 PDF 第 13 页并按所选 DPI 走生产的线上 OCR 路径，输出已知误读的复现检查、每页 token 与耗时；可选用 `--reference` 补充 CER/WER。

复现命令：

```sh
# 只看输入，不发起请求
python benchmark/scan_accuracy_probe.py render --page 13 --dpi 150

# 复现（需要已保存的凭据；会产生一次按量请求）
python benchmark/scan_accuracy_probe.py run --page 13 --dpi 150

# 查看历史结果
python benchmark/scan_accuracy_probe.py report
```
