# 三路 OCR 来源：配置与架构

2026-10-03。本文说明 Folith 现在的三个可选 OCR 来源、它们共享的同一条处理链、
任务级 Paddle 模型选择、线上 OCR 连接的保存方式，以及已经验证与尚未验证的部分。
实测记录见[三路 OCR 来源实测记录](ocr-sources-verification.md)；本地引擎的历史基准见
[本地 OCR 子系统](ocr-subsystem.md)与[阿拉伯语微调报告](paddle-arabic-finetuning.md)。

## 一句话

一个任务默认选择**一路** OCR 来源：

| 来源 | 展示名 | 执行位置 | 说明 |
| --- | --- | --- | --- |
| `tesseract` | Tesseract | 本机 | 默认来源；行为与旧任务保持一致 |
| `paddle` | PaddleOCR | 本机 | PP-OCRv5；可再选一个任务级模型（含本书阿拉伯语微调模型） |
| `online` | 线上 OCR API | 远端服务 | OpenAI 兼容 `chat/completions` 图像转写；**只在明确选择时使用** |
| `auto` | 自动（仅本地） | 本机 | 保持旧语义：优先 Tesseract，未安装时回退 PaddleOCR；**不会自动使用线上服务** |

三条来源共用同一条链，后续阶段完全不区分来源：

```text
PDF 渲染 → 选定 OCR 后端 → 页面结果 + 逐页缓存
        → 可选原文校对 → 分段 → 翻译 → 导出
```

本次没有实现自动投票、候选融合或按质量自动切换来源；一个任务只有一路识别结果。

## 页面结果保存什么

每个成功页在 `ocr_cache/pages/` 里保存一份完整证据：

- 页码、原始文字（`raw_text`）与规范化文字、阅读顺序由实测行序决定；
- 实际后端 `backend`、服务商 `provider`、模型 `model`、有效配置 `backend_version` /
  `backend_options`；
- 服务真实返回的行框、词框与置信度。**Paddle 的原生 0–1 分数与 Tesseract 的
  0–100 词均值不是同一种正确率**，通过 `confidence_kind` 区分；
- 坐标/置信度允许缺失：缺失时写 `geometry_known=false`、`coordinate_space="unknown"`、
  `confidence_kind="unknown"`，`bbox_pdf` 为 `null`，**不生成假的词框**；
- 线上来源额外保存请求编号、尝试次数、`finish_reason`、token 用量与未知用量标记。
  凭据从不写入页面证据、任务快照、缓存身份、请求日志或报告。

按坐标去除页眉页脚、排序与定位的代码已经区分“坐标未知”：坐标未知的行不会被
当作页边文字删除，也不会产生错误高亮；`pdf_preview._find_ocr_location` 仍会返回
命中页但不返回矩形，界面提示“该 OCR 无坐标，仅定位页面”。有真实坐标的来源行为不变。

## 任务级 Paddle 模型选择

- 选择位置：任务设置 → **OCR 来源 = PaddleOCR** → **Paddle 模型**。
- 可选模型：官方 `PP-OCRv5（官方）`，以及本机已注册的书籍模型
  （`benchmark/paddle-models/*/model-card.json` 自动发现；本书为
  `Alam al-din PP-OCRv5 Arabic book pilot（实验性）`）。
- 选择结果写入任务配置：`pipeline_config.ocr_paddle_model`、`ocr_config.ocr_paddle_model`；
  实际资源位置、模型标签与有效模型版本（权重摘要 + 模型卡摘要）写入
  `extraction_report.ocr`（`model_id` / `model_label` / `model_resource_dir` /
  `model_version`），并进入页面缓存身份。
- **模型配置通过参数传给后端实例和它派生的 worker 进程**，不修改进程环境变量，
  因此同一个应用进程里两个任务可以各用一个模型，恢复时各自继续用自己的模型。
- `FOLITH_OCR_MODEL_DIR` 保持原有的公开用途：只影响**官方**模型的资源位置
  （指向包含 `paddle/3.7.0/official_models` 的目录）；任务里的明确选择优先。
- 缺少模型资源时状态为 `model_missing`，不会下载、也不会悄悄改用官方模型：
  书籍模型的 `allow_download=false`，worker 在缺少权重时直接报错。
- 微调模型只声明经过验证的阿拉伯语用途（`ara/fas/urd`）；选其他语言时状态为
  `unsupported` 并给出明确原因，不会用它识别别的文字。
- 训练与导出流程未改动；Paddle 仍不是基础安装的必需依赖。

## 线上 OCR 连接

第一版只实现**一个**明确协议：OpenAI 兼容 `chat/completions`，用户消息里带
`image_url`（base64 data URL），要求忠实转写。已用 OpenCode Go 视觉接口实测。
专用 OCR 厂商以后通过适配器接入，本次没有实现多厂商框架、异步任务协议或任意
请求模板。

- 配置文件：`outputs/ocr_online_config.json`（权限 0600），与翻译模型配置
  `provider_config.json` **分开**。任务第一次运行时会把服务商、地址、模型与参数
  作为**不含密钥**的描述存进任务；此后更换翻译模型不会改变该任务的 OCR 服务或模型
  （引用翻译凭据时只有密钥会随翻译配置更新）。
- 凭据来源可显式选择：
  - `OCR 专用凭据`（默认）：使用上面这份 OCR 连接配置；
  - `引用翻译模型凭据`：显式复用已保存的翻译服务商、地址与密钥。
- 可配置：服务商、服务地址、OCR 模型、API Key、输出上限（tokens）、推理模式
  （`服务默认` / `关闭思考（DeepSeek 系）`）、超时与重试次数（保存在配置中）。
- 请求只包含页面图像与固定版本的转写提示词，**不包含任何参考答案、OCR 候选或翻译指令**。
- `推理模式` 默认不发送任何服务专用推理参数；只有显式选择“关闭思考”时才发送
  `extra_body={"thinking": {"type": "disabled"}}`（DeepSeek 系官方控制方式）。
  OpenCode Go 会话头只发给该服务，其他连接不会收到。
- 输出处理：只接受能解析、结构完整、未被截断的响应。空响应、非 JSON、缺少
  `break_after`、行号不连续、`finish_reason="length"`、内容被拒答等一律把该页标为
  失败，不会保存为成功页。
- 设置页的状态检查只读取本地配置，**不会自动发起收费识别请求**。
- 受控并发（最多 4 个识别线程）复用进程级 `request_control` 限流控制器：认证错误
  （401/403）与参数错误（400/404/422）不重试；429、超时与 5xx 有限重试并遵守
  `Retry-After`；取消后不再发新请求。超时记录为“用量未知”（服务可能已执行）。
- 实际返回的用量（prompt/completion/reasoning/total tokens）写入识别报告；服务不返回
  金额，因此费用**始终记为未知**，不做估算。

## 缓存、恢复与重扫

- 逐页持久缓存，成功页立即落盘；失败页不写成功记录，恢复时重试这些页。
- 缓存身份在原有字段之外增加 `backend_options`：Paddle 记录所选模型与资源位置；
  线上记录服务目标指纹、模型、提示词版本、输出上限、温度与推理模式。
  **Tesseract 默认的 `backend_options` 为空且不参与 key 计算**，所以旧任务的页面缓存
  可以继续命中（有测试锁定该字节级兼容）。
- 恢复任务只处理未完成页；预览（quick profile）与正式识别配置相同时复用预览页。
- 明确重扫是更换 OCR 来源的唯一入口：重扫会按既有机制让原文派生结果失效
  （原文校对、分段、译文对齐），不会把旧译文配到新原文上。
- 识别报告记录实际来源/模型/完成页/失败页/重试次数与用量；只要还有失败页，
  `all_pages_completed=false`，界面明确提示未覆盖全部页面。

## 界面

- 任务设置：OCR 模式、**OCR 来源**、来源相关设置（Paddle 模型选择及其状态、
  线上连接与模型）、扫描文字语言、扫描质量。
- 重扫面板：同样的来源、Paddle 模型与线上连接设置；更换来源时的后果写在面板上。
- 进度：`【阶段一】扫描 PDF OCR（完成/总数 页；实际来源 · 模型 · 语言，失败 N 页，
  重试 M 次）`。
- 识别报告：实际后端与模型（不是用户请求的名称）、完成/失败页、无坐标页、用量与
  未知用量的说明。

## 已知限制

1. 线上来源不返回行框，原页对照只能定位页面；同一行内的词级定位不可用。
2. 无坐标时不做页边过滤，因此扫描页页码可能作为一行正文进入原文，交给已有原文校对
   阶段处理（不静默删除无法定位的文字）。
3. 每个来源的置信度语义不同，不能互相比较，也不代表“正确率”。
4. 线上模型会把整页图像缩放到约 1300×1300 像素再推理，密排小字可能损失细节；
   本次只在 4 页上实测，未验证整本书。
5. Paddle 书籍模型是一本书的少样本适配，只在 `ara/fas/urd` 声明可用，且没有证明
   在其他古书上有效。
6. `deepseek-v4-flash-vision-exp` 已被上游标记为退役别名（请求由最新 Flash 模型承接）；
   本实现按服务返回的 `model` 字段记录实际模型，但该别名的长期可用性不由本项目保证。
7. 未验证：自动候选融合、按质量自动切换来源、专用 OCR 厂商适配器、整本书的线上识别
   成本与准确率。
