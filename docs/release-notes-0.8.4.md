# Folith 0.8.4 发布说明

状态：**候选 2，未发布。** 候选是 main `416ce194`（版本号 0.8.4，PR #640 合入后从 main 出）。用户 2026-11-28 采纳综合审查结论，本版主题定为「隐私修复与崩溃止血」（里程碑 #36）：只背隐私、Windows 冻结包加压（G1a）与不回退这三条门槛，G1b 只评估、不平就披露并转 0.8.5。

一句话：这一版把**备份、诊断和任务状态里能看到的凭据**清掉，并止住 Windows 冻结包在打开任务时的 **Qt 崩溃**；引擎子进程（G-E）**不在本版**，默认仍走进程内。

---

## 这一版改了什么

### 1. 隐私：备份、诊断与任务状态不再带凭据

- **备份不再带凭据，也不再带失败的原始取证**（#615）。全量导出不再把模型连接、专用视觉连接的密钥写进备份；交接任务状态的失败记录改为固定诊断，不再把异常原文、响应体或服务商回显的片段复制进去。
- **模型错误在落盘前就脱敏**（#615）。任务状态、运行时事件与本地日志里的失败信息只保留受控内容，供应商回显的密钥片段不会先落盘再指望导出时清理。
- **诊断摘要只写类别与次数**（#631）。设置里的「导出诊断」不再复制日志原文——日志里可能有正文段落、路径和不符合任何固定形状的合成值；摘要现在写受控的错误类别和每个来源的条数。
- **凭据文件创建即 owner-only**（#626）。`provider_config.json` 与 `ocr_online_config.json` 原先先按默认权限写、再 `chmod 0600`，中间存在可被本机其他账号读到的窗口；现在创建时就是 0600，再原子替换。
- **URL 里的凭据不进入任务状态**（#637）。自定义连接允许把凭据放在 URL 上（`user:pass@host`、`?key=`），而任务状态里的连接副本会随导出和备份离开本机。现在状态副本去掉 userinfo 与凭据类查询参数，**请求本身仍用完整 URL**。
- **手动重审走审校连接，清缓存覆盖项目内派生缓存**（#616）。手动重审原先借用翻译连接，会把原文和人工改写的译文发给没有指定做审校的服务；现在与自动审校走同一个「审校」用途连接。清缓存同时清掉每个项目目录下的派生缓存，项目记忆与任务正文保留，界面文案写明范围。
- **反馈绑定任务、留白容不下就舍弃、路径不按换行拆**（#610，CX-07 第 5、6、8 项）。

### 2. 崩溃止血与终态可信

- **打开任务不再在 worker 回调里同步重绘**（#642，G1a）。Windows 冻结包在 30 轮加压里出现过 2 次 `Qt6Gui` 崩溃，栈都经过「worker 结果 → 打开任务 → 显示载入遮罩 → 强制重绘」。遮罩的 `present()` 现在只排队一帧（`update()`），不再从回调里同步画。**同口径复测 30/30 轮、0 次崩溃、0 条新的 WER 记录**（W，候选 2）。同一个崩溃在 0.8.3 正式包上也复现过 1 次，所以这不是本版引入的回归。
- **终态写入没落盘就不算发布**（#643）。Windows 上 `ReplaceFileW` 拼不过杀毒/索引句柄时会重试 5 秒后失败；普通状态更新允许「退回内存里的状态」，终态写入原先也走了这条路，于是监视器以为已经收束、不再重试。现在终态写入失败如实返回失败并重试。
- **XLIFF 子段锁定按 `external_id` 对应**（#617）。前面有被排除的段落时，锁定原先按位置对齐，会把 `translate=no` 的部分锁定落到后面一个普通单元上，编辑和导出可能覆盖真正锁定的子段。

### 3. 一并带上的其他修复（原属 0.8.6）

- XLIFF 导入的两种文件类型分成两个独立筛选项，写回原因的文案不再含糊（#595）。
- 关于页的 X 链接用窄范围安全例外，不再为了绕开检查去拼接 URL（#611）。
- 审校快捷键的键帽可被鼠标和辅助技术发现（#613）。
- 「AI 解读」入口在链路未接通前先隐藏（#614）。

### 4. 内部（不影响使用）

- 引擎化纯搬移：worker 生命周期、`runtime_state` 读写、进程内 owner 登记表移进 `folith/engine/`（#593、#598、#602，`core.py` 15,695 → 14,889 行），`adapter.py` / `views.py` 腾出 200 / 265 行（#623）；均为纯搬移，无行为变化。
- 七个语言目录按 key 排序，并加排序检查与冲突合并工具，接入 CI（#625）。
- 外部保存的 worker-lock 等待规则抽到 `folith/engine/locks.py`（#585）。
- 参数化的 G1b 候选预检入口（#635）；`window.py` 去掉分号、`cleanup_paths` 改名（#618）。
- 两个测试的观测口径修正：限流间隔测试改记闸门自己的放行时间（#619）、替换日志的 Windows 偶发失败带上缓存诊断（#636）；另两处测试随语义修正（#638、#639）。
- 探针脚本读报告改用 UTF-8（#641）：中文 Windows 默认 GBK，`qt_desktop_probe.py` 曾在流程成功后读报告失败、退出码 1。
- 版本号 0.8.4（#640）。

## 已知问题

1. **≥300 段的准备页切换仍在回调里同步重绘**。这一条为了让 0.8.4 的改动面收敛，保持了 0.8.3 的行为（同步重绘后再同步建表），与 G1a 属于同类风险，Windows 冻结包的 30 轮加压没有覆盖这条路径。真正的修法（等遮罩首帧再应用，并把待应用请求与轮询串行化）在 0.8.5，实现冻结在 `wip/0.8.5-overlay-handoff`。
2. **G1b 长跑内存**：候选 1 上 Windows 单进程 58 分钟 RSS 从 462 MB 涨到 2345 MB。候选 2 的同口径结果待填；若仍不平，按路线图转 0.8.5 P0，本版发布说明如实披露。<!-- G1b: 待填 -->
3. **Windows 自定义数据目录下凭据文件沿用父目录 ACL**。凭据文件本身创建即 0600，但 Windows 上 0600 只是建议性标志；数据目录若被改到自定义位置，ACL 继承自父目录，别的本机账号仍可能读到。0.8.5 改为 owner-only DACL。
4. **Windows handoff 测试偶发失败仍在**（另一类早退），0.8.5 在状态机收口时一并处理；本版只修了「终态没落盘却算发布」（#643）这一处确定的原因。
5. **引擎子进程（G-E）不在本版**，默认仍是进程内模式；`FOLITH_ENGINE_PROCESS=1` 可手动开启。G-E 移到 0.8.5，与 #621 / #633 的锁内状态转换一起收口。

## 未覆盖

- **G2、G3 不在本版门槛**，不挡发布：G2（大书流畅与交互预算）与 G3（10,000 段滚动/选中 p95）按路线图在 0.8.6 / 0.8.5 处理。
- 两平台冻结包的完整冒烟（原生窗口、通知位置、快捷键）沿用 0.8.3 的结论；本版只对 G1a、G1b 与隐私三项做了候选验收。
- 独立发布差异复核（Codex）在打标签前做一轮；结果不回填本文件。
