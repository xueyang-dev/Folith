# Folith Qt Desktop — Loop Engineering to Beta

以下全文可作为开发 Agent 的执行指令。

## 1. 目标与授权

从当前 Qt Spike S1 的成果继续，持续推进 **Python + PySide6（Qt Widgets）** 客户端，直到得到可以交给受邀测试者使用的 **macOS Apple Silicon Private Beta**。

Windows/macOS 共用业务核心、界面代码与数据格式，分别打包。当前先完成 macOS；Windows 保留适配和实机验收要求，缺少 Windows 环境不阻塞本轮，也不能宣称 Windows 已支持。Intel Mac / Windows ARM 不在首批范围。

本指令授权完成目标所需的本地实现、必要依赖安装、针对性测试、构建、打包和文档工作。常规实现选择自行判断，不要每轮请求确认；没有必要工作剩余时结束循环。远端推送、公开发布、发送消息、购买证书和未经授权的付费模型调用不包含在本授权内。

如果界面中的自动执行目标仍是 paused / disarmed，明确提示用户需要恢复该目标；遵守系统的目标状态规则，不自行绕过暂停或重建目标来规避它。恢复后按本指令持续执行。

**完成定义是用户结果**：测试者无需安装 Python、Homebrew 或开发环境，无需 Terminal，能够从 DMG 安装、双击启动，在稳定本机目录里完成导入、翻译、人工编辑、审校、交付、保存、退出及重开恢复。

Private Beta 可接受明确标注的未签名候选和针对该应用的 macOS 系统放行步骤；不得要求全局关闭 Gatekeeper，不得将其称为正式公开分发。公开 Beta 另外要求 Developer ID / hardened runtime / 签名 / 公证 / staple 与真实下载验收。

## 3. 每轮怎么工作

每轮执行：**选一个能推进用户结果的单元 → 阅读相关实现 → 实现 → 验证其失败风险 → 修复本轮引入的问题 → 记录结果 → 继续下一单元**。

- 优先级：数据损坏/编辑丢失/凭据泄漏/退出错误，其次主流程不可用，再到明显交互问题，最后观感。
- 每轮有具体完成条件，不以“新增测试”“增加文档”“跑了多少轮”作为产品完成条件。
- 检查前说明它检测什么失败、失败后会采取什么动作。优先真实行为测试，避免只检查代码字符串、菜单项存在或生成结果与自身相等。
- 只运行与变更有关的检查；核心接口、生命周期或最终候选改变时才扩大回归。不要每轮重复整套旧 WebView sweep。
- 产品故障、夹具错误、自动化基础设施故障分别归因。保留原始失败与重试记录，重试不能抹去失败，也不能代替定位反复发生的故障。
- 用隔离数据或真实数据副本验证，避免实验覆盖用户原始项目。测试结束回收自己创建的进程和资源。
- 每轮记录：具体行为变化、修改位置、测试及构建身份、证据、仍未验证项、下一步。简洁即可。
- 一轮结束后自动继续，不用“是否继续”结束。较大单元可跨轮推进，不能把未完成写成 PASS。

如果连续两轮只是增加场景或重复测试，却没有减少 Beta 缺口，回看必需流程，调整下一单元。不要为了维持循环增加新功能或无关边界。

## 4. 先完成 Architecture Spike，再持续实现 Beta

S1 已做；先核对其证据，不从零重来。按交接 S2–S8 推进，允许根据依赖合并或拆分，但必须完成真实切片：

```text
导入 PDF / DOCX → 建任务 → 启动小型翻译任务 → 多段工作台
→ 人工修改并提交 → 审校 / 交付门禁 → 生成交付快照
→ 原生保存文件 → 正常退出 → 重开恢复
```

5–8 轮是 Spike 的初始预算，不是整个 Beta 的承诺。到 S8 或累计约 8 轮必须给出明确决策；若未完成，说明实际阻断和调整后的工作量，不靠改阶段名称宣称通过。

Spike 决策：

- **GO — Qt Widgets / macOS arm64**：真实窗口和 frozen 主流程成立，核心/数据语义保持，强制输入与生命周期验证有证据。随后无需再次确认，继续 Beta。
- **CONTINUE — REQUIRED ACCEPTANCE PENDING**：自动化/构建成立，但真实 IME 等必测人工项待完成；可继续可逆的 Beta 工程，单独保留该门槛，不能写成完整 GO。
- **NO-GO — specific Qt blocker**：真实输入、编辑状态、后台响应或打包存在根本阻断；输出可复现证据与最小替代方案，停止扩大页面迁移，等待技术决策。

Qt 的实际输入缺陷先定位到控件使用、焦点更新、模型刷新或调用线程。若持续存在且不能在限定试验中解决，不继续堆补丁，不自行改成 SwiftUI、Tauri、QML 或 WebView 工作台。

## 5. 实现边界

- 使用 **Qt Widgets** 构建主界面；不以嵌入旧 Streamlit 页面完成迁移，不引入 QtWebEngine 作为主工作台。
- 复用现有翻译、OCR、分段、术语/TM、审校、交付门禁、快照、journal、草稿和恢复能力。UI 只维护展示与未提交编辑，不建立第二套业务真值。
- 保留旧界面和旧产物作语义对照。旧 CSS、`st.session_state`、DOM 冲刷和服务握手不照搬进 Qt。
- 先采用最小调用适配层；沿用既有 worker 能力。耗时导入、OCR、模型请求、审校和导出不得阻塞 GUI 主线程；后台线程不得直接操作 Qt 控件。
- **暂停沿用现有核心语义**：当前暂停可能保留 worker 和锁。不要为了满足“暂停后锁释放”而更改它；取消/退出时才验证 worker 完成清理和锁释放。
- 保存已提交译文、编辑草稿和正式交付快照的区别不变。未通过审校/完整性门禁，不提供被伪装成正式交付的结果。
- 桌面稳定目录在导入核心前确定；安装目录和 `.app` 内不存用户数据。单实例和任务锁继续防止实际共享目录的重复执行。
- 打包优先验证现有 PyInstaller；根据真实失败选择必要调整，不同时引入多套常驻构建后端。Qt 候选使用独立输出目录（如 `dist/qt-desktop/`、`build/qt-desktop/`），保留旧 `dist/desktop/` 基线。最终迁移目录和默认启动入口清楚，测试者不需要运行 `qt_spike/main.py`。
- 模型连接配置必须能在界面完成；无需测试者手改 JSON 或设置环境变量。默认开发验证使用本机 stub；真实服务测试需用户明确授权与测试凭据，不打印凭据。
- 不新增自动更新、云同步、认证、遥测后台、daemon、通用 REST/RPC、新数据迁移体系或全新翻译内核。
- 本轮不要求复制旧界面全部 107 个渲染单元。优先完成下述 Beta 流程；高级报告、案例库、完整语言资产管理等未迁移功能保留旧实现，在 Qt 中如实说明范围，避免无效入口。

## 6. Beta 必需能力与验收

每项采用 PASS / FAIL / REQUIRED MANUAL / BLOCKED / DEFERRED，并关联当前 Qt 构建的证据。DEFERRED 只用于明确排除的功能，不能用于规避本节必需项。

### A. 普通用户能完成主流程

1. 从 DMG 安装到 Applications，Finder / Dock 双击启动，不依赖仓库、venv、Python、Homebrew、shell PATH 或 Terminal。
2. 首次启动有清楚的模型配置和连接状态；失败可理解、可重试。能新建任务、查看历史并打开已有项目/任务；基本项目归属与任务切换可用。
3. 原生文件面板导入真实文本层 PDF、DOCX、扫描 PDF；取消选择不产生半成品任务。源文件与任务状态按既有格式保存。
4. 小型任务完成翻译，显示可信进度、错误与恢复入口；运行期间能编辑、切换和取消。暂停/恢复按核心既有契约工作。
5. 多段工作台呈现原文、译文、状态和相关 QA；支持选择段落、编辑、提交、下一段及必要的审校处理；提交后的 `human_edited` 和核心状态正确。
6. 最小术语/TM 配置可传入现有核心，不静默丢弃已有项目配置。无需在本轮复制完整语言资产管理界面。
7. 使用既有交付门禁生成正式 DOCX / 双语 DOCX 等首批声明的交付文件；原生保存面板的确认/取消可靠，中文和空格路径可用；文件能用默认应用打开并在 Finder 定位。只显示已实际生成的格式。
8. 连续完成至少一份真实 PDF 和一份真实 DOCX 的全流程，重开读回人工修改与交付文件；至少一次使用获授权的真实模型服务验证连接与任务链。stub 结果用于确定性测试，不替代真实服务验收。

### B. 编辑体验与界面响应

- 实际中文输入法候选与组合输入、选中替换、光标移动、复制粘贴、撤销/重做正常；不能只发送程序化 composition 或 setText 后宣称 IME 已通过。
- 中英阿混排、RTL 与字体可读；人工编辑后的 Unicode 文本在提交、重开及导出后保持正确。
- 至少一段约 10,000 字符的长文本、约 200 段的文档，以及已有 50 任务数据副本可用；不要把每段永久建成大量重型编辑控件导致明显卡顿。
- 后台进度更新不重建正在输入的编辑器，不清掉选择、光标、撤销历史或未提交内容。切换任务/段落时有明确的保存或保留草稿策略。
- 测量普通首次启动、任务切换、长文本编辑及任务运行时的响应。输入和导航不得出现秒级无反馈卡死；长操作显示状态并允许必要的取消，避免每轮做无目标性能优化。
- 菜单、Cmd 快捷键、Tab 焦点、窗口缩放和普通全屏操作连贯；保持产品品牌、清楚层级和可读布局，先解决操作阻断，再做观感调整。

### C. 生命周期与数据安全

- 新装首页无任务、已有任务首页、未失焦编辑、运行任务、暂停任务、至少两个活跃任务和取消中的退出均按实际 Qt 路径验证。
- 关窗、Cmd+Q、Dock 退出遵循统一保存/停止规则；保存失败时应用保持打开并给出原因，不伪报安全。超时提供继续等待/明确确认强退；强退只保证已落盘结果。
- 正常退出不会损坏数据；强制结束后既有检查点可恢复；没有残留 Folith worker、子进程或锁。SIGTERM 后进程消失不能替代正常退出验证。
- 单实例行为正常，重复启动不会重复执行任务。取消/退出后的任务可恢复，不被误标为完成。
- 旧数据目录通过现有导入/接入逻辑可用，保留来源，不覆盖既有任务。升级/替换应用与卸载不会删除用户数据。
- Qt 如果提供任务/项目删除，则验证明确确认、运行/暂停任务保护、仍含任务的项目拒删以及既有备份语义。未提供的删除入口如实标注；不为了补旧探针而重回 Streamlit 调试。
- 可达的保存失败/权限拒绝以及模型断连可理解、可重试，不丢已有状态。睡眠/唤醒需要实际验证；缺条件时明确列为必测人工项。

### D. 构建、依赖与诊断

- 提供真正的 Qt `.app` 与 DMG，包含 Python/Qt、必需插件、品牌资源与固定声明的 OCR 载荷；无需首次运行 pip。源码通过不等于 frozen 通过。
- OCR Beta 基线为 `eng / chi_sim / ara`：在 frozen 包内无 Homebrew 条件验证扫描输入；缺包准确报错，不静默改用英语。Paddle 不默认随包。
- LibreOffice 保持可选：正确发现，缺失记录 NOT_RUN；未经验证不宣称其渲染通过，不以缺少它阻塞可用 DOCX 的 Beta。
- 核对整个原生依赖闭包的架构/最低 OS/库引用。支持声明与包内组件一致，发布说明只称实际验收系统已验证；无法验收 macOS 13 时，不声称支持 13。
- 诊断包含 app version、build id/commit、dirty 状态、实际 Python/PySide6/Qt 版本、已有 schema 版本、OS/架构、打包后端、数据与日志位置。发行 metadata 提取完整版本；依赖范围与实际解析版本分别记录，不把范围称为 pinned。
- 诊断导出不含 API Key、文档正文或不必要的个人信息；只收集筛选后的相关信息，不默认打包用户整个数据目录。
- 修正适用于 Qt 的 CI 接线：同一解释器环境、实际 Qt 构建依赖、候选 DMG 对应的 manifest/发布说明生成次序。workflow 定义和本机测试不能被写成真实远端 CI 已通过；缺远端授权先准备本地可复现命令并披露。
- 保存最终构建记录、实际依赖版本与可复现命令；构建 ID 与时间能区分同一 dirty checkout 的不同构建。Qt 应用和 DMG 的产物身份一致，构建/镜像/清单/说明针对同一候选；不用旧 Streamlit DMG 充当 Qt Beta。
- 在无开发环境的干净 Mac，以普通用户从最终 DMG 完成安装与主流程。开发机 env-i/offscreen 只作补充证据。

## 7. 已有问题如何收口

复核 `docs/desktop-macos-review-backlog.md` 的 MAC-01…05，不机械修旧壳，不遗忘同类风险：

- MAC-03：校正新 Qt 构建的解释器、依赖和发行说明步骤。

## 8. 人工项、阻塞和停止条件

尽早准备可安装的验收包、简短逐步清单与待回传记录，向用户一次性请求必要信息/人工验收，继续不依赖该回复的工程工作。系统文件对话框、真实 IME、睡眠唤醒、真实服务和干净机器验收不能用模拟证据冒充。

某个外部项受阻，不作为整轮停止理由；继续其余已授权的有价值工作。全部剩余必需项均依赖用户/外部条件且无法再推进时，输出具体阻断、准备好的候选与最短操作步骤，停止空转。没有验收回复就保持待验状态，不凭等待时间判通过。

禁止静默缩小完成定义、降级强制项、跳过失败测试、增加重试掩盖产品故障、虚构人工 PASS。不得通过修改本文中的门槛来宣布完成。

最终状态明确使用：

- **PRIVATE_BETA_READY**：本节要求的普通用户主流程、编辑、生命周期、数据安全、最终 frozen/DMG、真实服务与干净机器等强制验收均通过；无已知会阻断主流程、丢数据或泄漏凭据的问题。未签名只限如实披露的受邀测试分发。
- **ENGINEERING_COMPLETE — REQUIRED_ACCEPTANCE_PENDING**：本地工程和候选已备齐，但强制人工/真实服务/干净机器等验收未完成。列出缺口，不能称 Beta 已达标或将目标标为完成。
- **NO_GO — specific technical blocker**：Qt 路线关键能力存在已复现的根本阻断，停止扩大迁移并提交证据与选择。

如果所有 Private Beta 门槛已通过，缺 Developer ID 只阻塞公开分发；记录公开发布条件，不继续无限循环。未经用户另行授权，不上传、公开发布或扩大到 D4。
