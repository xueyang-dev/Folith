# 0.8.3 发布说明性能表（macOS）

- 日期：2026-11-20
- 对比：0.8.2 冻结（Release 资产，commit `ee99abd5`）vs 0.8.3 候选冻结（RV run 44757841244，commit `eba19231`）
- 同机、同一份合成数据目录（15 任务、seed 11、41 MB，放 `.loop/base`，用完删）
- 每项 3 次，取中位数；数值如实，变差项标 ⚠

## 能直接测的项

| 用户操作 | 0.8.2 冻结 | 0.8.3 候选 | 变化 | 判定 |
|---|---:|---:|---:|---|
| 启动到窗口出现（`--smoke` 墙钟） | 1908 ms（1859/1908/2806） | **1601 ms**（1589/1601/2137） | **−16%** | 改善 |
| 启动到可交互（probe `imported` 相对时刻） | 370 ms（320/370/530） | 370 ms（360/370/430） | 0% | 持平 |
| 打开任务（probe `opened` 相对时刻） | 440 ms（400/440/610） | 450 ms（440/450/530） | +2% | 持平（噪声） |
| 空闲/峰值 RSS（smoke 进程） | 505 MB（494/505/512） | **336 MB**（324/336/341） | **−33%** | 改善 |

## 无法在冻结包上直接测的项（如实标注，不用估算填表）

| 用户操作 | 原因 |
|---|---|
| 任务库 ↔ 项目页切换 | 冻结包不提供自动化切换入口；runner 的 `--mode frozen` 只跑 app 自带 `--selftest` 流程，拒绝 S5 场景（实测 exit 2：`--seconds is not applicable to --mode frozen`）。 |
| 打字到回显 | probe 的 `edit-submitted − draft-saved` 恒为 15.01 s，是 stub 网关延迟而非打字耗时，不能作数。 |
| 滚动 / 选中 p95 | 同上，冻结模式不支持 S5；源码模式下的 G3 数字口径不同，不混入本表。 |

这三项的 0.8.2 基线在 `docs/evidence/0.8.3-g3-macos.md`（B，源码 offscreen + seeded 10k）：滚动 56.57、选中 148.46、切页 26.77、键入 11.90 ms。0.8.3 的对应数字需等 0.8.5 统一测量窗口；本表不据此声称改善或回退。

## 判定

可测的四项里，**0.8.3 不比 0.8.2 差**：启动 −16%、RSS −33%，可交互与打开任务在噪声内持平。无法测的三项按上表标注，交监工判断是否接受作为发版证据。

## 关于 `scripts/perf_table.py`

按 A-45 用该脚本从冻结 probe 的报告生成表，但它的输入是 **runner 的 G3 回合目录**（`g3.operations` 里的 p95），
而冻结 probe 的报告没有这个块，生成的是一张五行全「—」的空表。因此本表按 A-45 的「按用户操作列」
要求手写可测的项，并明确标注无法测的项；不把空表当结果，也不把源码 offscreen 的 G3 数字混进来。

Windows 列由 W 补。
