# 0.8.6 C4（#522）译名统一后卡片仍不关闭

日期：2026-11-20。分支 `fix/0.8.6-c522-entity-consistency`，基线 `origin/main` `944c7041`。
写集按 C-28 放行；本 PR 实际只改 `folith/consistency.py` 与测试、证据两处，
`_refresh_entity_consistency` 调用的 `current_occurrences` / `findings` 改了，重建结果随之正确。

## 根因与改动

真实案例：统一 Crown → 皇冠出版社 后，segment 14 的「皇冠标识」是 "Crown colophon" 的正确译法，
但检测器仍把其中的裸「皇冠」算作 `locked_mismatch`，卡片永不关闭；且卡片标题/证据来自旧快照。

1. `folith/consistency.py::current_occurrences`：
   - 锁定实体扫描全部段落（此前只扫记录的索引，新段落的裸变体不会被发现）；
   - 新增 `_is_longer_valid_phrase()`：当命中的变体是更长合成词的开头、且源段落里同一个源词也
     出现在更长的英文短语中（"Crown colophon"），视为语境正确，跳过该命中；
   - 完整首选译名本身（「皇冠出版社」）不再被自己的裸形式误伤。
2. `folith/consistency.py::findings`：锁定实体只把译名确实与首选不同的段落列入卡片，
   `observed_targets` / `segment_indexes` 与真实不一致一致。
3. `_refresh_entity_consistency` 打开卡片时重新调用上面的 `current_occurrences` / `findings`，
   所以现在 count、旧译法、occurrences 和 `preferred_target` 都来自当前数据、不再显示旧快照。

未决策实体的检测完全不变（测试断言）。
