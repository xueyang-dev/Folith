## schema

未改过的 OASIS 原件，来源和 SHA-256 在 `tests/fixtures/xliff12/schema/README.md`。版权声明和 Notices 在同目录的 `OASIS-notices.txt`。标准允许为了实现而复制，不允许改 schema 本身，所以没有改 `schemaLocation`。

`xml.xsd` 是 W3C 的 XML 命名空间 schema，XLIFF schema 用它声明 `xml:lang` / `xml:space`。放进仓库是为了校验时不访问网络。许可页是 <https://www.w3.org/copyright/document-license/>。

## 方法

每个文件先按内核原样导出。四个通用样本用 `parse_xliff12` 后 `render()`。九个方言样本用 `export_unchanged`。十三份导出字节都与原文件相同。

然后用同一份 schema 分别校验原文件和导出。比较的是 `(行, 列, 消息)` 列表。两边相同才算通过，包括两边都有同一批错误的情况。原文件已经不过，只要导出没有新错误，这一条就成立。

strict 不过的原因是文件里本来就有 XLIFF 1.2 strict 不接受的扩展：`test1_es.xlf` 的外来元素和属性，SDLXLIFF 的 sdl 命名空间，MQXLIFF 的 mq 命名空间。transitional 这些都过了。这不是导出引入的。

`messages.fr.xlf` 在 strict 和 transitional 上都是 0 条错误，用来确认校验器不是空转。

## 结论

原样导出没有引入新的校验错误。十三份导出都与原字节相同，所以这个结果是预期的，不是一次「把非法文件修合法」。strict 上原文件已经失败的，导出仍然失败，而且是同一批错误。
