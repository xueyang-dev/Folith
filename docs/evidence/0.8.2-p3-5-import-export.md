# P3-5 导入导出入口

PR [#425](https://github.com/xueyang-dev/Folith/pull/425)，分支 `wb/0.8.2-p3-5-import-export`。

## 做什么

- 工作台能导入 `.xlf` / `.xliff` / `.sdlxliff` / `.mqxliff`（通用 1.2、SDL、memoQ）。导入前按后缀和声明命名空间判断方言；文件缺后缀时靠命名空间仍认得出，同时声明两种方言时明确拒绝。
- 交付面板多了两个入口：「原样导出双语文件…」和（仅通用 1.2）「导出双语文件并写入译文…」。SDL / memoQ 只有原样导出，界面上不出现写回译文的按钮（G5 第 3 条）。
- 导入、导出都在 `TaskRunner` 的后台线程里读文件、解析、落盘；GUI 线程只做界面。测试用线程 ID 断言这两个动作不在 GUI 线程上。
- 锁定段在工作台里看得见、不可编辑：编辑框只读、保存 / 复制原文 / 重译 / 结构编辑 / 排除按钮关闭。批量替换跳过锁段（`allow_protected=True` 也跳），定点重译拒绝锁段，候选采用拒绝锁段，实体统一在状态锁内重算完整预览、跳过锁段，并把跳过的数量回报给界面。
- 双语任务整体不进入翻译管线：`start_job` / `continue_job` / `retry_job` 三个入口在 `adapter` 里明确拒绝，工作台的「继续翻译」和「重试」按钮也不显示。原因写在代码里：管线重建批次时不保留导入身份和只读标记。
- 用户看得到的文字都走 i18n，7 个语言目录都补齐了。

## 安全边界（明确说明，不夸大）

1. **核心持锁保护只覆盖导出，不覆盖全部编辑入口。** 导出会在状态锁内重解析原件、逐段比对身份/源文/锁定信息，锁段译文变了一律拒绝。但 `core.save_translation_edit` 等既有入口本身没有 `readonly` 判断（本任务禁止改这些既有函数），所以界面/adapter 的拦截不是原子的：绕过 GUI 直接调核心仍可能改到只读段的内部状态。导出会把它拦住，不会写出错误文件。
2. **结构修复 / 确定性修复的引擎入口没有改。** P3-1 契约 §4.2 要求修复计划里只读段一律跳过并计数；那个入口在 `folith/engine/`，本任务明令禁止修改。这次只做到：实体统一走了新的状态锁安全入口；确定性修复仍可能包含锁段，需按引擎那条要求另行处理。
3. **导出不更新外部状态属性。** 内核的保全校验只允许 `<target>` 文本变化，不允许改属性。因此若被修改的单元本身或其 `<target>` 带 `approved` / `state` / `status` / `state-qualifier`，写回会**明确拒绝并报原因**（否则回读会把未审译文当成已批准），目标文件保持原样。无改动时原样导出不受影响。
4. **多子段单元按整段导入。** 内核的 `build_import(subsegments=True)` 会给每个子段一行，但每行的原文都取整个单元的 `<source>`，与文件不符。这里改为每个 `trans-unit` 一行；只有部分子段被锁定的单元整体按只读导入，并在导入报告里给出一条警告，不会悄悄放行未锁部分。
5. **目标语言来自文件。** 导入时读所有 `<file>` 的 `source-language` / `target-language`；多个 `<file>` 不一致、部分缺失、或显式传入的语言与文件冲突，都明确拒绝。都缺失时保留空值，不猜。
6. 导入先在同级临时目录准备完整任务再改名发布。导出先在同目录临时文件写入再替换。断电级别的目录持久性没有验证。
