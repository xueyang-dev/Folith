## 计划 §13 G5 的三条

### 1. 4 个 SDLXLIFF 与 5 个 MQXLIFF：解析后原样写回

配置在 `folith/interop/xliff12_dialect.py`。`SDLXLIFF` 只认 `sdl:seg` 上的 `locked` / `conf`。`MQXLIFF` 只认 `trans-unit` 上的 `locked` / `status`，不读 `mrk`。两份都只通过 `LockPolicy` 交给现有的 `parse_xliff12`。`write_target` 直接拒绝，不解析、不改字节。允许的导出是 `export_unchanged`：不打补丁，内核 `render()` 返回原字节。

结构 diff 使用空白名单交给 `verify_export`，所以译文文本的变化不算豁免。另有一条声明式规则 `crlf-lf`：只豁免 `#text` 上「去掉 CR 之后逐字符相同」的差异，理由写在规则上。属性、元素和其它字符不豁免。这 9 个文件的 CR 字节数都是 0，所以这条规则命中 0 次。

### 2. 单元数、锁定段数、状态分布与审计脚本一致

单元数等于审计脚本的 `trans_unit_count`，9 个文件都相同。

锁定段：SDL 的 `locked_true_count` 是 2、0、0、0，等于只读行。MQ 的 `locked_values["locked"]` 是 1、1、0、0、6，也等于只读行。

状态要按审计脚本的粒度比，不能拿单元行去比 `sdl:seg`：

- memoQ 的状态在 `trans-unit` 的 `mq:status`。内核单元的 `raw_status` 与 `status_values` 逐文件相同。`document` 是 ManuallyConfirmed ×16；`locked` 是 Proofread ×1、NotStarted ×2；`mt` 是 MachineTranslated ×36、PreTranslated ×15；`pe` 是 ManuallyConfirmed ×51；`translation_status` 六种状态各 2。
- SDL 的状态在 `sdl:seg@conf`。子段 `raw_status` 与 `conf_values` 相同，没有 `conf` 的子段另计。`QuotesSample`：Draft ×2、Translated ×2、ApprovedSignOff ×2、ApprovedTranslation ×1，另有 1 个 `sdl:seg` 没有 `conf`（`seg_count` 8）。`SamplePhotoPrinter`：Translated ×1，其余 18 个子段没有 `conf`（`seg_count` 19）。`TTSExample` 4 个、`quickplace` 8 个都没有 `conf`。

审计脚本的 `tu_translate_no_count` 是属性 `translate="no"` 的个数，锁定段也算进去（`document` 1、`locked` 1、`translation_status` 6）。P3-3 的排除数不是这个数：锁定优先，这 8 个单元是只读行，排除数是 0。`SamplePhotoPrinter` 的 26 个排除不在 MQ 审计脚本里。

这一条：**单元数、锁定段数、状态分布与审计脚本一致。** `translate="no"` 属性个数是另一列，上面写明了，没有拿它去改 P3-3 的排除数。
