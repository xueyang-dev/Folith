## 3. 分阶段算法（照计划 §5.4）

报告 JSON 里有两个窗口：

- **场景窗口** `metrics.gui_jank`：从 `jank.checkpoint()`（导入之前）到运行结束。
- **运行窗口** `metrics.run_records[0].gui_jank`：任务自己的那次运行（翻译开始→完成）。

```
R（翻译中）>X ms 次数/分钟 = 运行窗口 >X ms 次数 ÷ 运行窗口 observed_s × 60
I（完成后）>X ms 次数/分钟 = (场景窗口次数 − 运行窗口次数)
                            ÷ (场景窗口 observed_s − 运行窗口 observed_s) × 60
I 阶段时长 = 场景窗口 observed_s − 运行窗口 observed_s
I 阶段短于 15 秒的轮次作废
```

`>100 ms` 用 `slow_count`，`>500 ms` 用 `severe_count`；两者都不含 `instrumentation_*`
（采样器自报的工具内卡顿）。中位数取每组 5 个有效轮次。按 P0-5v 同一口径，I 阶段包含
导入窗口（本次场景窗口比 60 秒交互窗口多 0.37–1.07 秒，对 I 的影响可忽略）。

## 10. 这些数字不能当什么

**这是 offscreen + mock 负载 + 源码构建的诊断数据。**

- 不是冻结版：`environment.mode = source_offscreen`、`real_machine_baseline: false`；
- 不是真实窗口系统：`QT_QPA_PLATFORM=offscreen`，没有合成器、没有 GPU 绘制路径、没有原生输入；
- 不是真机验收：GPU、字体、电源状态、外接屏都与真实使用不同；
- mock 网关瞬时返回，翻译窗口只有 10.1–12.0 秒，与真实模型延迟下的运行时序不同；
- 驱动脚本自身仍是最大的卡顿来源之一（P0-5v 已记：#347 要修的东西），绝对卡顿率被工具放大。

**因此本文件只能作为"同一工具、同一参数下的 A/B 相对对照"，不能作为 G2 门槛证据。**
G2 需要冻结候选版 + 回放负载 + 真机（计划 §13）。
