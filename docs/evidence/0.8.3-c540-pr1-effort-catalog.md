# 0.8.3 C1b（#540）PR-1：模型档位目录 + 下发层 + 运行提醒

机器：macOS arm64，offscreen，PySide6 6.11.2。

## 范围（PR-1：界面不变、行为不变）

### 1. 档位目录（新模块 `folith/engine/reasoning_catalog.py`）

把 `llm_provider.py` 里两处前缀白名单搬成数据。四条目录项只收**已有实测**的模型：

| 项 | 档位 | 下发方式 | 无 Off 的原因 |
|---|---|---|---|
| Local Gateway（任意模型名） | Low / Medium / High | `reasoning_effort` | 网关收下 thinking 字段但不改思考，实测正文被推理吃空 |
| DeepSeek / OpenCode Go 的 `deepseek-flash*` / `deepseek-v4*` | Off + On | DeepSeek `thinking` 开关 | — |
| 任意 OpenAI 兼容 provider 的 `dots3*` / `dots-*` | Off + On | vLLM 模板开关 | — |
| OpenAI 兼容的 `o1/o3/o4-mini/gpt-5/gpt-6/deepseek-r1/qwq`（非 `-chat`） | Low / Medium / High | `reasoning_effort` | — |

每项带 `verified`（原注释里的实测结论与日期）、默认档位、档位显示名。没有新增模型、
没有花用户 API 额度。`llm_provider.reasoning_effort_options` / `thinking_control_options`
保留公开契约，内部改为读目录。

### 2. 下发层改为读目录

`core.call_llm` 里原来的 7 段模型名分支（档位校验、`temperature` 取舍、两种关闭思考
`extra_body`）搬进 `reasoning_catalog.resolve_effort()` / `apply_to_request()`。
请求体逐字段断言：OpenAI 推理家族带档位时不发 temperature；网关带档位保留
temperature；DeepSeek / dots 的 `extra_body` 形状与旧实现逐字节一致。

### 3. 一个统一留痕字段

`reasoning_level = {"level": …, "dispatch": …}` 写进每次模型调用的 trace 记录，
并作为可选字段进入运行时遥测（`runtime_telemetry.request_finished`，C-8 放行）。
它取代旧的单值 `reasoning_mode` 元数据；两个名字不再是两套状态。

### 4. 收下 #552 的运行时与报告部分（C-14）

从提交 `dfcfde17` 取：

- `folith/engine/reasoning_watch.py`：一次运行里 ≥20 次成功调用且思考占输出 ≥50% 时，
  发一条 `reasoning_heavy` 用户可见活动提醒；`on_timeout="skip"`、吞掉所有异常。
  读到的是同一个 `reasoning_level` 字段（不是旧的 `reasoning_mode`）。
- `folith/trace.py`：`RunContext.record_model_call` 钩子；报告新增
  「Reasoning Share of Output」一行与「Reasoning-Heavy Output」瓶颈规则。
- 对应测试：`tests/reasoning_visibility_test.py`（watch / report 两组，11 条）。
- 提交信息保留 `Co-authored-by: Claude Opus 5.5`，PR 描述注明来自 #552。

**不照搬** #552 的设置页「思考：这条连接无法关闭…」那一行（基于旧的「开关在连接上」
模型）：按 C-14，PR-2 的「用途」档位列会承担该作用。
