# P2-21 / P2-21b：Windows 上的原生崩溃（2026-11-16 至 11-17）

面向发布说明与后续维护。**两个独立的问题叠在一起**，都修了；P2-21 的验收门槛（Windows 产品默认
S3 ≥20 轮 0 崩溃）在 P2-21b 修完后达成。

## 1 现象

Windows 上跑 S3（打开/切换任务）时偶发整轮崩溃，进程没有 Python 异常栈，`runtime-baseline.json`
不会生成。两种形态：

| 形态 | 退出码 | `Current thread` | 栈顶 |
|---|---|---|---|
| access violation | `-1073741819`（`0xC0000005`） | **主线程** | `views.paintEvent` / `stagebar.paintEvent` / `components.paint_tab_shadow` |
| abort | `3` / `-1073740791`（`0xC0000409`） | worker 或主线程 | `Garbage-collecting`，或收尾时 `QPaintDevice: Cannot destroy paint device that is being painted` |

修前频次：CI `windows-latest` 上约 **2/10 ~ 7/20 每轮**；macOS 上从未复现（两平台都跑过上百轮 S3）。

## 2 P2-21：采样器把别的线程的帧拖进循环垃圾

### 怎么找到的

完整过程（含逐次类型计数与引用链）保留在本地报告里，关键是**方法**：`gc.garbage` 里的对象**不一定在环里**
（`DEBUG_SAVEALL` 会保留只被环里对象引用着的连带对象），所以必须求强连通分量。
探针 `scripts/gc_cycle_probe.py`：对 `gc.garbage` 建图（只保留指向同批垃圾的边）+ **Tarjan 求 SCC**，
按「每次打开」归一化。

第一名是一个二元环：`frame jank_monitor.py:337 capture_other_thread_frames` + `builtins.dict`，
**16.4 次/每次打开**，从它可达 3 个 `_TaskSignals`（一个 `QObject`）。

成因：`sys._current_frames()` 返回的字典**装着采样函数自己的帧**，而这个帧的局部变量装着那张字典。
每次采样留下一个环，环里挂着被检查线程的**帧对象**，连同它们局部变量里的一切——打开任务的工作
状态、`_TaskSignals`、绘制中的 `QPainter`。

### 修复（#443，已合入 `78d62025`）

采样结束的 `finally` 里清 `targets` / `frames`，并把循环变量置空。

证据（macOS offscreen、S3、每边 3 次运行、按每次打开归一化）：

| | `gc.garbage` 里的 `_TaskSignals` | QPainter / QPaintEvent |
|---|---|---|
| 修前 | 11 / 11 / 11 | 0 / 0 / 2+2 |
| 修后 | **0 / 0 / 0** | **0 / 0 / 0** |

旁证：禁 GC 臂（`FOLITH_GC_MODE=off`）的收尾 `0xC0000409` 从 **18/20 降到 0/20**。

**但它没有关掉 P2-21**：Windows 上仍然崩（control 臂 2/20、3/20）。

## 3 P2-21b：采样器跨线程取帧就是剩下的崩溃源

#443 之后剩下的崩溃全部是**主线程在 `paintEvent` 里的 access violation**，而且每一份崩溃报告里
采样线程都正好在 `capture_other_thread_frames`（6 次停在其 `finally`，3 次在 `_watch`）。

判别实验（run `44050865338`，Windows，三臂 × 20 轮，同一提交）：

| 臂 | 设置 | 结果 |
|---|---|---|
| control | 采样器全开（旧默认） | **7/20 崩溃**（`0xC0000005`，无报告） |
| sampler-off | `FOLITH_JANK_MONITOR=0` | 0 崩溃，但每轮 `exit=1`（runner 把"采样器被禁用"记成 failure） |
| sampler-main-only | 采样器照跑、跳过跨线程取帧 | **0/20，每轮 exit 0** |

三臂只差一个开关，20 轮 0 vs 7 ⇒ 跨线程取帧就是崩溃源。

机制：采样器在**别的线程**里物化并释放**正在执行的主线程帧对象**（`sys._current_frames()` + `f_back`
遍历），而主线程这时正停在 C++ 绘制里、GIL 已释放。CPython 3.11 上这会让主线程的帧被破坏。
崩溃轮 Qt 原文与此一致（`QWidgetEffectSourcePrivate::pixmap: Painter not active`、
`QPainter::setOpacity/worldTransform: Painter not active`、`restore: Unbalanced save/restore`）：
effect 去画源 widget 时，painter 已经失效。

### 修复（#446）：默认不跨线程取帧

`FOLITH_JANK_OTHER_THREADS` 默认 **关**；`=1` 才打开。采样器本身照跑，主线程自身的停顿照旧记录。

验收（run `44053160507`，20 轮/臂）：

| 臂 | 崩溃 | 退出码 |
|---|---|---|
| **control（新默认）** | **0 / 20** | 全部 `0` |
| sampler-on（`=1`，阳性对照） | 2 / 20 | 其余 `0` |

## 4 对测量的影响

- 第 7、8 条与 P2-0r2 的「全线程栈排行」需要跨线程取帧：这些运行**自己导出**
  `FOLITH_JANK_OTHER_THREADS=1`。macOS 上这条路径至今 0 崩溃。
- `FOLITH_JANK_MONITOR=0` 会让 runner 记 failure（`ok=false`），**不能**用于正式测量轮。
- 产品默认不再碰别的线程的帧；这是有意的取舍：产品要稳，测量工具要能看到全线程。

## 5 遗留（0.8.3）

- `text_import.py:153 _html_paragraphs.<locals>.walk`：另一个真环（function + cell + tuple），
  不挂任何 Qt 对象，不是崩溃源。
- 跨线程取帧本身仍不安全。如果要给用户保留"卡顿时可看到全线程栈"，得改成不持有、不释放活帧
  （只读 `code`/`lineno` 并立刻丢弃），并重新评估安全性。
- 崩溃检测：runner 现在能把 Qt 原文（`FOLITH_QT_MESSAGES=1`，逐行 flush）留在 artifact 里，
  这条在 0.8.3 应做成默认。
