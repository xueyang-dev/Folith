- 日期：2026-11-20 凌晨（测量窗口内，机器无人使用，`caffeinate` 全程）
- 代码：`944eeee1`（测量窗口时的 main）上的 S5 场景 + seeded 路径（`--seed-template/--seed-segments`）
- 任务：**seeded 10,016 段**（从一个引擎真正跑完的 16 段任务按记录平铺，`_seed_tiled_task`），
  报告里 `g3.task_segments = 10016` 如实写出；计划的预算是按 10,000 段定的，这个规模达标

## 结论

- **10,000 段规模下，计划 §10 的五条预算有两条不达标**：滚动 56.6 ms（预算 50）、
  **选中到详情 148.5 ms（预算 100，三个回合里两个明显超标）**。键入、切页、浮层在预算内。
- 这正是 #514 / #515 用户先感受到的两件事：**启动到可交互约 3.2 s、打开一万段任务约 4.7 s**。
  它们没有预算（计划没给），所以只作观测，但数字本身足以写进发布说明的「已知性能」一节。
- 回合间波动很大（切页 19–162 ms、选中 90–175 ms），说明这些操作的成本对调度与可见行数敏感；
  **单回合数字不能当结论**，所以这里给中位并保留全部回合。
- 这是 **seeded** 任务（状态由 `_seed_tiled_task` 写入，非流水线产出）；对"读一本已完成的书"这个
  使用场景是等价的，报告里也标注了来源。真实流水线产出的 10k 任务没有在本窗口内构建（翻译一万段
  不在窗口预算内）。
