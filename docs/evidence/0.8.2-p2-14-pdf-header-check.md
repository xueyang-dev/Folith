# P2-14：PDF 可用性判断只读文件头

日期：2026-11-15。分支 `fix/0.8.2-p2-14-pdf-header-check`，基于 main `cd909d56`（不 rebase）。
只改 `folith/pdf_preview.py` 的 `has_pdf_source`，加两条测试。

## 1 问题（P2-13 核查时发现，P2-15 复核后排期）

打开任务的路径（`MainWindow._apply_open_job → views.load → _load_pdf`）上，
`adapter.pdf_available(job_id)` 调 `pdf_preview.has_pdf_source(job_id)`，后者为了看
文件是不是 `%PDF`，把整份 `source.bin` 读进内存：

```python
source = core.load_source(job_id)          # 整份读
return source.startswith(b"%PDF")          # 只要前 4 个字节
```

紧接着 `_load_pdf` 还会调 `pdf_panel.load(job_id)` → `adapter.pdf_page_count(job_id)`
→ `open_pdf_doc` → **再整份读一遍** + `fitz.open`（这一遍是渲染真正需要的）。

所以对 PDF 任务，同一次打开会**整份读三次**源文件，其中两次是可以避免的；
第三次（渲染）必须读。扫描版 PDF 常见 20–50 MB。

## 2 第二轮为什么没看见

第二轮 S1/S3 两臂的 fixture 都是 **EPUB**（`source.bin` 只有 1,163 B）：
`has_pdf_source` 在 1 KB 上读完就返回 False，实测 0.05 ms，进不了 `top_stacks`。
这是「机制在、样本没覆盖」的节点，所以按任务书建成节点而不是并进 P2-13。

本机微基准（20 KB 的真实 PDF 夹具）：`has_pdf_source` 0.02–0.07 ms、
`pdf_page_count` 0.2–6.8 ms。**按字节数线性放大**：50 MB 的扫描版 PDF 上，
这两次白读是几十毫秒级的 GUI 线程 I/O。

## 3 改动

```python
PDF_MAGIC = b"%PDF"

def has_pdf_source(job_id: str) -> bool:
    if not job_id or not fitz:
        return False
    path = core.job_dir(job_id) / "source.bin"
    try:
        with open(path, "rb") as handle:
            head = handle.read(len(PDF_MAGIC))
    except OSError:
        return False
    return head == PDF_MAGIC
```

判定结果与旧实现逐条等价：文件缺失/不可读 → `False`（旧的 `load_source` 返回 `None`）；
空文件 → `False`（旧的 `b""` 为假）；`%PDF` 开头 → `True`；`%PDF` 之后任何内容不影响。

**没有改** `pdf_page_count`（渲染需要整份内容）、没有改 `open_pdf_doc`、
没有改 `views._load_pdf` 的调用顺序。所以「打开一次 PDF 任务整份读三次」→ 两次，
剩下的一次是 `pdf_page_count` + 一次 `fitz.open` 的渲染读取。

## 4 测试

`tests/pdf_preview_test.py`

- `test_has_pdf_source_reads_only_the_header`：造一个 200 KB 的 PDF 源，把
  `core.load_source` 换成「一被调用就报错」，断言 `has_pdf_source` 仍返回 True；
  再断言缺失任务与空 job_id 都是 False。
  **退回旧实现实测变红**（旧实现调 `core.load_source`，直接命中 `AssertionError`）。
- `test_has_pdf_source_rejects_other_formats`：非 PDF、空源文件为 False，
  恰好只有 `%PDF` 四个字节时为 True —— 判定没有被「只读头」改变。

本机：`pdf_preview / qt_pdf_panel / qt_pdf_tip / pdf_navigation_anchor /
qt_scan_progress` 五套 **58 passed**。
