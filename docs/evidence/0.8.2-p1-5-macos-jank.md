## 4. G2 四格（R/I × >100 ms / >500 ms）

单位为**每分钟卡顿次数**（excluding_tool 与 including_tool 本次数值相同，工具份额为 0）：

| 格子 | 基线中位 | 候选中位 | 降幅 |

| R >500 ms | 0.00 | 0.00 | **不可判定**（基线已是 0） |
| I >100 ms | 0.80 | 0.80 | **0%** |
| I >500 ms | 0.00 | 0.00 | **不可判定**（基线已是 0） |

**G2 要求每格降 ≥70%：四格全部未达。**

### 为什么这个数字说明不了产品好坏

1. **计数太小**：每轮约 **10,750** 次采样，`slow_count` 只有 **0–1**，`severe_count` 恒为 **0**。
   在这个量级上，1 次事件的有无就能把比率从 0.22 推到 0 或 0.44，**70% 的阈值没有统计意义**。
2. **两臂 R 阶段的操作负载不等价**（这一点更关键）：
   - 基线 R 段采到 `scroll 2288`、`select_segment 134`、`type_echo 134`、`page_switch 67`、`open_panel 22`；
   - 候选 R 段这些操作**全是 0**，同样的操作全部落在 `complete` 阶段（`scroll 1309` 等）。
   - 两臂 R 阶段时长相同（约 270 s）、I 阶段相同（约 150 s），采样总数也相同（约 10,750 / 16,600），
     但**操作发生在哪个阶段**不一致 —— 于是"翻译中"这个窗口里两臂被施加的负载不同，R 的对比不是同序列对比。

**因此本次不能判定 G2 通过或不通过，只能判定为「未达 / 不可判定」，并留下上面两条可复现的证据。**

## 6. 这份证据能证明什么、不能证明什么

**能证明**：
- 在当前 main（`79acc145`）与基线 `8109b9c2` 上，S1 / 40 段 / 回放 `TS=1.0` / 真实窗口 / 动画开启的负载**都不产生可测卡顿**；
- 测量链路本身是可用的：6 轮全部 `verify ok`、`aggregate_ready`、0 void、动画状态与窗口形态都被正确记录。

**不能证明**：
- **不能证明 G2 达成**，四格全未达（见 §4）；
- **不是冻结产物**：这是源码 + 真实窗口的数字，G2 要求的是"冻结基线版 vs 冻结候选版"，**候选还没有冻结产物**（P2-9），这一部分仍然缺；
- **没有覆盖 Windows**：G2 要求 macOS 与 Windows 分别达成，Windows 侧本次未测。
