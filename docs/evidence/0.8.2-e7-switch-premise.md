# E-7 前提：`FOLITH_ENGINE_PROCESS=0` 真的把流水线留在本进程（诊断 + 测试）

日期：2026-11-16。只读诊断 + 一条测试，**没有改产品行为**。

## 1 任务书要求

第 8 条（E-7）要在同一个独占时段里对照「进程内」与「子进程」两种跑法。
前提是 `FOLITH_ENGINE_PROCESS=0` 真的把翻译流水线拉回本进程——P2-E 里试过，
当时的结论是「**没拉回来**」。拉不回来就要先修开关、单独开 PR。

## 2 实际情况：开关是好的，P2-E 的观察是探针口径的问题

`folith/desktop/engine_host.py:113` 的 `engine_process_enabled()` 读环境变量，
空 / `0` / `false` 都是**关**；`folith/application/commands.py:397` 是唯一的消费者：

```python
supervisor = _engine_supervisor()
if supervisor.engine_process_enabled():
    return _start_in_engine(job_id, resolved_name, kwargs, file_bytes=file_bytes)
if file_bytes is None:
    started = core.resume_job(...)
else:
    started = core.start_job_worker(...)     # ← 本进程，worker 线程
```

本机实测（`start_job` 的两条分支都换成记录器）：

```
engine_process_enabled: {'': False, '0': False, 'false': False, '1': True, 'true': True}
  env='0': dispatched -> ['in-process']
  env='1': dispatched -> ['engine-child']
```

所以 **`FOLITH_ENGINE_PROCESS=0` 确实调 `core.start_job_worker`**，流水线跑在 GUI
进程的 **worker 线程**里。P2-E 当时用 `cProfile` 只看到 `{built-in method exec}`，
原因是 **`cProfile` 只 profile 它被启用的那个线程**，看不到另一条 worker 线程——
不是开关没生效。E-7 要的「进程内」是成立的。

## 3 加了什么

只加测试，`tests/engine_host_dispatch_test.py`：

- `test_the_switch_reads_as_documented`：空 / `0` / `false` → 进程内；`1` / `true` → 子进程。
- `test_start_job_stays_in_process_when_the_switch_is_off`：把
  `core.start_job_worker` 与 `commands._start_in_engine` 换成记录器，断言
  `start_job` 在 `0` 时走前者、在 `1` 时走后者。

**变异检查**：把 `commands.py` 的分支条件取反，`test_start_job_stays_in_process_…`
立刻变红；改回后 6 passed。

## 4 对 E-7 的影响

- 第 8 条的两种跑法都可用：`FOLITH_ENGINE_PROCESS=0`（进程内、worker 线程）与
  `=1`（每个任务一个 engine 子进程）。
- 如果要看**进程内那条线程**的 profile，必须用 `threading.setprofile` 或
  `py-spy`，不能用主线程的 `cProfile`——这是 P2-19/P2-E 踩过的坑，记在这里。
- 全线程栈排行（第 8 条要求附）用现有的 `jank_monitor` 的 `other_threads` 就有；
  E-7 跑的时候它会把 worker 线程的帧一起记下来。

## 5 局限

- 本次只是**开关与派发**的证据，没有真的跑「进程内 vs 子进程」的卡顿对照（那是第 8 条
  明天独占时段的活）。
- 没有跑 Windows：Windows 上 `engine_supervisor` 的启动形状不同（冻结包执行自身），
  但 `FOLITH_ENGINE_PROCESS=0` 走的是同一条 `core.start_job_worker` 分支，测试不依赖平台。
